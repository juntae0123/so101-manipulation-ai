## Problem — 어시스턴트 오류 18건

> **정정.** 이 절은 초판에 11건으로 적었다. 세션 전체를 다시 세니 18건이다.
> 세션 중에는 "다섯 건"이라 말했다. **5 → 11 → 18.**
> 오류 개수 자체를 모수 없이 세 번 틀렸다. 계측기 규칙이 내 자기보고에도 그대로 적용된다.
>
> 상세는 `TS_assistant_errors_0918_2.md`. **전반부 11건**(E2 folds · 실물 기하 ·
> K 스윕)은 `TS_assistant_errors_0918.md` 에 따로 있고 **겹치지 않는다.**

**(A) 문서·응답 한 줄을 전체 맥락 없이 인용했다 — 4건**
- 0912 "대상물 규격 15~25mm"(타겟 도메인 부품)를 **시연 물체 폭**으로 읽었다.
  G3 예측을 "불합격"으로 냈는데 실제는 3.74mm 차이로 통과. **방향까지 반대**
- 체크포인트 하나만 보고 *"문서의 action horizon 16 은 틀렸다"* 단정.
  E1 재니 시뮬 경로는 진짜로 16 이었다. **문서가 맞았다**
- BE 문서의 예시 페이로드 `algorithm:"ACT"` 를 설정된 enum 으로 읽고 "ACT 전용"이라 기록
- HW(현석) 답변을 트랙 A 답변으로 처리했다. 3·4번은 도경·은찬 소관인데 "해소"로 반영할 뻔했다

**(B) "전달됐다"를 확인 안 했다 — 2건**
- 패치본 전송이 `{"written":[...]}` 성공이었는데 장비 파일은 구판. **총 4회 발생.**
  사용자가 구판으로 92편 전수를 한 번 더 돌렸다
- Jupyter 업로드를 지시했다. 실제 경로는 커밋·푸시. 프로젝트 문서의 낡은 줄을 그대로 적용

**(C) 판별력 0 인 검사를 만들었다 — 3건**
- `drops` 가 92/92 전부 1. 첫 간격이 항상 공칭 2배(워밍업)인데 그걸 셌다
- gap G1 게이트 초판 Otsu 분리도 >= 2.0 — 단봉 정규분포가 2.63 으로 통과 (자체검증이 잡음)
- 프레임당 변위 속도로 30fps / 10Hz 를 가리려 했다. 0.376 · 0.125 m/s 둘 다 사람 손 속도로
  그럴듯하다. **가설 두 개를 다 통과시키는 검사였다**

**(D) 내 코드·실행 실수 — 5건**
- `dist("raw_closed_marker_center_mm", ...)` 에 `g_` 접두어 누락 → "값 없음 (n=0 / 92)".
  **모수를 같이 찍어둔 덕에 "필드가 없다"가 아니라 "내가 잘못 읽었다"로 읽혔다**
- `--dataset` 에 zarr 디렉터리를 넘겼다. 로더는 `zarr.ZipStore` 라 `.zarr.zip` 필요.
  E1·E2 가 전부 `.zarr.zip` 을 쓰는 걸 내가 보고도 그랬다
- v4.zarr 학습을 **홀드아웃 분할 없이** 띄웠다. 76편 전부 train → 그 체크포인트로는 성능 측정 불가
- `[3b]` 자체검증 기대치 오기 — 4시그마 분리를 "겹친다"로 썼다 (자체검증이 잡음)
- zarr gap 중앙 기대치를 64.42mm 로 제시. 그건 92편 편별중앙의 중앙이고,
  76편 풀링 중앙은 61.60mm — **내가 앞서 로컬에서 읽은 값과 정확히 일치했다**

**(E) 판단·제안 오류 — 4건**
- 2단계 전달 제안 — 비싼 단계(SLAM)가 아니라 싼 단계(v10 변환)에 게이트를 걸었다
- hand-eye 를 블로커라 불렀다. `convert_v10_to_umi.py` 에 hand-eye 참조가 0건.
  적용 지점은 도경 파이프라인 상류다
- 사용자 다운로드 폴더의 **무관한 대용량 파일** 삭제를 제안했다
- v10 **입력** 규약을 모델 **출력** 규약으로 적어 BE 에 보낼 뻔 (사용자가 잡음)

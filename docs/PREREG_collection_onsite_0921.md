## 0. 이 문서의 규칙

게이트와 예측을 **결과 보기 전에** 박는다. 못 맞추면 게이트를 낮추지 않고 다시 찍는다.
참조 집단: 현석 `s22_pick_v3` 35편(120 epoch 학습이 돌아간 배치)과 `v4` 76편.

## 1. 현장에서 반드시 지킬 것 — 물리 조건

**상면 파지로 시연하면 로봇이 못 따라간다.** 🟢
handoff SO-101 도달 포락선 실측: top-down 수직 구속은 z 0.02~0.04 만 도달(513칸 중 28칸).
**측면 파지만 재현 가능하다.** 평행 그리퍼 측면 파지는 접근축 둘레 회전이 자유라 5축으로 된다.

- 측면 파지 포락선: `z=0.027 → x 0.37~0.46` · `z=0.051 → x 0.34~0.46` (베이스 원점, m)
- **물체를 그 범위 안에 놓고, 옆에서 집는다.** 위에서 덮어 잡지 않는다
- 접근 방향을 편마다 바꾸지 않는다 — 현석 배치는 y 폭 59mm, 회전 폭 0.127 rad 로 고정돼 있었다

**환경은 다양하게, 시연 방식은 동일하게.** 조명·배경·물체 위치는 흔들고, 손 동선은 고정한다.

## 3. 수집 **전에** 해야 하는 계측 2건

**(a) 이미지-액션 타임스탬프 동기화.** ARCore 전환으로 재부상한 항목이다.
찍고 나서 재면 늦다. 20편 찍기 전에 1편으로 잰다.

**(b) `T_camera_tcp` (hand-eye).** 상수 편향이라 학습이 지우지 못한다 — ±10mm 에서 재생 3/4.
현석 report 는 `camera_tcp_status: physically_validated` 라고만 쓰고 값이 없다.
**값과 검증 절차를 현석에게 받아서 쓰거나, 현장에서 다시 잰다.** 둘 다 안 되면 수집은 하되
그 배치는 "hand-eye 미확정" 으로 표시한다.

## 4. 게이트 — 20편 찍고 바로 판정한다

```bash
python AI/tools/audit_umi_zarr.py --zarr <새 zarr> --gate --rate-hz 30.0021 --out out/gate_0921.json
```

| 항목 | 기준 | 현석 s22_pick_v3 | v4 |
|---|---|---|---|
| 편 수 | ≥ 20 | 35 | 76 |
| 결측 행 | = 0 | 0 / 3475 | 0 / 16328 |
| 파지 닫힘 채점률 | = 100% | 35/35 | 76/76 |
| 파지 개구 p10–p90 폭 | ≤ 3.0 mm | 1.4 | 1.6 |

| 경로/직선 비 중앙 | ≤ 2.5 | 1.63 | 2.90 ✗ |
| EEF 축별 최대 폭 | ≤ 0.30 m | 0.257 | 0.472 ✗ |

| 표본율 | 29.5 ~ 30.5 Hz | 30.0021 | — |

**v4 는 4개 항목에서 떨어진다.** 게이트가 실제로 갈린다는 판별 근거다.
미판정(대조 불가)이 하나라도 있으면 PASS 가 아니다 — `INCOMPLETE` 로 나온다.

## 5. 예측 (결과 보기 전 기록)

- **편 길이·경로 비**: 현석 프로토콜을 그대로 따라 찍으면 통과할 것으로 본다.
  참조 집단은 현석 s22_pick_v3 다 (1.63 / 99프레임)
- **파지 개구 폭**: 3mm 안에 들어올 것으로 본다. 같은 물체·같은 그리퍼면 현석 1.4mm 수준
- **EEF 폭**: 태그 원점이 바뀌면 절대 좌표는 달라지지만 **폭**은 0.3m 안일 것으로 본다
- **가장 위험한 항목은 회전 크기 폭**이다. 현장에서 여러 사람이 찍거나 손목 각도가 바뀌면
  0.35 rad 를 넘길 수 있다. 넘기면 편 수를 줄이더라도 시연자를 한 명으로 고정한다

빗나가면 방향까지 기록한다.

## 6. 수집 후 순서

1. 20편 → `--gate` 판정 → PASS 면 프로토콜 확정, FAIL 이면 **다시 찍는다**
2. 나머지 수집 (목표 100편)
3. `convert_v10_to_umi` 로 변환 → 앵커 규약 확인 `probe_chunk_anchor.py`
   (v10 74편은 ANCHOR 오차 0.0000mm 였다. 새 배치도 같아야 한다)
4. 학습 전 baseline 선측정. baseline 없이 고급 모델로 넘어가지 않는다
5. 평가는 **롤아웃 성공률**이다. validation loss 가 아니다
   (val 0.00547→0.00517 인데 롤아웃 0% 그대로였던 실증이 있다)

## D-AI-47 (제안 v2) — `command` 와 `relative_target_trajectory` 를 나눠 추가한다

**작성** 김준태(트랙 B) · **수정 제안** 황도경(트랙 A) · **합의 필요** 양 트랙

### 무엇을

```
action                       (6,) float32   계약 그대로 state[t+1] 유지
command                      (6,) float32   실제로 내린 명령. 시뮬·로봇 원격조작에만 존재
relative_target_trajectory   (K, D)         UMI. 사람이 이동한 미래 상대 파지 궤적
```

`action` 의 정의와 `validate()` 의 `action[:-1] == state[1:]` 검사는 **그대로 둔다.**

### 왜 두 개로 나누나 — 트랙 A 회신이 이걸 정했다 🟢

v1 초안은 `command` 하나였다. 실수집 UMI 에서 `ctrl` 을 역산할 수 있다는 전제였다.
**그 전제가 틀렸다.**

트랙 A 확인 (2026-09-14, 황도경) — UMI raw 에 기록된 것은:

```
ARCore 카메라 pose · 이미지 · 그리퍼 gap · IMU · tracking 정보
```

`ctrl`·EEF 목표 pose·IK 입력 목표 같은 **명령값이 없다.** `ctrl - qpos` 를
정확히 역산할 수 없다.

⚠️ **없는 명령값을 추정해 `command` 로 저장하지 않는다.** 그러면 계측기를 위조하는
것이고, 이후 어떤 결과도 원인 귀속이 불가능해진다. 트랙 A 판단에 동의한다.

핸드헬드 UMI 에는 controller command 가 **물리적으로 존재하지 않으므로**, 같은
필드에 넣으면 의미가 다른 두 가지가 섞인다. 그래서 이름을 나눈다.

### 근거 — `action = state[t+1]` 이 학습을 무력화한다 🟢

같은 데이터 59편, 같은 시드, 같은 설정. 타깃만 다르게 독립 학습 3회 × n=100.

| 타깃 | 성공률 | 95% 구간 | 닫는 순간 |
|---|---:|---|---|
| `action = state[t+1]` | 0/300 = 0.0% | [0.0, 1.3] | 158.1 / 158.4 / 158.3mm |
| `state[t+2]` | 0/300 = 0.0% | [0.0, 1.3] | — |
| **`command = ctrl`** | **22/300 = 7.3%** | **[4.9, 10.9]** | 45.2 / 42.5 / 48.8mm |

조건: MuJoCo 3.12.0 EGL · 30Hz · 2cm 20g 큐브 · 지터 ±50mm · `cam_wrist` 1대 ·
`joint_delta_gripper_binary` · 학습 시드 0·1·2 · 평가 시드 3000~3099

158mm 는 **다섯 조건에서 폭 0.4mm 로 재현**됐다.

**`state[t+k]` 로는 대체되지 않는다** (lead2 기각, `MEASURE_lead_sweep_0914.md`).
`ctrl` 의 값어치는 리드가 아니다.

### 되돌릴 조건

- `command` 로 학습해도 게이트 20% 를 못 넘는 상태가 지속되면 → 필드는 유지하되
  "이것으로 충분하다"는 주장은 철회한다
- `cmd_noise96`(이미지 파괴 대조군)에서 성능이 안 떨어지면 → 7.3% 는 상태 기반
  지름길이고, 이 결정의 근거가 약해진다. **실행 중, 결과 대기**

## 미결 — `relative_target_trajectory` 의 계약 차원 🔴

트랙 A 의 v6 는 다음 구조다 (2026-09-14 회신):

```
원본 UMI pose 에서 현재 파지점 기준 미래 상대 SE(3) 궤적
0.1~0.8초의 8-step action chunk 예측
robot base 등록·IK 는 학습 라벨에서 제외하고 실행 시점에 적용
```

⚠️ **이것은 필드 추가가 아니라 텐서 모양 변경이다.** 현행 계약은 관절 (6,) 단일
스텝이고 v6 는 EEF 상대 SE(3) × 8스텝이다. **트랙 B 의 학습·평가 코드가 전부
(6,) 를 가정한다.** 합의 전에 v6 로 본수집을 쌓으면 그 데이터를 학습에 넣을
경로가 없다.

확정해야 할 것 — 전부 수집 착수 전:

1. **차원과 표현** — SE(3) 를 무엇으로 직렬화하나 (6D 회전? 쿼터니언? 행렬?)
2. **좌표계** — "현재 파지점 기준" 의 기준 프레임 정의
3. **청크 길이 K 와 시간 간격** — 0.1~0.8초가 8스텝이면 100ms 간격인가
4. **그리퍼 채널** — 궤적에 포함인가 별도인가
5. **패딩 규약** — 에피소드 끝에서 K 스텝이 모자랄 때

## 미검증 — v6 의 전제 🟡

v6 타깃(사람이 이동한 미래 궤적)은 성질상 `state[t+k]` 계열이다. 트랙 B 는
오늘 `state[t+2]` 를 기각했다 — **다만 그 실험에는 제어 게인 교란이 있었다**
(k틱 변위를 1틱 목표로 전송, 게인 k배). v6 는 8스텝을 8스텝에 걸쳐 실행하므로
그 교란이 없다.

**따라서 트랙 B 의 0/300 은 v6 를 부정하지 않는다. 동시에 v6 가 된다는 근거도 없다.**

이 질문은 UMI 데이터 없이 시뮬에서 답할 수 있다 — S15P21A103-171(청킹).
**그 결과 전에 v6 로 본수집에 들어가지 않기를 권고한다.**

## 미검증 — 실행 시점 시간 확대 🟡

트랙 A 계획: 학습 라벨은 원본 시간 유지, 로봇 실행 단계에만 시간 확대.

청크 안(열린 루프)은 문제없다. **청크 경계에서 다음 관측을 받을 때, 정책이 보는
장면의 속도가 학습 분포 밖이다.** 확대 배율을 메타에 기록하면 트랙 B 가 영향을
수치로 낼 수 있다.

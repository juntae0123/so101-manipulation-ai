## 근거가 된 이번 측정

### 카메라 마운트 (1·2번)
```
카메라 세타 기울기 → 작업거리 0.25m 에서 겉보기 이동 L*tan(세타)
  2도 8.7mm · 5도 21.9mm · 10도 43.7mm
파지 여유 +-25mm = (개구 90 - 물체 40) / 2
→ 5도면 여유를 거의 다 먹는다
```
- hand-eye 오차는 **상수 편향이라 학습이 지우지 못한다** (+-10mm 재생 3/4) 🟢
- `motor_control/urdf/so101_ver1.urdf` 링크 12개 전수 확인 — **카메라 링크 0개** 🟢

### 그리퍼 (4번) — URDF 실측 🟢
```
gripper         prismatic [0, 0.09]     총 개구 90mm
gripper_right   prismatic [0, 0.045]
gripper_mirror  prismatic [0, 0.045]
```
**사용자(김준태) 진술과 일치한다** — 스프링 상시 개방 90mm, 방아쇠로 닫는다.

⚠️ **기획서 "닫힘 간격 약 1.7cm → 대상물 1.5~2.5cm" 는 URDF 와 안 맞는다.**
URDF 하한은 0 이고, 트랙 A 실측 케이스는 40mm 다. **"대상물 1.5~2.5cm" 는 근거 불분명.**
지침 정정 대상.

### 모터 (3번) — 소스 확인 🟢
`src/st3215_bus.cpp` 에 `read_position` / `read_positions` 가 `PRESENT_POSITION`
레지스터로 구현돼 있고 `write_position` 과 **별개 경로**다.
⚠️ **토크 disable 명령은 이 파일에 없다.** 백드라이브하려면 추가 구현이 필요하다.

### 5스킬 대상물 (6번)
`run_side_expert` 는 물체 위치는 따라가지만 크기·높이를 못 따라간다 🟢
높이 50mm 박스에서 **0/60**, 물체 이동량 정확히 0.0000.

## 6축 전환은 요청하지 않는다 — 명시적으로

9/17 에 "실 시연 전체 궤적 IK 29.2%" 를 근거로 6축 검토 요청 직전까지 갔다.
그건 **궤적 모방 기준**이었고 제품 기조는 결과 모방이다. 파지 기준으로 다시 재니
~~533/535 = 99.6%~~ → **78/90 = 86.7%** (n=10, 2026-09-19 재측정).
**5자유도로 간다** — 판단은 그대로다. 닫힘 pose 는 10/10 도달 가능하다.

⚠️ **2026-09-19 정정**: 99.6% 는 커밋되지 않은 코드로 나온 값이라 재현되지 않는다.
`MEASURE_real_grasp_ik_0917.md` 머리의 정정 블록 참조. **결론은 안 바뀐다.**

병목은 자유도가 아니라 **카메라 마운트 정밀도**로 옮겨갔다.

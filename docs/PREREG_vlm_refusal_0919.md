② target grounding           미측정

```

③이 시연에서 실제로 문제가 되는 지점이다. 지원하지 않는 지시에 아무 스킬이나
고르면 **로봇이 실제로 엉뚱하게 움직인다** (S15P21A103-109 본문).

## 계측 전에 확인한 구조적 사실 🟢

현재 선택 경로는 **강제선택**이다 — `forced_choice_scores` 가 `SKILLS` 5개를
후보로 놓고 그중 argmax 를 낸다. **거절이라는 출력이 존재하지 않는다.**

→ **지금 구조에서 ③은 0%다. 재볼 것도 없이 구조적으로 그렇다.**
   계측기를 만들기 전에 이걸 먼저 적어둔다. "재봤더니 0" 과 "낼 수 없어서 0" 은
   다른 상태다.

그래서 이번에 재는 것은 *"현재 구조가 거절하는가"* 가 아니라
**"후보에 거절을 하나 추가하면 쓸 만해지는가"** 다.

## 🛑 개정 (2026-09-19, 같은 날) — 팔이 둘이 됐다

초판은 **후보에 거절을 하나 추가하는 안** 하나만 재려 했다.
그런데 그건 프롬프트를 바꾸는 안이라 **더 싼 baseline 을 건너뛴 것**이다.
지침 — *baseline 없이 고급 모델로 넘어가지 않는다.*

```
A (baseline)  margin 기권.  프롬프트도 후보도 안 바꾼다.
              forced_choice_scores 가 이미 1등−2등 margin 을 돌려준다.
              그 값이 임계 미만이면 "모르겠다" 로 처리한다. 비용 0
B             후보에 cannot_execute 를 하나 추가한다 (초판안)
```

**A 를 먼저 보고, A 로 충분하면 B 는 안 쓴다.**

### A 의 임계값을 어떻게 정하나 — 결과를 보고 정하지 않는다

```
임계 = 지원 지시 100개 중 **맞힌 항목들의 margin 하위 5 퍼센타일**
```
임계를 **지원 지시 집합에서만** 뽑고, **거절 지시 집합에는 손대지 않는다.**
즉 거절 성능은 임계를 정할 때 쓰이지 않은 자료로 잰다.
이 규칙을 지금(실행 전) 박는다. 실행 후에 퍼센타일을 바꾸지 않는다.

두 가지를 동시에 봐야 한다. 거절만 잘하고 본업을 망치면 쓸 수 없다.
**A·B 각각 같은 게이트로 판정한다.**

```

판정           G1·G2 **둘 다** 통과해야 채택. A 가 통과하면 B 는 안 쓴다
둘 다 미달 시   게이트를 낮추지 않는다. 시연에서는 **FE 화이트리스트**로 막는다 —

⚠️ G2 를 못 맞추면 **게이트를 낮추지 않는다.** 후보 문구를 바꾸거나 n 을 올린다.

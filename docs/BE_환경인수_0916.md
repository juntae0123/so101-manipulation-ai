# BE 인수 — UMI 시뮬 학습 환경 (GPU 서버)

작성 2026-09-16 · 김준태(AI 트랙 B) · 대상 최은찬(BE)

## 무엇을 주는가

`requirements_sim_server.txt` — UMI 시뮬 데이터 생성 + 정책 학습이 도는
파이썬 환경 목록. 서버에 DB·인프라 올릴 때 같은 GPU 서버에 얹는 학습
워커가 이 환경을 쓴다.

## 설치

```bash
# [서버]
conda create -n handoff312 python=3.12.14 -y
conda activate handoff312
pip install torch==2.13.0+cu126 torchvision==0.28.0+cu126 \
  --index-url https://download.pytorch.org/whl/cu126
pip install -r requirements_sim_server.txt
```

## 반드시 지켜야 하는 것 2개

**1. torch 는 cu126 계열이어야 한다** 🟢 실측
서버 GPU 는 Tesla V100 = Compute Capability 7.0(sm_70).
`torch 2.11.0+cu128` 은 sm_75 이상으로만 빌드돼 있어서
`CUDA error: no kernel image is available for execution on the device` 로
죽는다. `torch 2.13.0+cu126` 의 `get_arch_list()` 에는
`['sm_50','sm_60','sm_70','sm_75','sm_80','sm_86','sm_90']` 이 있고
실연산도 통과했다.

검증 명령 (환경 세팅 후 반드시 1회):
```bash
# [서버]
python -c "import torch;print(torch.__version__, torch.cuda.get_arch_list());print('실연산:', (torch.ones(4,device='cuda')*1).tolist())"
```
`torch.cuda.is_available()` 만 보면 안 된다 — True 가 나오는데 커널이 없어서
학습에서 죽는다. **가용성 확인은 기능 확인이 아니다.**

**2. 헤드리스 렌더는 `MUJOCO_GL=egl`**
서버에 디스플레이가 없어서 이게 없으면 MuJoCo 가 씬을 못 연다.
학습 워커 프로세스의 환경변수에 박아둬야 한다.

```bash
MUJOCO_GL=egl CUDA_VISIBLE_DEVICES=2 python -m umi_adapter.train ...
```

## GPU 배정

- 쓸 수 있는 GPU: **1, 2, 3, 4, 6** (0·5·7·8·9 는 다른 사람 것)
- NVLink 가 없는 PCIe 구성이라 DDP 보다 **GPU 당 독립 잡**이 맞다
- 학습 워커를 큐로 돌릴 때 `CUDA_VISIBLE_DEVICES` 를 잡 단위로 하나씩 배정

## 미확정 — 그대로 쓰면 안 되는 부분

- 🟡 **목록 전체 조합은 아직 서버 학습 스모크를 통과하지 못했다.**
  torch 줄만 실측이고 나머지는 handoff 패키지 원본 핀 그대로다
- ⚠️ `numpy==2.2.6` 이 원본 핀인데, torch 강제 재설치가 2.5.2 로 올려버린
  상태다. opencv / numba / zarr 와 충돌하는지 미확인.
  스모크가 통과하면 그 조합으로 이 파일을 갱신해서 다시 보낸다
- 학습 큐 API·DB 스키마는 이 문서 범위 밖이다 (BE 설계)

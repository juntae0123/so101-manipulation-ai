**해석 🟡**: E2 에서 B 가 크게 이긴 이유의 상당 부분이 **A 조건이 축 틀어진 데이터로 학습해

⚠️ **귀속 불가**: 데이터셋도 70편 → 74편으로 바뀌었다. 축 수정 단독 기여로 자를 수 없다.
가르려면 같은 74편을 축 수정 전/후로 변환해 비교해야 한다. 미실행.

## 6. ⚠️ 진짜 걸릴 것 — 로봇 파지점 정의 78.1mm 🟢

같은 이름의 값이 저장소에 둘이다.

```
AI/configs/so101.yaml              pinch_offset_local [0, 0, −0.080]        레거시
AI/configs/grasp_so101_ver1.yaml   pinch_offset_local [0, 0, −0.158118819]  ver1 (실물)
차이 78.118819 mm
```

`grasp_so101_ver1.yaml` 주석 원문: *"레거시 −0.080 대비 78.1mm 더 길다. 도경님 회신의
78mm 와 일치."* 그리고 헤더에 *"학습·수집 파이프라인은 `configs/so101.yaml` 을 그대로 쓴다."*

**실물은 ver1 인데 파이프라인 기본값은 레거시다.**

```
어댑터가 so101.yaml 값을 쓰면   접근축 방향 78.1mm 상수 편향
그리퍼 개구                      90 mm
물체 폭                          41 mm
파지 여유                        ±25 mm  = (90 − 41)/2
```

**78mm 편향이면 확정적으로 빗나간다.** hand-eye 계열 상수 편향은 학습이 지우지 못한다
(±10mm 에서 재생 3/4 🟢).

추가: **ver1 은 jaw 축도 바뀌었다.** gripper 로컬 `(−0.048656744, 0.998815559, −0.000003629)`,
레거시 jaw(+X) 기준 로컬 +Z 주위 **+92.79도**. 현행 `solve_pose_ik` 는 접근축만 구속하고
jaw 를 구속하지 않으므로 **`wrist_roll` 로 보정해야 한다.**

→ 트랙 A(황도경) 오프라인 IK 가 어느 값을 쓰는지 확인 대기. **추정하지 않는다.**

🟡 미검증: handoff(현행 시뮬 메인 경로)에는 `pinch` 문자열이 grep 0건이다. MJCF site 로
잡는 것으로 보이나 확인 안 했다. 실물 재생 경로에는 시뮬 기하가 안 들어가므로 오늘은 안 걸린다.

## 8. 예측 대조 — 이번엔 과대추정이다

| 대상 | 예측 | 실제 | 방향 |
|---|---|---|---|
| fold 5개 부호 일치 | 통과 | 15/15 통과 | **적중** |
| 효과크기 | 명시 안 함. E2 급 암묵 기대 | 1/5 ~ 1/13 | **과대추정** |

어제까지의 편향은 일관되게 **과소**추정이었는데 이번엔 반대다.
원인: **참조집단을 "축수정 전 E2"로 잡았다.** 그건 A 조건이 불리했던 집단이다.

→ **추가 규칙: 조건이 바뀐 실험을 참조집단으로 쓰지 않는다.** 바꾼 조건이 어느 팔을
   유리/불리하게 했는지 먼저 따진다.

또 하나 — **효과크기를 사전등록하지 않았다.** 부호만 박았다. 부호는 n 만 키우면 거의
통과하므로 게이트로서 약하다. 다음부터 **최소 의미 효과크기를 같이 박는다.**

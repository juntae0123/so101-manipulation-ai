## 3. ⚠️ 판정 기준이 문서와 코드에서 다르다 🔴

`simulation/evaluate.py` 의 성공 조건:

```python
ok = contact['bilateral'] and not contact['table_contact']
     and z > initial_z + 0.1                                    # <- 하드코딩 0.1
     and coupled and side_ok
     and sum(qpos[fids]) < env.task.get('success_max_width',.06) # <- config 를 읽는다
success = max_hold >= 0.5
```

**`can_slam.yaml` 의 `lift_height: 0.13` 은 어디에도 쓰이지 않는다.**
바로 옆줄 `success_max_width` 는 config 를 읽는데 리프트만 코드에 박혀 있다.

같은 100편을 기준만 바꿔 읽으면:

| 리프트 기준 | 통과 | 95% 구간 | |
|---|---:|---|---|
| ≥ 0.10 m | 100/100 | [96.3, 100.0] | **코드가 실제로 쓰는 값** |
| ≥ 0.11 m | 94/100 | [87.5, 97.2] | |
| ≥ 0.12 m | 42/100 | [32.8, 51.8] | |
| ≥ 0.13 m | 2/100 | [0.6, 7.0] | **config 가 적어둔 값** |
| ≥ 0.14 m | 0/100 | [0.0, 3.7] | |

리프트 분포 폭이 30mm(0.1057~0.1356)라 **기준이 그 안에 있으면 결과가 급변한다.**

### 어느 쪽이 맞나 — 판단 보류

0.1m 이 부당한 기준은 아니다. 캔 높이가 101mm 이므로 0.1m 리프트면 테이블에서
완전히 뜬 상태다. 0.13 은 더 보수적일 뿐이다.

**문제는 둘이 다르다는 것이다.** "성공률 100%" 를 인용할 때 어느 기준인지
아무도 알 수 없다. 기준 확정은 팀 결정 사안이고, 확정 전까지 이 수치는
**"리프트 0.1m · 유지 0.5s 기준"** 을 반드시 병기한다.

## 4. 정책 자체는 일관적이다

리프트 중앙 0.1192m, 폭 30mm. **매번 거의 같은 높이까지 든다.**
0.1 초과 여유가 최소 +5.7mm, 중앙 +19.2mm 다. 실패 0편.

첫 파지 자세도 안정적이다:

```
first_grasp_vertical_component      중앙 0.00924 (side_ok 기준 < 0.5)
first_grasp_pad_height_from_center  중앙 0.00542 m (기준 < 0.03)
```

즉 이 수치는 "겨우 통과" 가 아니라 **판정 조건 안쪽 깊숙이** 들어와 있다.

## 5. 이 측정이 답하지 않는 것 — ⚠️ 가장 중요

### ① 정책이 손목 카메라를 실제로 쓰는가 — 미측정

물체 배치 변동이 **x 30mm × y 70mm** 뿐이다. 내 시뮬 조건(xy 지터 ±50mm,
100×100mm)의 1/5 면적이다. **이 크기면 이미지를 안 보고 고정 궤적으로도
100% 가 나올 수 있다.**

`VALIDATION.md` 가 "카메라 내부·외부 파라미터는 실제 S22 측정값이 아닌 임시
설정", "근거리 클리핑·카메라 배치 문제가 남아 있음" 이라고 적어둔 상태라
더 확인이 필요하다.

검증 두 단계 (진행 중):
1. **배치 확장** — x [0.350, 0.450] · y [-0.050, 0.050] 로 넓혀 n=100.
   코드 무수정, config 만. 게이트는 착수 전 확정: 하한 80% 이상이면 위치에
   반응, 50% 미만이면 좁은 영역에 맞춰진 것, 그 사이는 보류
   ⚠️ x 끝단(0.44~0.45)이 도달 밖일 수 있다. 실패 편의 물체 x 를 분해해
   도달 한계와 정책 문제를 구분한다
2. **이미지 어블레이션** — 학습된 체크포인트 그대로, 추론 시점 이미지만 파괴
   (`policy/perturb.py` 의 noise/blackout/freeze). 코드 소량 수정 필요

### ② 학습 재현성 — 미측정

HW 는 1회 학습이다. 같은 데이터로 다시 학습했을 때 편차를 모른다.
트랙 B 실측으로는 같은 데이터·같은 설정에서 성공률이 25%p 갈린 적이 있고,
cuDNN 비결정이 원인으로 확인됐다(0916). 이 경로도 같은 검사가 필요하다.

### ③ 실물 성능

전부 시뮬이다. 시뮬 성공률은 sim2real 갭의 **하한**이다.
카메라 파라미터가 임시 설정이므로 실 UMI 영상으로 바꿨을 때의 성능은 미지수다.

### ④ 트랙 B 수치와의 직접 비교

물체(2cm 큐브 vs 66mm 캔)·파지(상단 vs 측면)·주기(30Hz vs 10Hz)·
회전표현(관절각 vs axis-angle)이 전부 다르다. **같은 표에 놓을 수 없다.**

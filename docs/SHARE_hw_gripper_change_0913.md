## 0. 세 줄

1. **SO-101 그리퍼가 교체됐습니다.** 양쪽이 중앙으로 닫히는 평행 그리퍼, 개구 **0~90mm**.
   시뮬은 아직 옛 그리퍼(한쪽 턱, 5.3~79.4mm)를 씁니다
2. **어제 제가 낸 "그리퍼가 안 닫힌다"는 오독입니다.** 시연 대상물이 41mm였고,
   마커 평탄 구간 38~40mm는 **그 물체를 쥔 상태**입니다. 정상 동작이었습니다
3. **계약의 `gap_m` 0~0.090 → [-1,1] 은 신 그리퍼 URDF 범위 그대로입니다.**
   제가 "시뮬과 계약의 정규화가 다르다"고 한 것도 틀렸습니다 — 계약이 맞고 시뮬이 낡았습니다

## 1. 실물 그리퍼 (URDF ver1)

```
gripper         prismatic  lower=0  upper=0.09       ← 전체 개구 폭 [m]
gripper_right   prismatic  0~0.045  mimic ×0.5
gripper_mirror  prismatic  0~0.045  mimic ×0.5
pinion_passive  revolute   mimic ×-27.7778
```

`BACKEND_INTERFACE.md`:

> `/gripper_controller/commands` · `data[0]`: **full gripper opening width in metres**
> Valid range: `0.0` (closed) to `0.09` (open)

메시도 바뀌었습니다 — `assets/ver1/`: `finger_left` · `finger_right` · `holder_left/right`
· `pinion` · `drive_motor`. 옛 `moving_jaw_so101_v1.stl` 이 아닙니다.

| | 실물 (ver1) | 시뮬 (`configs/so101.yaml`) |
|---|---|---|
| 관절 종류 | **prismatic** | revolute |
| 범위 | 0~0.09 m | −0.175~1.745 rad |
| 개구 | **0~90mm** | 5.3~79.4mm (`gap_curve`) |
| 폐쇄 | **양쪽 중앙으로** | 한쪽 턱만 |
| 명령 단위 | 미터, 폭 그대로 | 정규화 관절각 |

## 2. 제가 되돌리는 것

**① "수집분 그리퍼가 끝까지 닫히지 않는다" — 철회합니다.**

대상물이 41mm이므로 38~40mm 평탄 구간은 물체를 쥔 상태입니다.
`gap < 30mm` 가 0.09%인 것도 41mm 물체를 쥐고 있으니 당연합니다.
저는 "닫힘 = 0mm 까지 가야 한다"를 전제로 읽었는데, 물체가 있으면 거기서 멈추는 게 맞습니다.

**② "대상물이 커서 SO-101이 못 잡는다" — 철회합니다.**

신 그리퍼는 0~90mm입니다. 41mm를 잡을 수 있습니다.
재수집 필요 판정의 근거로 이걸 쓰면 안 됩니다.

**③ "시뮬과 계약의 그리퍼 정규화가 다르다 (D-AI-43 합의 필요)" — 철회합니다.**

계약 `gap_m` 0~0.090이 신 그리퍼 URDF 범위와 같습니다.
도경님 규약이 맞고, 제가 옛 시뮬 config를 기준으로 봐서 불일치라고 했습니다.

## 3. 그래도 남는 것

**시뮬이 옛 그리퍼로 돌고 있습니다.** 이건 여전히 고쳐야 합니다.

| | |
|---|---|
| 🟢 유효 | 마커 검출 대조 (영상 처리 비교, 그리퍼 모델 무관) |
| 🟢 유효 | 같은 시뮬 안의 **조건 간 비교** — 손목 전용 vs 2대 카메라 51.4% [47.0, 55.8] 등 |
| ✗ 무효 | 시뮬 개구 mm 를 실물 규격으로 옮긴 문장 전부 |
| ✗ 무효 | 0912 폐쇄량 스윕의 실물 해석 (도구·수치 자체는 시뮬 안에서 유효) |

**팔 관절에서도 하나 어긋납니다.**

```
elbow_flex   URDF  [-1.57080, 1.69]
             시뮬  [-1.69000, 1.69]      ← 하한이 0.119 rad 더 넓다
```

나머지 4축(`shoulder_pan`·`shoulder_lift`·`wrist_flex`·`wrist_roll`)은 소수점까지 같습니다.
시뮬이 실물보다 팔꿈치를 더 접을 수 있다고 보고 있으므로,
**도달 가능 영역 63.9%가 과대일 수 있습니다.** 재측정 대상입니다.

이 값이 틀리면 UMI 실행가능성 검사기(이슈 113)도 틀린 수용률을 냅니다.

## 4. 확인 요청

**HW·PM — 타겟 대상물 규격의 근거**

프로젝트 문서의 "그리퍼 닫힘 시 손가락 간격 약 17mm → 대상물 1.5~2.5cm"에서
**17mm는 옛 `moving_jaw` 스펙으로 보입니다.** 신 그리퍼는 0mm까지 닫힙니다.

15~25mm 규격이 그 값에서 나온 것이라면 근거가 사라집니다.
타겟 도메인(다품종 소량생산 소형부품)의 실제 부품 폭 범위를 다시 정해야 합니다.

**PM — 재수집 판단이 바뀝니다**

기계적으로는 41mm를 잡을 수 있으므로 "못 잡아서 재수집"은 아닙니다.
남는 것은 **도메인 정합성**입니다 — 타겟이 15~25mm인데 시연을 41mm로 했습니다.
이번 주가 개발 마지막 주이므로, 재수집 여부를 오늘 정해야 합니다.

**MW·HW — 그리퍼 변경 이력**

교체 시점과 이유, 그리고 앞으로 추가 변경 예정이 있는지 알려주시면
시뮬·configs 재정렬을 한 번에 하겠습니다.

**트랙 A — 캘리브레이션 재적합 검토**

검증점 두 개에서 부호가 반대입니다 🟡.

```
실제 30mm → 측정 31.06mm        (+1.06 과대, midpoint_check)
실제 41mm → 마커거리 88.9mm      → 37.3mm 로 읽힘 (−3.7 과소)
```

41mm가 확정됐으니 이제 두 점으로 재적합할 수 있습니다.
선형식이 두 점을 동시에 못 맞추면 비선형이거나 개방측 기준점(134mm)이 어긋난 것입니다.

## 5. 제가 이어서 하는 것

1. `configs/so101.yaml` 을 `so101_ver1.urdf` 기준으로 정렬 (그리퍼 + `elbow_flex` 하한)
2. 도달 가능 영역 재측정 — 63.9%가 얼마나 과대였는지
3. 그 위에서 UMI 실행가능성 검사기(이슈 113) 착수

시뮬 그리퍼 모델 교체는 씬 MJCF를 건드려야 해서 **[ROS] 이슈 63 소속**입니다.
AI 파트가 작업하더라도 이슈는 그쪽으로 잡겠습니다.

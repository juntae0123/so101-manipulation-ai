# 규칙 — 계측기를 쓰기 전에 지킬 것

- 작성 김준태(트랙 B) · 2026-09-16 · 근거 `TS_instrument_empty_field_0915.md` 🟢
- 자동 검사 `python tools/lint_instruments.py` (커밋 전 필수)

---

## 0. 왜 있나

2026-09-15~16 이틀에 **같은 병의 계측기 결함이 6건** 나왔다.
전부 "없음" 과 "정상" 이 같은 출력을 내는 형태였고, **전부 사전에 알 수 있는 것**이었다.

6건을 겪고 TS 문서에 규칙을 적었는데, **그 다음 날 아침 새로 만든 계측기가
그 규칙 첫 줄을 어겼다.** 문서만으로는 안 고쳐진다는 게 증명됐다.

그래서 이 문서는 두 부분이다 — **린터가 잡는 것**과 **사람이 지킬 것**.
린터가 잡을 수 있는 규칙은 전부 린터로 옮겼다. 남은 것만 여기 글로 있다.

---

## 1. 원칙 하나

> **"없음" 과 "괜찮음" 이 같은 모양으로 나오는 검사는 검사가 아니다.**

집합 연산·필터·`get()` 기본값·`grep` 카운트·빈 리스트 집계가 전부 이 성질을 가진다.
빈 입력이 들어오면 조용히 "문제 없음" 을 출력한다.

파생 규칙:

> **비교하거나 판정하는 값은 비어 있으면 죽는다.** 빈 값을 비교에 넣지 않는다.

---

## 2. 린터가 잡는 것 — 커밋 전에 돌린다

```
# [서버] 또는 [로컬]
python tools/lint_instruments.py            # 🔴 있으면 종료코드 1
```

| 규칙 | 무엇 |
|---|---|
| `grep-c-in-and-chain` | `grep -c` 는 0건이면 종료코드 1. `&&` 사슬이 끊긴다 |
| `zero-or-more-number` | `[0-9.]*` 는 0개 이상이라 **숫자 없이도 매칭**된다 |
| `compare-without-empty-check` | 명령치환 결과를 빈 검사 없이 비교 → 빈 값끼리 "같다" |
| `grep-case-sensitive-status` | `skip` 만 찾으면 `SKIP`·`INVALID` 를 놓친다 |
| `no-set-u` | 오타난 변수가 빈 문자열로 퍼진다 |
| `bare-except-pass` | 예외를 삼켜 실패가 정상처럼 보인다 |
| `minmax-without-guard` | 빈 입력에 `min`/`max`. `default=` 가 결과로 둔갑 |
| `float-equality` | 부동소수 동등 비교 |

억제하려면 같은 줄에 `default=` 를 두거나(minmax), `# 의도` 주석을 단다(float).

## 3. 린터가 못 잡는 것 — 사람이 지킨다

### ① 모수를 같이 찍는다

```
나쁨   print('교집합:', a & b)
좋음   print('찾음 %d / 전체 %d' % (len(a), len(all)));  print('교집합:', a & b)
```

**찾은 개수가 전체와 다르면 그 자리에서 눈에 띈다.**
2026-09-15 에 없는 필드를 조회해 빈 교집합이 나왔고, `n=0` 을 같이 찍어둔 것이
유일한 단서였다. 그게 없었으면 "시드 분리 확인됨" 으로 넘어갔을 것이다.

### ② 부분합이 전체와 다르면 죽인다

경고 출력이 아니라 **종료코드**다.

```python
print(f"시도 {total} = 저장 {n_ok} + 도달불가 {n_skip} + 계약위반 {n_bad}")
if n_ok + n_skip + n_bad != total:
    raise SystemExit(4)   # 집계되지 않는 폐기 경로가 있다
```

폐기 경로가 하나 더 생기면 그날 바로 죽는다. 사람이 눈으로 검산하게 두지 않는다.

### ③ nan 은 비교에서 항상 False 다

`nan` 이 섞이면 `min`/`mean` 이 조용히 `nan` 을 돌려주고, `nan > gate` 는 항상
False 라 게이트를 **통과처럼** 지나간다.

- `np.nanmean` 계열을 쓰거나, **먼저 nan 개수를 세어 0 이 아니면 보고**한다
- 결과표에 nan 이 나오면 그 행은 값이 아니라 **결함 신호**다

(린터에 넣었다가 뺐다 — `max(1, int(seconds * rate))` 같은 줄을 전부 잡아 오탐이 많다)

### ④ 종료 신호 문자열은 다른 맥락을 먼저 확인한다

`grep` 이 매칭됐다는 것은 그 줄이 있었다는 뜻이지 그 **의미**였다는 뜻이 아니다.

실제 사례 — 큐 진행 스크립트가 완료 판정에 `배포 불가` 를 썼는데,
`eval/rollout.py` 가 특권 baseline 마다 `(특권정보 사용 — 실물 배포 불가)` 를 찍어
롤아웃 1회만 끝나도 "완료" 가 됐다.

### ⑤ 진단 명령은 `;` 로 잇는다

`&&` 는 **실패 시 뒤를 막아야 할 때만**. 0건이 정상인 명령을 게이트로 쓰지 않는다.

### ⑥ 조건을 바꿨으면 조건에 적는다

EXP_LOG 의 `conditions` 에 안 들어간 변수는 **존재하지 않는 것과 같다.**
같은 키로 조회되는 다른 실행끼리 서로의 수치를 집어간다.

실제 사례 — `eval/repeat.py` 가 학습 기록을 (데이터, 시드) 로만 찾아
8잡 병렬 실행이 서로의 `val_loss` 를 가져갔다. `out`·`chunk` 를 넣어 고쳤다.

새로 추가한 인자는 **반드시** `conditions` 에도 넣는다.

### ⑦ 사이드카·부가 파일은 개수를 검증한다

사이드카가 없으면 **조용히 계약 `action` 으로 되돌아가는** 코드 경로가 있으면 안 된다.
없으면 즉시 실패한다. 병합·필터 도구는 `npz 수 == 사이드카 수` 를 검사한다.

### ⑧ 시드를 고정했다고 재현된다고 믿지 않는다

`torch.manual_seed` 만으로는 **CUDA RNG 도 cuDNN 알고리즘 선택도 덮이지 않는다.**
필요한 것: `torch.cuda.manual_seed_all`, `np.random.seed`, `random.seed`,
그리고 `--deterministic`(cudnn).

⚠️ 그래도 **재현된다고 선언하지 말고 측정한다** — `tools/check_reproducibility.sh`.

### ⑨ 계측기를 만들면 기존 데이터에 한 번 돌려본다

이 린터도 만든 날 116개 파일에 돌려 오탐 4건을 걷어냈다.
**오탐이 많은 계측기도 고장난 계측기다** — 아무도 안 쓰게 되고, 그러면 없는 것과 같다.

## 4. 도구를 쓰기 전 체크리스트

```
[ ] 판정에 쓰는 값이 비었을 때 죽는가
[ ] 집계에 모수를 같이 찍는가
[ ] 부분합을 검산하고, 안 맞으면 종료코드를 내는가
[ ] nan 이 섞일 수 있는가. 세는가
[ ] 종료·성공 신호 문자열이 다른 맥락에서도 나오는가
[ ] 새 인자를 conditions 에 넣었는가
[ ] 사이드카·부가 파일 개수를 검증하는가
[ ] python tools/lint_instruments.py 가 🔴 0 인가
```

## 5. 기록된 사례

| # | 어디 | 모양 |
|---|---|---|
| 1 | 시드 누설 검사 | 없는 필드 조회 → 빈 교집합을 "분리됨" 으로 |
| 2 | `st.sh` 완료 판정 | 다른 맥락의 부분 문자열을 종료 신호로 |
| 3 | `grep -c` 게이트 | 0건이 종료코드 1 → 사슬 중단 |
| 4 | 수집 요약 | 폐기 경로 둘 중 하나만 집계 |
| 5 | 로그 grep | 소문자만 찾아 `SKIP`·`INVALID` 누락 |
| 6 | 재현성 계측기 | `[0-9.]*` 가 빈 매칭 → 빈 값끼리 "같다" |

6번은 1~5 를 문서로 적은 **다음 날 아침**에 냈다. 그래서 린터가 있다.

## 왜 지금

**실물에는 3인칭 카메라가 없다.** 사용자 구두 확인 🔵 (2026-09-11):

> "우리 카메라 2대는 UMI 그리퍼와 로봇팔에 하나씩 같은 각도로 촬영하는 게 끝이다."

두 카메라는 **같은 시점을 두 번 구현한 것**이다 — UMI 핸드헬드에 1대(시연 수집용),
로봇팔에 1대(실행용), 같은 각도. **동시에 켜지지 않는다.**
추론 시점에 정책이 보는 이미지는 **1장**이다 🟡(내 추론).

그런데 시뮬·계약은 `cameras.count: 2` 이고 그중 하나(`cam_front`)는
`kind: fixed`, `parent: world` 인 **작업공간 대각 3인칭 고정 카메라**다 🟢.

⇒ 현행 체크포인트(6/69/25)는 **실물에 없는 입력을 요구한다. 그대로는 배포 불가능하다.**
L62 해소 · L76 등재.

## 질문

**3인칭 카메라를 빼면 얼마를 잃는가. 손목 1대로 배포 가능한가.**

## 이미 있는 근사치 🟢

`MEASURE_obs_ablation_0911.md` 의 `donor_front` 조건이 곧
"front 가 쓸모없는 입력이 된 정책"이다 — **완전 짝지어진**(같은 체크포인트) 비교다.

```
seed1   69 → 55   (−14%p)
seed2   25 → 12   (−13%p)
seed0    6 →  3   (바닥 효과, 무효)
```

**단 재학습이 없다.** front 를 아예 빼고 처음부터 학습하면 인코더 용량과
융합층 입력이 손목에 집중된다 (`BCNet.in_dim = feat * len(camera_names) + state_dim`).
따라서 **−14%p 는 비용의 상한이다** 🟡. 이 실험이 그 상한을 실측으로 바꾼다.

데이터는 **재수집하지 않는다.** 기존 2대짜리 에피소드에서 손목만 읽는다

`BCPolicy.act` 는 `self.model.camera_names` 만 순회한다 🟢.

## 계측기 검사 (해석 전에 통과해야 한다)

1. `--random` 스모크가 `--cameras cam_wrist` 로 끝까지 돈다
2. 체크포인트 메타의 `camera_names == ["cam_wrist"]` 다
3. 학습 로그의 `dataset.summary()` 가 카메라 1대를 찍는다
4. 셋 중 하나라도 어긋나면 **해석하지 않는다**

## 사전등록 판정 (결과 전 확정)

**주 판정: 3시드 평균 성공률. 대조군 33.3% 대비.**

| 하락폭 | 판정 | 다음 |
|---|---|---|
| < 15%p | **손목 1대로 간다** | 계약을 `count: 1` 로 바꾼다. D-AI-39 확정. 실물 준비는 손목 마운트·hand-eye 하나에 집중 |
| 15~30%p | **비용이 있다** | 손목 1대로 가되 손실을 인정하고 간다. 보완은 데이터·증강 쪽 (카메라 추가가 아니다 — 실물에 자리가 없다) |
| >= 30%p | **1대로는 부족하다** | 실물 카메라 배치를 HW 와 재논의해야 한다. 3인칭 1대 추가가 가능한지가 W6 MVP 의 선행 조건이 된다 |

**보조 판정**

1. 처리군 최고 시드가 **50% 이상**이면 → 손목 1대 배포 가능성 자체는 확인된 것이다
   (평균이 낮아도 학습 불안정 문제로 분리된다)
2. 처리군 범위 폭이 대조군의 63%p 와 비슷하면 → **문제는 카메라가 아니라 학습 불안정이다.**
   그쪽이 먼저다
3. 처리군 평균이 `donor_front` 근사치(약 −14%p → 19~20%)보다 **높으면** →
   재학습 이득이 실재한다. 낮으면 → 상한 추정이 틀렸다는 뜻이니 이유를 찾는다
4. 실패 에피소드 **최근접 거리**가 대조군(dagger 3.2~4.2mm)과 같은 수준이면 →
   접근 정밀도는 손목만으로 유지된다. 크게 나빠지면 → 3인칭이 **거리 추정**에
   기여하고 있었다는 뜻이다 (단안 손목 카메라의 깊이 모호성)

## 예측 (실행 전) 🟡

- 평균 하락 **8~18%p** (33.3% → 15~25%). 즉 판정 1~2 경계에 걸릴 것이다.
  근거: `donor_front` 가 −13~14%p 인데 재학습 이득이 그중 일부를 되돌린다
- **범위 폭은 여전히 클 것이다** (40%p 이상). 카메라를 줄여도 학습 불안정은 안 고쳐진다
- 최근접 거리는 **거의 그대로**일 것이다. 손목 카메라가 접근 단계의 주력이라는 것이
  절제 실험에서 이미 4.5배로 나왔다 🟢

**크게 빗나갈 때**: 평균 하락이 30%p 를 넘으면 시뮬 성능의 상당 부분이
**실물에 없는 3인칭 시점**에서 온 것이고, 지금까지의 성공률 수치 전부를
배포 관점에서 다시 읽어야 한다.

## 해석 제한

- **짝지어진 비교가 아니다.** 같은 시드라도 신경망 형상이 달라 RNG 소비가 갈린다.
  학습 실행 간 편차 25%p 실측이 있고 대조군 자체의 범위 폭이 63%p 다 🟢 —
  **3 대 3 비교로는 15%p 미만의 차이를 분해할 수 없다.** 판정 1과 2의 경계는
  그래서 약하다. 완전 짝지어진 증거는 `donor_front` 쪽이다
- 시뮬이다. 실물 전이를 보장하지 않는다
- 실물 손목 카메라의 **마운트 위치·FOV 가 미확정**이다. 시뮬 `cam_wrist`
  (`pos [0.06,-0.07,0.02]`, `fovy 70`) 와 일치한다는 보장이 없다 (L62 잔여).
  이 실험은 "3인칭을 빼도 되는가"만 답하고 "손목 배치가 맞는가"는 답하지 않는다
- "같은 각도" 를 **각 엔드이펙터 기준 같은 상대 장착각**으로 읽었다.
  둘 다 외부를 보는 3인칭이라면 이 실험의 전제가 무너진다. **사진·도면 미확인** 🟡

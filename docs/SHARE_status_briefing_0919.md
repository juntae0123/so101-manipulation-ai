## 3. 포지션별 — 저희가 받아야 하는 것

### HW (김현석)
1. **[지금] 1a·1b 안전절차** — 관절 속도·가속도 한계, 비상정지 절차, 설치물 간섭. 이거 없으면 실물 수치가 영원히 0입니다
2. **[지금] 5스킬 대상물 확정** — 이름 · 3축 치수 · 질량. 시연 생성기가 **물체 전용**이라 물체가 바뀌면 전문가 코드를 새로 씁니다 (높이 50mm 박스에서 0/60 🟢)
3. **[이번 주] 로봇팔 카메라 마운트 도면값** — 위치·자세. 각도 5° 틀어지면 작업거리 0.25m 에서 21.9mm, 파지 여유 ±25mm 를 거의 다 먹습니다. **상수 편향은 학습이 못 지웁니다** (±10mm 에서 재생 3/4 🟢)
4. **[이번 주] 카메라 재장착 반복성** — 매번 편향이 달라지면 매번 재캘리브레이션입니다
5. 실물 그리퍼가 **ver1** 맞는지 1줄 확인 (파지점 −0.158118819 m)
6. 브래킷 수정 후 wrist_roll 간섭 재검사 결과

### MW / ROS (신현우)
1. **제어 루프 수용 가능 여부** — 우리는 10Hz 액션 8점 중 **4점을 실행하고 재관측**합니다. 즉 **재관측 2.5Hz**. 이 주기로 궤적을 받아 추종 가능한지
2. **누가 관절로 바꾸나** — 우리 출력은 EEF 상대 궤적 (8,10). 변환기(`AI/tools/policy_to_joints.py`, 자체검증 15/15)는 저희가 만들어 뒀습니다. ROS 쪽에서 쓸지, 인터페이스를 맞출지
3. **놓기 스크립트 5종의 소유자** — 스킬 = 집기(정책) + 놓기(스크립트). 놓기가 0개입니다
4. 실행 중 **정지·복귀** 인터페이스
5. VLM 노드를 Jetson 에 둘지 서버에 둘지 ([ROS] 47 소관). 스킬 선택이 텍스트만으로 되면 서버로 빼고 Jetson 8GB 를 정책이 통째로 쓸 수 있습니다 (제안일 뿐, 결정은 ROS/BE)

### BE (최은찬)
1. **문자열 확정 + 실제 1회 요청 테스트** — `profileKey: "umi-diffusion-default"` · `algorithm: "DIFFUSION_UNET_TIMM_UMI"`. 한 글자 다르면 422. **"인지하고 있다"와 "enum 에 값이 있다"는 다른 상태**라 422 안 나는 것까지 확인 부탁드립니다
2. **`actionSpace` 에 `EEF_RELATIVE_ROT6D` 추가 가부** — 현재 `JOINT_ABSOLUTE`/`JOINT_DELTA` 뿐인데 우리 출력은 EEF 상대 궤적입니다. 이름만 맞추고 텐서 의미가 다르면 조용히 틀립니다
3. **`obsDownSampleSteps` 는 프로필 하나로 고정 불가** — 실 시연 zarr 는 1, 시뮬 zarr 는 3. 요청에 데이터 레이트를 담거나 프로필을 둘로 나눠야 합니다
4. **`controlRateHz` 의미 확정** — 액션 점 10Hz 인지, 재관측 2.5Hz 인지
5. `gripper.csv` 구조검증 7종 반영 여부 (거부는 구조까지만, 도메인 판정은 BE 에 넣지 않음)
6. ckpt 보관·조회 API 형태

### FE
1. **클릭 UI 가 보내는 `skill_id` 문자열** — `pick_place` · `sort_two` · `line_up` · `present_inspect` · `align_fixture` 5개와 **정확히** 일치해야 합니다 (`AI/contract/ids.py` 가 정본)
2. **불가능한 상황의 UX** — 장면에 대상물이 없는데 클릭하면 로봇이 엉뚱하게 움직입니다. "지금은 실행 불가" 를 띄울 자리가 필요합니다
3. 실행 중 상태 표시 + 정지 버튼

### PM
1. **시연 멘트 정정** — "5개 행동을 학습했다" 는 현재 뒷받침 못 합니다. 정확한 표현은 **"파지 정책 1개를 5개 작업이 공유한다"**(안 A). 코드가 이 숫자를 항상 사실대로 출력합니다: `스킬 5개 · 서로 다른 학습 정책 0개 · 실제로 동작하는 스킬 0개` 🟢
2. **기획서 두 군데 정정 필요** — "범용 6축"(실측 5자유도), "닫힘 간격 약 1.7cm → 대상물 1.5~2.5cm"(URDF 하한 0, 실측 케이스 40mm)
3. 6축 전환은 **요청하지 않습니다.** 파지 기준으로 재니 533/535 = 99.6% 🟢. 병목은 자유도가 아니라 카메라 마운트 정밀도입니다

### 트랙 A (황도경)
1. 오프라인 IK 가 쓰는 `pinch_offset_local` — 레거시 −0.080 인지 ver1 −0.158118819 인지
2. jaw 축 **+92.79°** 보정을 누가 넣나 (현행 IK 는 접근축만 구속, jaw 미구속 → `wrist_roll` 로 보정)
3. 도메인 랜덤화에 **카메라 pose 섭동**이 이미 들어가 있는지, 범위가 얼마인지
4. v10 실행 구간 index **0..3** vs 우리 **1..4** — 계약에 어느 경로인지 같이 적어야 합니다
5. 베이스 정렬 좌표

## 4. VLM — "스킬 클릭" 은 어떻게 되나

### 결론: **클릭 경로에 VLM 은 필요 없습니다. 필요한 건 "거부" 입니다.**

제품은 플랫폼에서 5종을 **골라** 실행하는 구조입니다 (D-AI-11/12). 클릭이면 선택은
결정적이고, 거기에 언어모델이 낄 자리가 없습니다. VLM 이 하는 일을 셋으로 쪼개면:

| | 무엇 | 클릭에 필요한가 | 상태 |
|---|---|---|---|
| ① 지시문 → 스킬 5종 선택 | "부품 정렬해줘" → `line_up` | **클릭이면 불필요** (자연어 입력을 열 때만 필요) | 🟢 Qwen2.5-VL-3B **0.83** [0.74, 0.89] n=100 · **텍스트만으로** |
| ② target grounding | "저 빨간 거" → 어느 물체인가 | 물체가 하나면 불필요 | **미측정** |
| ③ 거부 | 지금 장면에서 불가능한 지시 거르기 | **필요** | **미측정** |

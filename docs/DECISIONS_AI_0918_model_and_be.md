## D-AI-60 · 제품 모델 아키텍처를 diffusion 으로 확정

**작성자**: 김준태(트랙 B) · **상태**: 확정 · **양 트랙·BE 통보 완료**

```
확정   공식 UMI diffusion  (train_diffusion_unet_timm_umi_workspace)
       ResNet18 비전 인코더 + UNet [64, 128, 256]
```

### 왜 — 현행 스택에서 게이트를 통과한 경로가 이것뿐이다

| | 현행 스택 게이트 통과 기록 |
|---|---|
| **diffusion** | E1 97.0% [94.4, 98.4] · E3 교차 1.3% · E2 B-A **15/15** CI 0 미포함 (n=69) |
| BC | 현행 스택 기록 **없음**. 트랙 A 트리의 `train_relative_chunk_bc.py` 는 실행 흔적만 확인 |
| ACT | 현행 스택 기록 **없음** |

⚠️ 구 경로 BC/ACT 233/300 = 77.7% 는 **MuJoCo 3.12 · 계약 0.3.0 포맷 · 다른 물체**다.
지침대로 **현행 스택 비교에 쓰지 않는다.** "diffusion 이 BC 보다 낫다"가 아니라
**"diffusion 만 현행 스택에서 검증됐다"** 가 정확한 표현이다.

### 되돌릴 조건
BC 또는 ACT 가 **같은 조건**(동일 데이터셋·동일 게이트·동일 n·사전등록)에서 더 나은
수치를 내면 재검토한다. 조건이 다른 비교는 근거로 받지 않는다.

### 연쇄 영향 (2026-09-18 정정판)

## §정정-1 · "BE 계약이 ACT 전용" 은 어시스턴트 오독

**작성자**: 김준태(트랙 B) · **근거**: 최은찬 구두 확인 (2026-09-18)

BE `모델학습유의사항.md` 의 `algorithm: "ACT"` / `profileKey: "umi-act-default"` 는
**예시 페이로드**였다. 나는 이것을 설정된 enum 의 실제 값으로 읽고
*"현재 ACT 전용, 다른 값은 422 거부"* 라고 D-AI-60 연쇄영향에 적었다. **측정이 아니라 추론이었다.**

최은찬은 **diffusion·공식 UMI 모델 사용을 이미 인지하고 있었다.** 1번의 절반(모델 종류 통보)은
없던 일로 한다.

**남는 것은 문자열 확정 하나다.** 우리가 학습 잡을 발주할 때 이 문자열을 그대로 써야 하고,
한 글자만 달라도 422 다. 제안값을 그대로 박으면 된다.

```json
{ "profileKey": "umi-diffusion-default", "profileVersion": 1,
  "algorithm": "DIFFUSION_UNET_TIMM_UMI" }
```

⚠️ **"인지하고 있다" 와 "enum 에 값이 들어가 있다" 는 다른 상태다.**
발주 전에 실제 문자열로 1회 요청해서 422 가 안 나는 것까지 확인한다. 가용성 확인 != 기능 확인.

**작성자**: 김준태(트랙 B)

어시스턴트는 이를 *"트랙 A 가 채운다고 했으니 해소"* 로 처리했다. **두 군데가 틀렸다.**

1. 출처가 트랙 A 가 아니다. `AI/umi/**` · `AI/tools/umi_*` 소유자는 황도경이다

## D-AI-61 · BE 학습 계약 정렬 요청

**작성자**: 김준태(트랙 B) · **근거 문서**: BE `모델학습유의사항.md` (6절·9.3절·5.1절)

### 1. algorithm / profileKey → §정정-1 로 대체. 문자열 확정만 남음

⚠️ `learningRate` 는 **공식 UMI 기본값을 그대로 쓰고 있어 우리가 명시한 적이 없다.**
확정 전 config 에서 읽어 채운다. **추측값을 계약에 넣지 않는다.**

⚠️ `obsDownSampleSteps` 는 데이터 원본 레이트에 따라 다르다 —
실 시연 zarr(이미 10Hz)은 **1**, 시뮬 zarr(30Hz)은 **3**. 프로필 하나로 고정할 수 없다.
**입력 데이터 레이트를 요청에 담거나, 프로필을 두 개로 나눠야 한다.**

### 2. actionSpace — 우리 출력을 표현할 값이 계약에 없다 · **미해결**

```
문서 기재   JOINT_ABSOLUTE (기본) · JOINT_DELTA
우리 출력   EEF 상대 궤적 (8, 10)
            = 상대 위치 3 + 회전행렬 첫 두 행 6 + 절대 gap 1
```

⚠️ 1번이 예시였다면 2번도 예시일 수 있다. **확인 안 됐다.** 다만 2번은 알고리즘 이름이 아니라
**텐서 의미**라서 예시로 넘길 수 없다 — BE 문서가 직접 경고한다:
*"이름만 바꾸고 tensor 의미가 다르면 안 된다."*

제안: `EEF_RELATIVE_ROT6D` 를 새 값으로 추가.
```
의미      T_next = T_cur @ A_relative  (현재 TCP 를 앵커로 복원)
회전 표현  회전행렬의 첫 두 **행** (열이 아니다)
gap       절대값, 미터, 0 ~ 0.09
샘플 레이트 10Hz · 8점
실행 구간  index 1..4 (0-based) → 0.4초마다 재관측
```
⚠️ **트랙 A v10 경로는 index 0..3 을 쓴다** (황도경 확인, 검증 전). 두 경로가 다르므로
계약에 **어느 경로인지 함께 적는다.**

### 3. Episode ZIP 포맷 — 네 번째 포맷이다

```
BE 계약    meta.json · summary.json · frames.csv · pose.csv · imu.csv · gripper.csv · frames/*.jpg
수집 앱    manifest.json · frames.csv · encoded.csv · accelerometer.csv · gyroscope.csv · video.mp4
v10        상대 EEF 궤적 zarr
공식 UMI   pos3+rot6d+gap zarr
```

**제안: 계약을 바꾸지 말고 우리가 어댑터를 만든다.** `BE ZIP → v10 → 공식 UMI zarr`

**조건 2건은 미확인이다** (§정정-2). 0918 회차는 파이프라인 1회 실행으로 판정한다.
- `pose.csv` 가 SLAM 결과로 채워질 것
- `gripper.csv` 가 비어 있지 않을 것

### 4. gripper.csv 가 비어도 통과한다 — **최은찬 수용 (2026-09-18)**

> BE 문서 5.1: *"`gripper.csv` 가 헤더만 있고 샘플이 0건이어도 입력 자체를 거부하지 않는다."*

**우리 정책은 gap 채널을 쓴다.** E2 에서 gap 개선이 +54.9% 로 세 채널 중 가장 컸다.
비면 학습이 **에러 없이 나빠진다.**

**BE 에 넘긴 검증 스펙 — 구조 검사까지만.** 도메인 판정은 BE 에 넣지 않는다
(물체가 바뀔 때마다 BE 배포가 필요해진다).

`422 INVALID_GRIPPER_CHANNEL` 로 거부:
```
1  샘플 0건
2  헤더가 frame_index,gap_m,status 정확히 3개 (이름·순서·개수)
3  행 수 != frames.csv 행 수        ← 프레임 대응이 깨지면 조용히 어긋난다
4  frame_index 가 0부터 연속 증가 아님 / 중복
5  status 에 D, X 아닌 값
6  gap_m < 0 또는 > 0.15            ← 단위 사고 방지. mm 유입 시 64.23 으로 즉시 걸림
7  status=D 인 행의 gap_m 이 빈칸/NaN
```
거부하지 말고 **숫자만 실어 넘길 것**: `detected` · `total` · `longest_x`.
검출률 임계는 BE 가 정하지 않는다 — 분포를 본 적이 없어 지금 박으면 취향이다.

`longest_x`(status X 최대 연속 길이)를 따로 요구하는 이유: 검출률 70% 여도 결측이
고르게 흩어지면 보간되고 한 덩어리로 몰리면 파지 순간을 통째로 잃는다. 비율만으로는 구분 불가.

**시급성**: 0918 회차는 앱→BE 를 타지 않고 파일로 직접 받는다. 이 검증이 실제로 쓰이는 건
앱 업로드가 BE 에 붙은 뒤다. 🟡 그 경로가 지금 살아 있는지 미확인 —
0911 `meta.txt` 에는 `server_url` 이 있었고 0918 `manifest.json` 에는 없다.

### 5. 계약에 못 채운 값 — 측정 후 확정

| 필드 | 상태 |
|---|---|
| `learningRate` | 공식 UMI 기본값 사용 중. config 에서 읽어 확정 — **우리 몫** |
| `nParams` | **미측정.** ckpt(146MB)에서 계산 — **우리 몫** |
| `frameworkVersion` | 학습기 2.13.0+cu126(V100). **Jetson 추론 버전과 다를 수 있음** |
| `controlRateHz` | 액션 점 10Hz vs **재관측 2.5Hz**. 어느 의미인지 BE 와 확정 |
| `contractVersion` | Jetson 추론 코드와 합의 필요. Jetson 보드 모델명 미확인 |

**추측으로 채우지 않는다.** 확정 전까지 `.env` 임시값을 유지한다.

## BE 의 역할 범위 — 지금과 제품은 다르다

```
지금 (수동)   raw → 품질검사(트랙B) → SLAM·v10(트랙A) → 학습(트랙B) → ckpt
              BE 가 데이터 경로에 없다
제품 (자동)   앱 → BE 수신·검증 → 학습 잡 발주 → ckpt 보관 → Jetson 배포
              BE 가 전 구간
```

"BE 는 ckpt 만 관리하면 된다" 는 **이번 회차에 한해 맞다.** 제품 경로에서는 아니다 —
BE 가 보관소로만 남으면 매 수집마다 수동 정제가 필요하고 4번을 막을 지점이 사라진다.

BE 우선순위: profileKey·algorithm 문자열 확정 → actionSpace → ckpt 보관·조회.
수집 ingest 검증은 앱 업로드가 붙은 뒤.

## 0. 왜 하나

두 가지를 한 번에 답한다.

**① 청킹이 BC 를 게이트로 올리는가.** `command` 타깃 BC 가 9.3% [7.3, 11.9] n=600
이다. 게이트 20% 에 미달이고, baseline 을 다 재고 나서 남은 처방이 청킹뿐이다.

**② 트랙 A 의 v6 전제가 성립하는가.** v6 는 8-step chunk 로 미래 pinch 궤적을
예측한다. 그 타깃은 성질상 `state[t+k]` 계열이고, 트랙 B 는 0914 에 `state[t+2]`
단일-step 을 기각했다 — **다만 제어 게인 교란이 있었다**(k틱 변위를 1틱 목표로 전송).
청킹은 그 교란을 없앤다. 따라서 **0914 의 기각은 v6 를 부정하지 않으며, 지지하지도
않는다.** 이 실험이 그 빈칸을 채운다.

⚠️ **UMI 데이터 없이 시뮬에서 답할 수 있다.** 트랙 A 회신을 기다릴 필요가 없다.

## 1. 태스크가 다르다 — 먼저 적는다

트랙 A §4 의 파지 의미와 현재 시뮬 씬이 다르다.

| | v6 (SPEC §4) | 현재 시뮬 씬 |
|---|---|---|
| 접근 | 세계 +X 수평 | 위에서 아래 |
| 대상 | 세로로 선 과자 케이스 | 2cm 20g 큐브 |
| 그리퍼 | 신형 | 구형 (이슈 166) |

**그래도 유효하다고 본다** — "청킹이 외삽 지름길을 막는가"는 태스크 독립적인
질문이기 때문이다. 하지만 **결과를 인용할 때 반드시 이 차이를 병기한다.**
v6 의 성공률을 예측하는 실험이 아니다.

## 2. 무엇을 바꾸나 — 한 번에 하나

`policy/act.py` 는 **BCNet 백본을 그대로 쓰고 출력 헤드만 k×6 으로** 바꾼다.
백본을 바꾸면 두 가지가 동시에 달라져 수치 차이를 귀속시킬 수 없다.

```
chunk=1  command                  계측기 검증
chunk=8  command                  청킹 순효과
chunk=8  state[t+1 .. t+8] 궤적   v6 대리. 게인 교란 없음
```

실행 규약: 한 관측에서 k 스텝을 예측하고 **k 스텝에 걸쳐 그대로 실행**한다
(열린 루프). 그래서 `lead-k` 와 달리 제어 게인이 안 바뀐다.

종단 패딩: 에피소드 끝에서 k 스텝이 모자라면 **마지막 값 클램프**.
샘플 수가 k 에 따라 변하면 조건 간 비교가 깨진다.

## 3. 계측기 검증 — 쓰기 전에 검증한다

```
G0  chunk=1 이 기존 BC 와 같은 체크포인트에서 롤아웃까지 일치한다
```

**실패하면 이 실험 전체가 무효다.** 청킹 구현이 다른 것을 하고 있다는 뜻이다.
평가는 결정론이므로(`offsamples 0`) 비트 동일을 기대한다.

## 4. 게이트 — 결과 보기 전 확정

대조군은 `command` BC **9.3% [7.3, 11.9] n=600** 🟢.

```
G1  chunk=8 command 의 95% 하한 > 11.9%      청킹 효과 인정
G2  chunk=8 command 의 95% 하한 >= 20%       배포 게이트 통과
G3  chunk=8 궤적타깃의 하한 > 11.9%          v6 전제 성립
    chunk=8 궤적타깃의 상한 < 4%             v6 전제 불성립 — 트랙 A 즉시 통보
    그 사이                                   판정 유보, n 을 올린다
```

조건당 **독립 학습 3회 × 롤아웃 n=100**. 구간이 겹치면 차이를 주장하지 않고
**게이트를 옮기지 말고 n 을 올린다.**

## 5. 이미지 어블레이션을 같이 돌린다

0914 에 확인한 것: 액션 정의를 고치니 정책이 이미지를 쓰기 시작했다
(정상 9.3% vs 파괴 1.7%, 비중첩).

**청킹이 그것을 되돌릴 수 있다.** 8스텝을 한 번에 내면 모델이 "관측 한 번 보고
가던 대로 8칸"으로 풀 유인이 커진다. 그래서:

```
chunk=8 command + --image-noise 96   3시드 × n=100
```

```
G4  이미지 파괴 조건의 상한 < chunk=8 command 의 하한   -> 여전히 이미지를 쓴다
    겹치면                                              -> 청킹이 지름길을 만들었다
```

⚠️ **G4 가 실패하면 G1 을 통과해도 성과로 인용하지 않는다.** 이미지를 안 쓰는
정책은 실물에서 무너진다.

## 6. 예측 — 실행 전에 적는다 🟡

| 조건 | 성공률 예측 | 근거 |
|---|---|---|
| chunk=1 command | 9.3% 재현 (±2%p) | 계측기 검증 |
| **chunk=8 command** | **12~20%** | 되먹임 오차를 끊으니 개선. 게이트는 아슬아슬하게 미달 |
| chunk=8 궤적타깃 | 5~15% | `ctrl` 보다 낮지만 0 은 아닐 것 |
| chunk=8 + 이미지파괴 | 2~6% | 여전히 이미지를 쓸 것 |

**핵심 예측: 청킹은 효과가 있지만 게이트 20% 를 단독으로는 못 넘는다.**

**틀릴 수 있는 지점:**

1. **chunk=8 궤적타깃이 chunk=8 command 와 같으면** → `ctrl` 의 값어치가 사실
   리드였고, 0914 의 lead2 기각은 전적으로 게인 교란 탓이었다. 그러면 v6 전제가
   성립하고 **D-AI-47 의 `command` 필드 근거가 약해진다**
2. **chunk=8 이 chunk=1 보다 나쁘면** → 열린 루프 8스텝 동안 물체가 시야에서
   벗어나거나 오차가 누적된다. chunk 를 줄여야 한다
3. **이미지 파괴 조건이 안 떨어지면** → 청킹이 지름길을 만들었다. 가장 나쁜 결과이고
   **v6 에도 그대로 해당한다.** 즉시 트랙 A 통보

## 8. 이 실험이 답하지 않는 것

- **v6 의 성공률.** 태스크가 다르다 (1절)
- **실물 성능.** 전부 시뮬이고 시뮬 성공률은 sim2real 갭의 하한이다
- **관측 horizon 2 의 효과.** 현재 정책은 단일 프레임이다. v6 는 2스텝을 주므로
  정책이 속도를 직접 계산할 수 있고, **그쪽이 외삽 지름길에 더 취약하다**.
  이 실험은 그 조건을 재현하지 않는다 — 별도 항목으로 남긴다
- 시간 확대(트랙 A §5)의 청크 경계 영향. 별도 계측 필요

서버 자원을 실측했다 🟢 — 잡당 CPU 151% · RSS 0.86GB · GPU 808MiB,

조건 수만큼 병렬하면 되고, 3개로 제한할 이유가 없었다.

### 늘린 조건과 이유

| # | 조건 | 타깃 | 무엇을 답하나 |
|---|---|---|---|
| 1 | `chunk8_cmd` | command | 청킹 순효과 (원안) |
| 2 | `chunk8_traj` | 계약 action | v6 대리 (원안) |
| 3 | `chunk8_cmd_noise96` | command+노이즈 | G4 이미지 어블레이션 (원안) |
| 4 | `chunk2_cmd` | command | K 스윕 하한 |
| 5 | `chunk4_cmd` | command | K 스윕 |
| 6 | `chunk16_cmd` | command | K 스윕 상한 |
| 7 | **`chunk8_traj_noise96`** | 계약 action+노이즈 | **v6 대리가 이미지를 쓰는가** |
| 8 | `chunk16_traj` | 계약 action | 궤적 타깃의 K 의존성 |

**7번이 새로 추가한 것 중 가장 중요하다.** v6 타깃이 외삽으로 풀리면 이미지를 안
쓰게 되고, 그건 실물에서만 드러난다. 2번이 되더라도 7번이 안 무너지면 **그 성공은
관측을 안 쓴 성공**이다. 트랙 A 에 즉시 알려야 하는 결과다.

### 예측 🟡 — 실행 전에 적는다

| 조건 | 성공률 예측 |
|---|---|
| `chunk2_cmd` | 10~16% |
| `chunk4_cmd` | 11~18% |
| `chunk8_cmd` | 12~20% (원안과 동일) |
| `chunk16_cmd` | 8~16% — 열린 루프가 길어 오차가 누적된다 |
| `chunk8_traj` | 5~15% (원안과 동일) |
| `chunk16_traj` | 3~12% |
| `chunk8_cmd_noise96` | 2~6% (원안과 동일) |
| **`chunk8_traj_noise96`** | **5~15% — `chunk8_traj` 와 겹칠 것으로 본다** |

**핵심 예측 둘:**

1. **K 에 최적점이 있다.** 너무 짧으면 되먹임 오차, 너무 길면 열린 루프 오차.
   K=4~8 에서 최대일 것으로 본다
2. **`chunk8_traj` 는 이미지 어블레이션에 안 무너진다** — 궤적 타깃은 외삽으로
   풀리므로 관측이 없어도 된다. 이게 맞으면 **v6 전제에 문제가 있다**

### 게이트 (추가분)

```
G5  chunk8_traj_noise96 의 구간이 chunk8_traj 와 겹친다
    -> v6 대리 타깃은 이미지를 쓰지 않는다. **트랙 A 즉시 통보**
    겹치지 않으면 -> 궤적 타깃도 관측을 쓴다. v6 전제 성립 쪽 근거

G6  K 별 성공률이 단조가 아니라 최대점을 가진다  -> 최적 K 를 그 값으로 확정
    단조 증가면 -> 스윕 밖(K>16)을 더 본다
    전부 겹치면 -> K 는 중요하지 않다. 청킹 자체가 처방이 아니다
```

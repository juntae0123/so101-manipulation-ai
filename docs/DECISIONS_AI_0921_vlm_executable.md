## D-AI-88 · VLM 은 스킬을 고르지 않는다. **할 수 있는지를 판정한다**

**작성자** 김준태(트랙 B) · **상태** 제안 → 트랙 A·PM·FE·BE 합의 필요

### 왜 바꾸나 — 지금 구조에 모순이 있다

제품 정의는 **"5개 행동을 클릭으로 선택"** 이고, D-AI-63 에 **FE 가 `skill_id` 를
보낸다**고 박혀 있다. 그러면 VLM 의 스킬 선택은 **잉여다.** 클릭이 이미 답을 준다.

그런데 지금 `vlm/skill_choice.py` 가 하는 일이 정확히 그 스킬 선택이고,
0912·0914 측정도 전부 그것이었다. **제품에 자리가 없는 기능을 재고 있었다.**

그리고 구조적 막힘이 하나 더 있다 🟢 — `forced_choice_scores` 는 후보가 `SKILLS`
5개뿐이라 **"거부"라는 출력이 존재하지 않는다.** 빈 장면 거부를 물으면 답은
재볼 것도 없이 0% 다. **"재봤더니 0"과 "낼 수 없어서 0"은 다른 상태다.**

### 무엇으로 바꾸나

```
지금   이미지 + 지시문   ->  skill_id 5개 중 하나           (클릭이 이미 준다)
이후   이미지 + skill_id ->  {executable, confidence, margin}
```

클릭을 눌렀을 때 **지금 그 장면에 그 작업을 할 대상이 있는가**를 판정한다.
없으면 팔이 움직이기 전에 멈춘다.

근거 셋:

1. **클릭 경로에서도 필요하다.** 클릭했는데 책상이 비어 있으면 팔이 허공을 집는다.
   데모에서 가장 나쁜 그림이다
2. **2지선다라 거부가 출력 공간 안에 실제로 있다.** 5지선다의 구조적 막힘이 풀린다.
   대신 chance 가 0.20 → **0.50** 이 되므로 게이트를 그만큼 높게 잡는다
3. **제품 서사에 붙는다.** "로봇이 못 하는 걸 시키면, 하기 전에 말한다."
   티칭 펜던트는 시키면 그냥 한다. 경쟁자와 갈리는 지점이다

### 유지하는 것

- **채점 규칙을 그대로 베낀다** — 답 토큰만의 평균 로그확률 argmax.
  바꾸면 0912·0914 수치와 비교가 끊긴다. 자체검증에서 같음을 확인한다
- `SKILLS` · `SKILL_KO` 는 **`skill_choice.py` 소스를 파싱해서 한 벌로 쓴다.**
  값을 복사해 두면 두 벌이 되어 말없이 갈린다
- `skill_choice.py` 는 **안 건드린다.** 기존 측정의 근거다

### 사전 등록 게이트 (사진 보기 전에 확정)

| 항목 | 기준 | 왜 |
|---|---|---|
| 묶음별 장수 | >= 10 | n 이 작으면 판정 못 한다. 게이트 말고 장수를 올린다 |
| **빈 장면 거부율** | >= 0.90 | 빈 장면은 거의 항상 거부해야 한다 |
| **오거부율** (있는데 불가) | <= 0.10 | **이쪽이 더 나쁘다.** 할 수 있는데 안 하면 제품이 안 된다 |
| 전체 정확도 | >= 0.85 | chance 0.50 |

**거부율만 걸면 "전부 불가"가 만점으로 통과한다.** 오거부율이 그걸 막는다 —
자체검증 3b 가 그 조합을 박아둔 판별행이다.

`other_`(비슷한 다른 물체)의 정답은 **가능**으로 둔다 (물체가 있으므로).
물체 종류를 구분하는지는 **게이트가 아니라 참고 지표**로 뺀다 — 정답을 모르는 것을
정답처럼 쓰지 않는다.

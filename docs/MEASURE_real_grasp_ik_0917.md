## 0. 결론

**앵커를 바꾸면 같은 데이터에서 29.2% 와 99.6% 가 나온다. 둘 다 맞고, 묻는 질문이 다르다.**

```
앵커 start · 구간 full    19/65 에피소드 = 29.2% [19.6, 41.2]
                          → "사람 손 궤적 전체를 그대로 따라가는가"
앵커 start · 구간 grasp   waypoint 192/404 = 47.5%
                          → 앵커가 틀린 중간 산물. 의미 없음
앵커 grasp · 구간 grasp   waypoint 533/535 = 99.6% · chunk 30/30 = 100%
                          → "캔이 있는 자리에서 사람이 잡은 그 자세를 낼 수 있는가"
                          거부 rotation 2건이 전부
```

**제품 기조가 결과 모방이므로 세 번째가 본 질문이다.**
사람이 요란하게 움직여도 로봇은 물체만 같게 집으면 된다. 접근 경로는 로봇이 계획한다.

→ **5자유도는 결과 모방의 병목이 아니다.** 535개 웨이포인트 중 자유도 때문에
   막힌 것은 2개다.

## 1. ⚠️ 철회 — "UMI 폐기율 71%"

2026-09-17 오전에 어시스턴트가 `29.2%` 를 **폐기율**로 해석하고
HW·PM 에 6축 전환 검토를 요청하는 보고서를 작성했다. **보내지 않았고 철회한다.**

틀린 지점은 계산이 아니라 **질문**이다. 시연 전체 궤적의 재현 가능성을 쟀는데,
이 제품은 궤적을 재현하지 않는다. 접근 중 사람이 손을 휘저은 구간까지 실패로 세면
폐기율이 통째로 부풀려진다.

사용자 지적으로 정정됐다. 규칙으로 박았다 —
**계측기를 만들기 전에 "이 태스크의 성공은 무엇인가"를 먼저 확정한다.**

## 2. 앵커 정의

```
start  T_base[t] = T_base_home  @ chain[t]
       시연의 첫 pinch pose 를 시뮬 홈 EEF pose 에 겹친다 (트랙 A 최초 명세)

grasp  T_base[t] = T_grasp_sim  @ inv(chain[closure]) @ chain[t]
       시연의 파지 순간 pose 를 시뮬의 측면 파지 pose 에 겹친다
       T_grasp_sim 은 run_side_expert 와 같은 식으로 계산 (물체 위치 기준)
```

**start 앵커에서 position 거부가 172/212(81%)였던 이유**: 파지 지점이
사람의 이동량에 따라 아무 데나 떨어져 시뮬 캔이 있는 자리와 무관해진다.
앵커를 옮기니 position 거부가 0이 됐다.

## 3. 닫힘 검출과 그 검증 🟢

물체가 어디 있었는지는 **그리퍼가 닫혀 멈춘 순간**이 말해준다 (사용자 지적).

검출: `gap` 이 최소값 + 2mm 이하로 **처음 내려간** 행.
`argmin` 을 그대로 쓰면 잡고 든 뒤에도 폭이 유지되므로 최소점이 리프트 중간에 찍힌다.

**검증 — 닫힘 순간 gap 은 곧 물체 폭이다. 70편이 같은 물체를 잡았으니 모여야 한다.**
```
중앙 38.5 mm · 범위 32.4 ~ 43.5 mm (n=69)
```
트랙 A 의 케이스 폭 **39mm 잠정**과 일치한다. 범위 11.1mm 로 경고 임계(15mm) 아래.
**검출이 맞다.** 이 검증이 없으면 99.6% 도 못 믿는다.

⚠️ 부수 발견 — 이 값이 프로젝트 지침의 *"그리퍼 닫힘 간격 약 1.7cm →
대상물 1.5~2.5cm"* 범위 **밖**이다. 9/13 그리퍼 변경 이후 값이 바뀐 것인지
지침이 낡은 것인지 **모른다. HW 확인 필요.**

## 4. 남은 실패는 전부 속도다

```
에피소드 전체 통과   0/69      ← 전부 속도 위반으로 걸림
시간확대율           최대 48.0
```

⚠️ **이 48배는 로봇 한계 대비가 아니다.** 예산의 분모가 시뮬 scripted expert 인데,
그 전문가는 1.2~1.5초 스테이지를 부드럽게 도는 **의도적으로 느린** 궤적이다.
"사람 손이 우리 스크립트보다 48배 빠르다"는 뜻이다.

**SO-101 실제 관절 속도·가속도 한계는 미측정이다** (LIMITS).
그리고 결과 모방이라면 로봇이 자기 속도로 가면 되므로 **게이트가 아니다.**
이 판단은 결과를 보기 전에 선언했다.

## 5. 이 측정의 한계

1. **부분적으로 순환이다.** 앵커를 시뮬 파지 pose 에 박으면 그 지점은 정의상
   도달 가능하다. 실제로 잰 것은 **파지 전후 ±0.8초의 국소 움직임이 도달권에
   머무는가** 이지 "이 시연을 로봇이 해낼 수 있는가" 가 아니다
2. **물체 배치 시드 1개**(`--anchor-seed 0`)만 썼다. 작업영역 안 다른 위치는 미측정
3. **접근 경로가 미측정이다.** 궤적을 따라가지 않는다면 파지 자세까지 가는 길은
   MoveIt 이 풀어야 한다. [ROS] 범위이고 **아직 아무도 안 쟀다**
4. **시뮬 캔(⌀67.8mm)으로 실 케이스(38.5mm) 시연을 평가했다.** 턱 간격이 다르다.
   위치·자세 도달성만 보므로 판정에는 영향 없지만 기록해 둔다
5. 짧은 편 1편 제외 (`rec_20260911_145625`, 파지 구간 2행)

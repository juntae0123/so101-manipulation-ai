## 1. 왜 했나

기존 E2 의 유일한 약점이 n 이었다. 홀드아웃 13편.
게이트는 통과했지만 **분할 하나에 의존한 결과**였다.

프로젝트 규칙: *"n 이 작으면 게이트를 판정할 수 없다. **게이트를 옮기지 말고 n 을 올려라.**"*

## 2. 설계

```
분할 시드   42 / 43 / 44 / 45 / 46  (각각 train/holdout 재변환)
A 조건      실 시연만 · 학습 시드 0 고정
B 조건      기존 e2_C 체크포인트 하나에서 warm start · 학습 시드 0 고정
C 조건      재학습 없음 — 시뮬 전용이라 분할과 무관
평가        eval_holdout_error.py · fold 별 B-A paired (에피소드 단위)
```

**학습 시드를 늘리는 대신 분할을 늘렸다.** 시드 간 변동이 이미 작다고 측정됐기 때문이다
(병진 범위 1.52mm = 3.9%, `MEASURE_e2_final_0918.md`). **게이트 변경이 아니라 설계 선택**이며
실행 전에 명시했다.

**B 의 출발 체크포인트를 하나로 고정**해 C 시드를 변수에서 제거했다.

### 정답을 아는 행 — 시드 42 재현 검정

`--task` 가 provenance 에 기록돼 있지 않아 `configs/can_side.yaml` 로 **가정**해야 했다.

```

```

**재현이 깨졌으면 한 fold 도 학습하지 않고 중단하도록 스크립트에 넣었다.**
`AI/tools/run_e2_folds.sh`

⚠️ **계측기 결함 기록**: `convert_v10_to_umi.py` 의 provenance 에 `task` 가 없다.
*"조건을 바꿨으면 conditions 에 적는다"* 가 빠진 자리다. 다음 수정 때 추가한다.

## 5. 한계 — 먼저 말한다

- **오프라인 예측 오차다. 롤아웃이 아니다.** val_loss 가 내려가도 롤아웃 0% 였던 전례가 있다
- **분할 5개는 진짜 k-fold 가 아니라 서로 다른 시드의 반복 무작위 분할**이다.
  에피소드가 fold 간 겹칠 수 있다. 각 fold 의 paired 비교는 독립적으로 유효하지만
  5개를 합쳐 하나의 n=69 검정으로 다루지는 않는다
- **학습 시드 1개**다. 시드 간 변동은 선행 측정(3시드, 범위 3.9%)에 의존한다
- **절대 mm 는 SLAM 스케일 k 를 안고 있다.** v10 이 단안 ORB-SLAM3 산출물이고
  스케일 근거인 마커가 `marker_black_square_size_verified: false` 다.
  **개선율과 B-A 부호·유의성은 스케일 불변이라 안전하지만, "-11mm" 라는 절대값은
  k 가 확정돼야 유효하다** (`check_marker_scale.py` 대기)
- 물체 한 종(구운감자 케이스)이다
- **2026-09-18 실물 복구**로 D-AI-52 의 되돌릴 조건이 발동했다. 이 수치는
  롤아웃 재측정이 나오면 대체된다

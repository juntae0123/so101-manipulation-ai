## 결함 11 — 거부 404/404 이 전부 `joint_limit`

### 증상
파지 구간 IK 수용률을 재는데 **404개 웨이포인트 전부가 같은 사유로 거부**됐다.

```
waypoint  0/404 = 0.0%
거부 사유: {'joint_limit': 404}
```

### 왜 바로 의심했나
0% 자체는 결과일 수 있다. 하지만 **거부 사유가 한 가지로 100% 쏠린 것**은 다르다.
실제 실패라면 위치·자세·관절범위가 섞여 나와야 한다.
직전 실행(`--segment full`)에서는 `position 272 / rotation 208` 로 갈렸는데,
구간만 좁혔다고 전부 `joint_limit` 이 되는 물리적 이유가 없다.

**→ 결과가 아니라 코드를 의심한다.**

### 좁힌 과정
`joint_limit` 판정을 내는 곳은 한 줄뿐이다.

```python
if np.any(q < lo - 1e-6) or np.any(q > hi + 1e-6):
```

`lo`, `hi` 가 무엇인지 거슬러 올라갔다.

```python
lo, hi = env.limits[:, 0], env.limits[:, 1]      # 관절 하한·상한 (배열, rad)
...
lo, hi = span if span else (0, chain.shape[0]-1)  # ← 구간 인덱스(정수)로 덮어씀
```

**구간 기능을 넣으면서 `lo, hi` 를 재사용했다.** 관절각(rad)을 행 번호와 비교하니
`q < 5 - 1e-6` 이 거의 항상 참이고, 모든 웨이포인트가 관절범위 위반으로 찍혔다.

⚠️ `--segment full` 경로에도 같은 버그가 들어가 있었다. 그때 나온 29.2% 는
이 코드가 아닌 **이전 버전** 결과라 유효하지만, 두 버전에 걸친 근거가 됐다.

### 고친 방법
관절 한계는 `qlo/qhi`, 구간 인덱스는 `i0/i1` 로 분리. 재사용 0건을 코드에서 확인.

### 자동화 — 사람이 잡은 것을 도구가 잡게 했다
거부가 한 사유로 100% 쏠리면 경보를 찍는다.
```
!! 거부 404/404 이 전부 'joint_limit' 이다.
   결과가 아니라 계측기 버그를 먼저 의심해라
```

## 결함 12 — `UnboundLocalError: gaps`

### 증상
70편을 다 돌고 **요약 JSON 을 쓰는 마지막 단계에서** 죽었다.

```
"closure_gap_mm": {"median": (sorted(gaps)[len(gaps)//2] if gaps else None),
UnboundLocalError: cannot access local variable 'gaps'
```

### 원인
물체 폭 집계를 **출력부**에 넣었는데, 그 값을 쓰는 요약 딕셔너리가 **그보다 앞**에 있었다.
정의보다 사용이 먼저다.

### 왜 안 걸렸나
`ast.parse()` 문법 검사는 통과한다. `--selftest` 도 통과한다 —
자체검증은 순수 수학(rot6d·연쇄 복원)만 돌고 `main()` 의 집계 경로를 안 탄다.

**계측기의 자체검증이 계측기 전체를 덮지 않는다.**

### 고친 방법
정의를 요약 딕셔너리 앞으로 이동. 정의 1회·정의<사용 순서를 코드로 확인 후 전달.

**두 건 모두 어시스턴트 환경에서 실행할 수 없는 코드를 문법 검사만 하고 넘긴 것이다.**

같은 날 패치 도구의 비멱등성(`--seed` 두 번 등록)도 같은 이유였다.

### 규칙

> 여러 곳을 동시에 고쳐야 하면 나눠서 낸다.

> **거부·실패 사유가 한 가지로 100% 쏠리면 결과가 아니라 버그를 먼저 의심한다.**

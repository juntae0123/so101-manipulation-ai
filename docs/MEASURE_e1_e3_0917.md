T1/T2 차이는 `workspace_y` 뿐이다 — T1 [-0.035, 0.035] / T2 [0.06, 0.10].
`approach = obj[:2] − [0.04, 0]` 정규화 때문에 물체가 좌측으로 가면 접근 방향이
회전하고 shoulder_pan 궤적이 달라진다.

⚠️ **발표에서 넘지 말 것** — 이것은 **"다른 조작 태스크 2종"이 아니라
"같은 태스크의 다른 위치 2개"** 다. 교차가 떨어진 것은 "정책이 작업영역을
구분했다"는 증거이지 "다른 스킬을 배웠다"는 증거가 아니다.
정확한 표현: **"2개 타겟을 각각 학습·저장하고 선택 실행"**

## 3. (철회된 해석) 전체 궤적 기준 IK 수용률

simulation-only episode-start alignment 기준, 실 UMI 70편의 연속 IK 수용률.

```
전체 70편 · 청크 불가(행 < 9) 5편 · 복원 검증 불가 1편
판정 분모 = 65편

■ 에피소드 전체 IK 기하 수용률   19/65 = 29.2%   Wilson95 [19.6, 41.2]
   waypoint                   811/1291 = 62.8%
   8-step chunk                306/771 = 39.7%

거부 사유   position 잔차 > 8mm : 272
            rotation 잔차 > 5°  : 208
시간확대율(시뮬 전문가 시연 대비) 중앙 15.2 · 최소 1.8 · 최대 43.5
```

**게이트 70% 불통과.** 사전 선언대로 앵커를 바꿔 재시도하지 않았다.

### 3-1. 이 수치의 프로젝트 의미 — 5자유도 폐기율

프로젝트 문서에 계속 열려 있던 리스크:

> *기획서는 "범용 6축", 실측 하드웨어는 5자유도.
> **UMI 궤적 재현 불가 폐기율 계산이 이 값에 통째로 의존한다.***

**그 폐기율이 처음으로 숫자가 됐다.**

```
에피소드 완전 재현 가능    29.2% [19.6, 41.2]   → 폐기율 약 71%
웨이포인트 단위            62.8%
```

rotation 거부 208건이 근거다. 사람 손 궤적은 6자유도이고 SO-101 은 5축이라
**위치를 맞추면 자세가 따라오지 못한다.** 구조적 제약이지 캘리브레이션 오차가 아니다.

→ **HW·PM 확인 필요.** 6축이면 이 숫자가 달라진다.

### 3-2. 게이트에 있던 결함 (기록)

게이트를 세울 때 근거가 *"수용률이 낮으면 학습해도 E2 가 죽는다"* 였는데,
그것은 **시뮬 롤아웃으로 평가하던 시절의 E2** 에 대한 말이다.
지표를 홀드아웃 예측 오차로 바꾼 뒤에는 IK 수용률이 지표 계산의 전제가 아니다.
**지표를 바꾸면서 게이트 문구를 안 고쳤다.** 트랙 A 에 알렸고 답 대기 중.

### 3-3. 시간확대율은 게이트가 아니다

예산을 **시뮬 전문가 시연의 실측 최대 관절속도**로 잡았다. 그 전문가는 1.2~1.5초
스테이지를 부드럽게 도는 의도적으로 느린 궤적이다. 즉 "사람 손이 우리 스크립트보다
15배 빠르다"는 뜻이지 서보 한계를 넘는다는 뜻이 아니다.
⚠️ **SO-101 실제 관절 속도 한계는 미측정이다.** LIMITS 행.

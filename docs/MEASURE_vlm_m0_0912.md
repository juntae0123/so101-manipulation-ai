## 읽는 법 — 두 가지가 판정을 뒤집는다

### ① SmolVLM-500M 의 0.20 은 "우연 수준 능력"이 아니라 **상수 예측기**다

```
혼동행렬 (행=정답, 열=예측)
           pick_pla sort_two align_fi present_  line_up
 pick_pla       20        0        0        0        0
 sort_two       20        0        0        0        0
 align_fi       20        0        0        0        0
 present_       20        0        0        0        0
  line_up       20        0        0        0        0
```

**100건 전부를 `pick_place` 로 찍었다.** 항목이 20/20/20/20/20 균형이므로 정확도가 정확히
0.20 으로 나온 것이지, 우연히 맞힌 것이 아니다. 사전등록 **보조 판정 4**(예측의 60% 이상이
한 값으로 쏠리면 사전확률로 찍는 것이다)가 발동했다 — **이 모델의 정확도 수치는 무의미하다.**

**함의: Jetson 8GB(이슈 42) 안에 들어가는 경량 후보가 사라졌다.**
Qwen2.5-VL-3B 는 fp16 만 약 6GB 라 정책과 합쳐 8GB 에 들어간다는 근거가 없다.
0901 fp16 안전성 측정에서 두 모델 모두 통과했지만, **통과는 수치 안정성이지 능력이 아니다.**

### ② Qwen 의 0.75 는 비전 성능이 아니다 — `blank` 와 **정확히 같다**

`render − blank = +0.00`. 사전등록 **보조 판정 1**(차이 0.10 미만이면 이미지 기여 미확인)
발동. 0 으로 채운 이미지를 줘도 같은 점수가 나온다.

이건 예측한 것이다 🟡 → 실측 적중:

> "`blank` 와의 차이가 0.05 미만일 것이다. 근거: 스킬 5종은 **놓기 단계로만 구분되고**(D-AI-22),
> 그 차이는 사진에 안 나온다. 사진으로 `sort_two` 와 `line_up` 을 구분할 방법이 없다."

**즉 M0 가 잰 것은 '한국어 지시문 → enum 분류' 정확도다.** 그리고 그것이 옳다 —
스킬은 사용자의 말이 정하는 것이지 사진이 정하는 것이 아니다. 잘못된 것은 이 측정이 아니라
"스킬 선택을 VLM 과제로 본 것"이다.

### 어디서 틀리나 — `sort_two` 가 무너진다

| 스킬 | 정확도 | |
|---|---:|---|
| pick_place | 1.00 | |
| line_up | 0.95 | |
| align_fixture | 0.75 | |
| present_inspect | 0.70 | |
| **sort_two** | **0.35** | 20건 중 **12건을 `pick_place` 로** 오분류 |

오분류가 **전부 `pick_place` 방향**이다. `pick_place` 가 다른 넷의 상위 개념처럼 읽히는
것이 원인으로 보인다 🟡 — enum 설명이 "집어 옮기기"라 "두 곳으로 분류"도 집어 옮기는 일이다.
**프롬프트·enum 설명 문제일 가능성이 크고, 파인튜닝으로 갈 문제가 아니다.**

## 판정

D-AI-17 게이트만 보면 Qwen 0.75 는 "LoRA 필요 구간"이다. 그러나 **보조 판정 1이 그 위에 있다.**

> 이미지 기여가 확인되지 않으면 M0 수치를 "VLM 이 현장을 이해한다"로 읽지 않는다.
> 스킬 선택은 사실상 텍스트 분류이고, **비전이 필요한 부분은 grounding(bbox) 이므로
> 다음 계측을 그쪽으로 옮긴다.** (사전등록 원문)

**따라서 스킬 선택용 LoRA 는 착수하지 않는다.** 비전을 안 쓰는 문제에 비전 모델을
파인튜닝하는 것이 되기 때문이다. 순서는 이렇게 간다:

1. **프롬프트·enum 설명 수정으로 `sort_two` 가 얼마나 오르는지 먼저 잰다** (비용 0)
2. 그래도 부족하면 **텍스트 분류기**로 충분한지 본다 — VLM 이 아니어도 되는 문제일 수 있다
3. VLM 파인튜닝은 **grounding(bbox) 정확도**를 잰 뒤에 그 결과로 판단한다

## 해석 제한

- **지시문 100개를 어시스턴트가 썼다.** 문제를 내는 쪽과 푸는 쪽이 같은 과정이다.
  실사용자 발화보다 쉬울 가능성이 크다. 사람(PM·사용자)이 다시 쓰면 그 판이 정본이고 재측정한다
- n=100 에서 95% 구간 반폭 약 ±9%p. 0.75 는 0.90 게이트와 충분히 떨어져 있어 구간이 판정을 바꾸지 않는다
- **`real` 조건을 못 돌렸다.** 실물 프레임 100장(`vlm_m0_frames.tgz`)이 서버에 없다.
  이미지 기여가 0 이므로 `real` 을 넣어도 결론이 바뀔 가능성은 낮지만, L22(렌더→실사 전이)는 미측정으로 남는다
- 자유생성(JSON 형식 준수율)은 출력 상단이 잘려 확인하지 못했다. `out/vlm_m0_20260912_153353.json` 에 있다
- VLM 은 보조 도구다. 이 결과는 MVP(W6)를 막지 않는다

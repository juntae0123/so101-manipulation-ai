## 1. `solve_grasp_anchor.py` — 정렬 좌표를 기다리는 대신 반대로 푼다 🟢

`robot_base_alignment_applied: false` 라서 시연 좌표가 작업영역 밖에 떨어진다
(한 편에서 작업영역 안 3/80). 그 숫자를 "5자유도가 모자라다"로 읽으면 틀린다.
**놓는 자리를 안 정했을 뿐이다.**

그래서 질문을 뒤집었다 — *파지 순간이 도달권에 들려면 물체를 어디에 놓아야 하나.*

```
T_align(p, yaw) = Trans(p) @ Rz(yaw) @ Trans(-g)      g = 파지 순간 위치
```
이러면 파지점이 정확히 p 로 간다. 그 다음은 **검증된 계측기를 그대로 쓴다** —
`check_real_traj_ik.check_episode(..., span=파지구간)`. 새 IK 를 안 짰다.

- 판정 대상은 **파지 순간 −2 ~ +6 행**이다. 전체 궤적이 아니다
- 2단 탐색: 1단은 닫힘 pose 하나만(싸다), 2단은 상위 후보에만 구간 전체
- 자체검증 8/8. 판별 행 둘 — 곱 순서를 뒤집으면 p 에 안 가야 하고,
  yaw 가 자세를 실제로 바꿔야 한다
- ⚠️ 산출물은 **제안값**이다. 실물 베이스 캘리브레이션이 아니다.
  출력 JSON 첫 줄에 그렇게 박아놨다

**미실행.** 서버에서 돌려야 한다 (MuJoCo + v10 데이터).

## 2. `sweep_camera_mount.py` — 도면값 대신 사양을 되돌려준다 🟢

각도 0/±2/±5/±10도 · 높이 0/±5/±10/±20mm · 판별 조건 45도 = **14조건**,
조건당 20편 = 280 롤아웃. GPU 1·2·3·4·6 병렬로 약 23분.

**인자 대조 🟢** — `evaluate.py` 에 `--camera` 는 **없다**(소스 확인).
그래서 교란은 task yaml 의 `camera_path:` 로 넣는다
(`simulation/env.py:14` 가 그 키를 읽는다).

계측기가 스스로를 못 믿는 지점 둘:
```
정답 아는 행   a0(0도 0mm) 카메라 yaml 이 원본과 비트 단위로 같아야 한다 → 통과
판별력 행      45도 조건이 기준선보다 안 떨어지면 camera_path 가 안 읽히는 것이다
               → 그 경우 허용치를 내지 않고 죽는다
```
합성 데이터로 두 경로 다 확인했다 — DISC 95%(기준선과 동일)면 중단,
DISC 10%면 표와 사양을 낸다. 🟢

생성물은 `configs/_sweep_camera/` 와 `outputs/sweep_camera/` 안에만 들어간다.

**미실행.** 서버 GPU 필요.

## 3. `probe_empty_scene_refusal.py` + 사전등록 🟢

시연에서 가장 터지기 쉬운 지점 — 책상에 물체가 없는데 클릭하면 정책은 그냥
빈 곳으로 손을 뻗는다. 막는 장치가 파이프라인에 0건이다.

**baseline 먼저.** VLM 을 붙이기 전에 *정책 자신이 신호를 주는가* 를 본다.
공짜다 — 이미 배포한 체크포인트 출력만 본다.

```
지표     한 관측당 예측 8스텝 중 gap 최소값 [mm]
게이트   without − with >= 20mm  → A 통과 (정책이 스스로 신호를 준다)
         5 ~ 20mm               → 애매. n 을 올린다. 게이트를 낮추지 않는다
         < 5mm                  → A 미달. VLM ③ 로 간다
예측 🟡  A 미달 쪽. 차이 0~5mm
참조집단 0912 렌더 측정(이미지 기여 음수) · 0914 M1(Qwen −6%p, BC 는 노이즈가 도움)
         ⚠️ 둘 다 구 경로다. 같은 종류의 외삽으로 9/17 에 크게 틀린 적 있다
```

선행 검정 둘 — **빈 장면 검정**(짝 프레임 화소차 8/255 미만이면 "빈 장면"이 사실
같은 그림이므로 중단)과 **정답 아는 행**(물체 있는데 안 닫으면 배선이 틀린 것).

자체검증 11/11. 초판에서 [2] 가 37.19 로 떨어졌는데 **코드가 아니라 내 기대값이
틀렸다** — 255 에서 잘리는 걸 계산에 안 넣었다. 계측기가 내 기대값을 잡아냈다.

프레임은 폰으로 책상을 두 번 찍으면 된다. 시뮬 불필요.

## 4. `run_policy_realtime.py` — http 스냅샷 카메라 소스 🟢

폰을 IP 웹캠으로 띄우면 정책에 실시간 프레임을 먹일 수 있다.

**MJPEG 스트림이 아니라 스냅샷 GET 으로 했다.** 스트림을 열어두면 디코더 버퍼에
프레임이 쌓이는데, 우리는 0.4초에 한 번만 읽으므로 나오는 게 몇 초 전 장면일 수
있다. 그런데 **낡은 프레임과 새 프레임은 똑같이 생긴 배열이다** — 검사가 안 되는
모양이다. 스냅샷은 이 실패가 원천적으로 없다.

`/video` 같은 스트림 경로를 주면 거부한다. 그래도 스트림이 얼 수 있으니
직전 응답과 바이트가 같으면 세어서 모수와 함께 보고한다.

자체검증 13/13 (거부 7/7 + 정상 URL 통과 판별 행).

# MEASURE — 파지 순간 도달 가능성, atlas_v1 70편 (2026-09-21)

작성 김준태 (트랙 B) · 계측기 `AI/tools/reach_at_grasp.py` (자체검증 7/7, lint 0건)
산출물 `out/atlas_v1/reach.json`

## 왜 만들었나

`audit_umi_zarr` 게이트에서 atlas_v1 이 **EEF 축별 최대 폭 0.466 m** 로 불합격했다
(기준 0.3m = SO-101 도달 반경). 게이트를 낮출 것인지가 아니라 **실제로 몇 %가 못
닿는지**가 질문이다. 계측 없이 결정하지 않는다.

**그리고 무엇을 재느냐가 답을 바꾼다.** 이 프로젝트 기조는 결과 모방이지 궤적
모방이 아니다. 로봇은 접근 경로를 스스로 짠다. **파지 순간을 재야 한다.**

## 이 계측기가 증명하는 것과 못 하는 것

- 증명한다 — 반경·높이 밖의 점은 **어떤 자세로도 불가**다 (위치만으로 충분조건)
- 못 한다 — 반경 안이라고 닿는다는 뜻이 아니다. **자세·관절한계·자기충돌 미검사**
- 즉 **"불가"는 확정, "가능"은 미확정**이다. 통과로 쓰지 않는다

베이스 위치는 격자 41² 로 탐색한다 (`robot_base_alignment_applied: false` 라
월드 좌표만 있고 베이스 위치는 우리가 고르는 값이다).

## 결과 🟢

조건: r 0.10~0.30 m · z 0.00~0.35 m · 파지 창 ±0.5s (31프레임) · 격자 41²

```
파지 순간     편 70 / 70 (거부 0) · 점 100.0% · 최적 base [0.134, 0.045]
전체 궤적     편 44 / 70            · 점  97.6% · 최적 base [0.286, -0.051]
```

**파지 기준 70/70. 전체 궤적 기준 44/70 (62.9%).**
궤적 기준으로 판정했으면 **26편을 버릴 뻔했다.** 한 편도 버릴 필요가 없다.

2026-09-17 의 "전체 궤적 29.2% 를 폐기율로 쓸 뻔한" 사건과 같은 모양이고,
이번엔 계측기가 그 차이를 스스로 찍는다 —
*"전체 궤적 기준이 더 낮다 — 그 차이를 폐기율로 쓰면 틀린다"*.

## 도달 반경 민감도 — 결론이 얼마나 튼튼한가

| r_max | 파지 순간 | 전체 궤적 |
|---|---|---|
| 0.35 | 70 / 70 | 69 / 70 |
| **0.30** | **70 / 70** | 44 / 70 |
| 0.25 | 70 / 70 | **0 / 70** |
| 0.22 | 70 / 70 | 0 / 70 |
| 0.20 | 69 / 70 | 0 / 70 |

**파지 기준은 0.20 m 까지 내려도 69/70 이다.** 도달 반경 값이 0.3 이든 0.25 든
결론이 안 바뀐다. 전체 궤적 기준은 0.30↔0.25 사이에서 44 -> 0 으로 무너진다 —
**그 지표는 반경 가정에 극도로 민감하다. 판정 근거로 쓰면 안 된다.**

## 그래서 게이트는

`EEF 축별 최대 폭 <= 0.3 m` 는 **전체 궤적 폭**을 본다. 위 표대로 그 양은
반경 가정에 따라 0~69편을 오간다. **파지 순간을 재는 이 계측기로 대체한다.**
게이트를 낮추는 게 아니라 **재는 대상을 바꾸는 것**이다 (D- 기록 필요).

회전 폭 0.749 rad 불합격은 **아직 안 풀렸다.** 위치만 쟀고 자세는 안 쟀다.
5자유도에서 파지 순간의 자세가 만족 가능한지는 별도 계측이다 — 평행 그리퍼 측면
파지는 접근축 둘레 회전이 자유라 5축으로도 될 수 있다. **미검증.**

## 한계 — 먼저 말한다

- 위치만이다. **자세·관절한계·자기충돌 미검사.** "가능"은 미확정
- 베이스 높이 0 고정. 실제 장착 높이가 다르면 z 범위가 통째로 움직인다
- r 0.10~0.30 · z 0.00~0.35 는 지침의 "도달 반경 대략 0.3m" 과 측면 파지 포락선
  실측에서 잡은 값이다. **MuJoCo 로 직접 IK 를 풀어 대조하진 않았다**
- 파지 창 ±0.5s 는 내가 고른 값이다. 창을 넓히면 결과가 달라질 수 있다

### ① 외삽 설명력 (팔 5축, 계약 단위 [-1,1])

`action[t] = state[t+1]` 이므로 "가던 방향으로 계속" 이 얼마나 맞는지를 잰다.

| 데이터 | 30Hz | 15Hz | 10Hz |

### ② 오픈루프 1초 지평 (관측 안 봄) — 오차 / 에피소드 내 변화폭

**실데이터가 시뮬보다 5배 예측하기 쉽다.** 시뮬은 2초에서 105% 로 폭발하는데

경로 고장도 아니고 장면이 매번 같은 것도 아니다. **볼 게 있는데 안 본다.**

## 2. 확인 부탁 — 트랙 A 소관

### ① ARCore → IK 변환에 평활화·보간이 있습니까

30Hz 에서 사람 손이 이만큼 매끄러울 리 없다고 봅니다 🟡.
리샘플링·스플라인 보간·저역통과 필터 중 하나가 들어가면
**관절 궤적이 2차 다항식에 가까워지고, 그러면 외삽이 94%를 먹습니다.**

들어간다면 그 강도를 알려주시면 이쪽에서 영향을 수치로 낼 수 있습니다.

### ② 시연 시 물체 위치를 얼마나 옮기셨습니까

에피소드 간 첫프레임 차이 47.91계조가 **물체 위치 때문인지 손 자세 때문인지**
이 도구로는 못 가릅니다 (손목 카메라라 팔이 조금만 달라도 프레임 전체가 바뀜).

물체를 매번 비슷한 자리에 놓으셨다면, 그게 원인일 수 있습니다.

### ③ `wrist_roll` — meta 로 재확인

체크포인트 `target_std` 의 `wrist_roll` 성분이 **0 → 1.0 으로 강제**되어 있습니다.
즉 이 축의 델타가 데이터 전체에서 정확히 0 입니다.
이전에 짚어주신 position-only IK 원인과 일치합니다.

## 3. 수집 프로토콜에 미치는 함의

⚠️ **재수집해도 같은 성질이면 또 못 씁니다.** 편수를 늘리는 것으로는 안 풀립니다.

| 지금까지 근거 | 상태 |
|---|---|
| "67편이 부족하니 더 모으자" | **약해졌다.** 데이터를 25% 더 줘도 train loss 가 그대로였다 |
| "환경은 다양하게" 원칙 | **위반 여부 미확인.** 물체 위치 변주량을 트랙 A 가 알려주셔야 한다 |

**제안 🟡** — 재수집 프로토콜에 다음 두 줄이 들어가야 한다고 봅니다.

1. **물체 위치를 매 시연마다 명시적으로 옮긴다** (범위를 숫자로 고정)
2. **변환 단계의 평활화 강도를 기록에 남긴다** — 지금은 메타에 없어서 사후에 못 가린다

## 4. 별건 — `sim_pick_v5` 는 `v3` 와 내용이 같습니다

여섯 키(`state`·`action`·두 타임스탬프·두 이미지) **전부 해시가 동일**합니다.
파일 sha256 은 달라 보이는데, npz 가 zip 이라 엔트리 메타데이터 때문입니다.

**과거 기록에서 "v5로 측정"이라고 적힌 수치는 v3 와 같은 데이터입니다.**
두 결과를 독립 표본으로 인용하면 안 됩니다.

## 5. 이쪽 미해결 — 감추지 않고 적습니다

- **체크포인트 vs 외삽 비교가 아직 무효입니다.** 외삽 잔차의 중앙값이 정확히 0 이라
  (절반 이상 스텝에서 가속도가 0) 비율이 발산했습니다. 평균 기준으로 다시 잽니다
- 1스텝 teacher-forced 만 쟀습니다. **누적 오차는 못 쟀습니다** —
  예측한 state 에 해당하는 이미지가 없어서 진짜 오픈루프 롤아웃이 불가능합니다
- 다운샘플(30→10Hz)은 사전등록 게이트(15%p) 미달로 **기각**했습니다. 낙폭 12.1%p

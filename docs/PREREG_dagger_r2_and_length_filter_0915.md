## 0. 무엇을 묻나

라운드 1(전문가 59 + 교정 120, K=8)이 **63.7% [58.1, 68.9]** 다.
두 가지를 따로 묻는다.

```
질문 A  DAgger 를 한 번 더 돌리면 더 오르나
질문 B  청크보다 짧은 조각을 버리면 더 오르나
```

두 질문은 독립이므로 **한 캠페인에서 각각 대조군을 둔다.**

## 1. 왜 이 둘인가

### A — 라운드 1 정책과 라운드 2 정책의 상태 분포가 다르다

DAgger 의 전제는 "정책이 실제로 방문하는 상태에 전문가 라벨을 붙인다" 이다.
라운드 1 의 교정 데이터는 성공률 0%대 정책이 방문한 상태에서 나왔다.
지금 정책은 63.7% 다. **가는 곳이 다르므로 라벨이 필요한 곳도 다르다.**

### B — 조각 절반이 청크보다 짧다 🟢

`datasets/dagger_cmd` 120편 길이 분포 (2026-09-15 계측):

```
길이 구간  2:19  4:26  8:10  16:4  32:3  64+:58      중앙 62 · 평균 83.6 · 최대 170
```

**이봉이다.** K=8 미만이 최소 45편(38%).
`data/dataset.py` 의 종단 클램프는 조각이 K 보다 짧으면 마지막 상태를 반복해 채운다.
길이 2 짜리 조각은 8스텝 타깃 중 6스텝이 "같은 자리에 머물러라" 가 된다.
**정지를 가르치는 샘플이다.** 이 프로젝트에서 정지는 이미 한 번 고정점이 되어
롤아웃을 0% 로 만든 적이 있다(0914, 계약 action).

## 2. 조건 — 한 번에 하나만 바꾼다

데이터 외 전부 동일: `command` 사이드카 · K=8 · 학습 시드 0·1·2 ·
평가 시드 3000~3099 · epochs 30 · 조건당 n=300.

| 조건 | 데이터 | 묻는 것 |
|---|---|---|
| `r1_ctrl` | 전문가59 + 교정R1(120) | **대조군.** 63.7% 재현 확인 |
| `r2_add` | 전문가59 + 교정R1 + 교정R2 | A: 라운드 추가 효과 |
| `r2_only` | 전문가59 + 교정R2 | A': R1 없이 R2 만으로 되나 |
| `r1_min8` | 전문가59 + 교정R1(길이≥8만) | B: 짧은 조각 제거 효과 |
| `r1_more` | 전문가59+59(추가수집) + 교정R1 | ⚠️ **증량 대조군** |

⚠️ `r1_more` 가 왜 필요한가 — `r2_add` 는 데이터가 늘어난다. 늘어난 것이
**DAgger 라운드여서** 좋은지 **그냥 양이 늘어서** 좋은지 구분이 안 된다.
같은 양만큼 전문가 시연을 더 넣은 팔이 대조군이다. 시뮬은 재수집이 싸다(60편 45초).

라운드 2 수집: `--episodes 120 --seed-base 4200`, 체크포인트는
`mix_cmd_v2_mix_c8_seed{0,1,2}.pt` (최종. `_bestval` 아님 — val 은 지표가 아니다).
시드 4200~4319 는 R1(4000~4059)·평가(3000~3099)·학습(0~2)과 전부 분리된다.

## 3. 게이트 — 결과 보기 전 확정

```
G0  r1_ctrl 의 95% 구간이 63.7% [58.1, 68.9] 와 겹친다
    -> 겹치지 않으면 코드가 바뀐 것이다. 나머지 판정을 중단하고 원인부터 찾는다

G1  r2_add 의 95% 하한 > r1_ctrl 의 95% 상한
    -> 라운드 2 가 개선이다. 라운드 3 을 검토한다

G2  r2_add 가 G1 미달이고 r1_more 와도 구간이 겹친다
    -> DAgger 추가 라운드는 수확 체감. **라운드 2 에서 멈춘다**

G3  r1_min8 의 95% 하한 > r1_ctrl 의 95% 상한
    -> 짧은 조각을 버린다. 수집기에 최소 길이 필터를 넣는다
```

⚠️ **게이트를 옮기지 않는다.** 미달이면 n 을 올리거나 기각한다.
G1·G3 은 구간 비중첩을 요구한다 — n=300 에서 폭이 약 10%p 이므로
**10%p 이상 올라야 통과**다. 그 미만의 개선은 이 표본으로 판정할 수 없다.

## 4. 예측 — 실행 전에 적는다 🟡

| 조건 | 예측 | 근거 |
|---|---:|---|
| `r1_ctrl` | 58~69% | 같은 코드·같은 데이터. 이게 벗어나면 뭔가 바뀐 것 |
| `r2_add` | **65~75%** | 오르되 G1(>68.9%)은 반반. 63.7%는 이미 높아 여지가 좁다 |
| `r2_only` | 30~55% | R1 없이는 낮은 성능 구간의 라벨이 없다 |
| `r1_min8` | 60~72% | 정지 샘플 제거 효과. G3 통과는 기대 안 함 |
| `r1_more` | 60~70% | 전문가 증량만으로도 조금 오를 것 |

**핵심 예측: `r2_add` 가 `r1_more` 와 구간이 겹친다** — 즉 라운드 추가의 값어치가
단순 증량과 구별되지 않는다. 이게 맞으면 실물에서 DAgger 를 포기할 근거가 된다
(실물 리셋 비용이 시연 추가 수집보다 비싸므로).

**틀릴 수 있는 지점:**

1. `r2_add` 가 `r1_more` 를 뚜렷이 이긴다 → DAgger 라운드가 실제로 값어치가 있고,
   실물 경로에서도 리셋 비용을 치를 이유가 생긴다
2. `r1_min8` 이 크게 오른다 → 문제가 DAgger 가 아니라 **종단 클램프**였다.
   그러면 `data/dataset.py` 를 고치는 게 우선이고 라운드 추가는 부차적이다
3. 전부 63.7% 근처에서 겹친다 → 데이터 처방도 소진. 남은 건 모델 구조다

## 5. 이 실험이 답하지 않는 것

- **실물 성능.** 전부 시뮬. 시뮬 성공률은 sim2real 갭의 하한이다
- **실물에서 DAgger 가 가능한가.** 리셋 60~120회의 실현성은 PM·HW 사안이다
- **ver1 측면 파지.** 전부 레거시 씬 2cm 큐브 상단 파지다
- **K=8 이 최적인 이유.** 조각 길이 가설은 0915 에 **기각**됐다(이봉 분포).
  현재 이유를 모른다. 이 실험은 그것도 답하지 않는다

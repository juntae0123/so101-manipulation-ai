## 0. 왜 쟀나

과제 ③(시연 정책 2종)의 두 번째 타겟이 필요했다.
처음 후보는 **상면 파지(top-down)** 였다 — 측면 파지와 접근 축이 직교해서
교차평가 차별력이 가장 크기 때문이다.

⚠️ 어시스턴트가 `simulation/env.py` 기본값으로 config 를 쓰면서
**"기본값이니 돌 것"이라고 가정했다. 검증된 적 없는 가정이었고 0/60 이 나왔다.**

## 1. 상면 파지 — 폐기 🟢

`run_expert`(top-down)는 `rotation=None` 으로 IK 를 풀고, 그 경로가
TCP +z 를 **수직 아래로 구속**한다. 그 구속 하의 도달 포락선:

```
격자 x 0.10~0.36 (27) × z 0.02~0.20 (19) = 513칸 · y=0 고정
도달  28칸 = 5.5%
도달 가능 z = 0.02 ~ 0.04 m  (x 0.14~0.27 대역)
```

전문가가 필요로 하는 높이:
```
pre  = 물체중심 − 0.01 + 0.115 = 0.130 m
lift = 물체중심 − 0.01 + 0.140 = 0.155 m
```

20편 요청 → **0/60**. 60건 전부 `Unreachable target [..., 0.12999521]`,
즉 **pre-grasp 에서 죽었다** (lift 까지 가지도 못함). residual 0.0667~0.0690 로
균일 — 경계선이 아니라 구조적으로 포락선 밖이다.

`home_q` 로는 못 고친다. `env.ik` 는 내부 고정 시드 5개로 풀기 때문에
시작 자세와 무관하다. **이 로봇 설정에서 상면 파지는 불가능하다.**

## 2. 물체 형상 실측 🟢


## 3. 측면 파지 포락선 🟢

접근 축을 +x 로 고정하고 `rotation` 을 명시한 IK:
```
z = 0.027 (박스 중심)  도달 x = 0.37 ~ 0.46
z = 0.051 (캔 중심)    도달 x = 0.34 ~ 0.46
```

## 4. 박스 측면 파지 — 폐기 🟢

`workspace_x [0.385, 0.415]`, `close_width 0.024` 로 20편 요청 → **0/60**.
실패가 두 갈래다:

| 갈래 | 수 | 신호 |
|---|---|---|
| pre-grasp IK 실패 | 35 | 목표 x 0.348~0.362 (포락선 하한 0.37 미만) · residual 0.008~0.0116 |
| 도달 후 파지 실패 | 25 | `lift_m` **정확히 0.0000** · 양측접촉 False · `normal_force` 0.34 N |

두 번째가 결정적이다. **물체 이동량이 0** 이라 그리퍼가 박스에 닿지도 않았다.

원인: 전문가는 **물체 중심 높이로 수평 진입**한다(하드코딩).
캔은 중심이 z=50.9mm 라 여유가 있지만 **박스는 25mm** 라 그 높이로는
그리퍼가 테이블에 걸린다. `close_width` 를 어떻게 바꿔도 안 닿는 건 못 고친다.

## 5. 캔 y 방향 전문가 성공률 🟢

`can_side` 에서 `workspace_y` 를 한 점으로 고정, 시드 9000~9004 (n=5/점):

```
y      성공/시도   중앙 lift_m
0.000    5/5        0.1193     ← 계측기 검증행
0.020    5/5        0.1193
0.040    5/5        0.1193
0.060    5/5        0.1192
0.080    5/5        0.1192
0.100    4/5        0.1192
0.120    3/5        0.1190
0.140    1/5        0.0103
0.160    1/5        0.0103
0.180    3/5        0.1187     ← 비단조. 설명 못 함. 쓰지 않는다
```

**y=0.000 의 5/5 는 계측기 자체 검증이다** — `can_side` 본 설정이 100편 100%
였으므로 여기서 5/5 가 안 나오면 이 스크립트를 믿을 수 없다.

⚠️ **n=5 는 95% 신뢰구간 반폭이 ±35%p 이상이다.** 대역의 경계를 이 표로
정밀하게 말할 수 없다. 여기서는 "0.08 이하는 확실히 되고 0.14 부터는 확실히
안 된다" 정도까지만 읽는다.

실패 신호는 박스 때와 같은 `lift_m ≈ 0.0103`, 양측접촉 False, `normal_force 3.42N`
— 한쪽 패드만 닿아 캔을 밀었다.

**추정 원인 🟡 (미검증)**: `env.ik` 통과 기준 `residual < 0.008` 에서
회전 오차 항의 가중치가 0.08 이다. 위치 오차가 0이어도 **자세 오차 0.1rad(5.7°)
까지 통과**한다. y 가 커질수록 필요한 회전이 커지고 어긋난 턱이 캔을 스친다.
**이건 설계 판단이지 측정이 아니다** — 자세 오차와 실패를 직접 짝지어 재지 않았다.

## 6. 채택 — `can_left` 🟢

```
workspace_y: [0.06, 0.10]   (나머지는 can_side 와 동일)
시드 8200~8219, 20편 요청 → 시도 20 · 성공 20 = 100.0%
```

낭비된 시도 0 (시드가 정확히 20개만 소비됨).

⚠️ `workspace_y` 는 **62.5% 관측 후 1회 조정한 값**이다. 최초 `[0.10, 0.16]`
에서 20/32 = 62.5% 가 나왔고, 5절의 y 스윕을 근거로 `[0.06, 0.10]` 으로 옮겼다.
조정은 1회로 미리 제한했고 그 안에서 끝났다.

## 7. 이 측정이 프로젝트에 갖는 의미

**시연 생성기가 물체 전용이다.** `run_side_expert` 는 물체 위치는 따라가지만
물체의 **크기·높이는 못 따라간다**. 잡는 높이가 물체 중심으로 고정이고
대기 지점이 50mm 뒤로 고정이다.

→ 제품의 **5스킬 물체를 고를 때 "작은 부품"으로는 부족하다.**
   높이 10cm급 측면 파지가 아닌 물체는 전문가 코드를 새로 써야 한다.
   HW·PM 확인 필요.

→ 타겟 도메인(D-AI-19, 다품종 소량생산 소형부품)과 정면으로 부딪친다.
   소형부품은 대체로 낮다. **이 시뮬 자산으로 그 도메인을 시연할 수 없다.**

# TS — 시뮬 정책이 안 움직인다: 어떻게 원인을 좁혔나

- 일자 2026-09-14 · 작성 김준태(트랙 B) · 이슈 S15P21A103-34
- 결론 **계약 0.3.0 의 `action[t] = state[t+1]` 규약이 학습을 무력화한다** 🟢
- 상태 **확정** — 조건당 독립 학습 3회 × n=100, 신뢰구간 비중첩

---

## 0. 증상

계약 0.3.0 규약으로 시뮬 데이터를 수집해 BC 를 학습했더니:

```
val loss 0.05      ← 아주 좋다. 실수집 UMI(0.34)보다 7배 정확
롤아웃   0/100     ← 완전 실패
평균 상승 0.00cm   ← 팔이 제자리
닫는 순간 158.1mm  ← 기존 BC v3 는 15.7~23.6mm
```

**손실만 보면 최고 성적이고 롤아웃은 0이다.** 이 프로젝트 함정 1번의 가장 극단적인 형태다.

## 1. 먼저 무엇이 아닌지부터 잘랐다

| 용의자 | 어떻게 배제했나 | 결과 |
|---|---|---|
| 씬·태스크 고장 | 같은 실행의 baseline | scripted 84/100, ceiling·task_validity 통과 🟢 |
| 카메라 1대 | 손목 전용 DAgger 실적 | 51.4% [47.0, 55.8] n=500 🟢 **무죄** |
| 물체 위치 변주 부족 | j0/j25/j50 3조건 × 학습 3회 × n=100 | 전부 0%. 설명력 낙폭 0.6%p 🟢 **기각** |
| 제어 주기 (30Hz) | stride 1/2/3 설명력 스윕 | 낙폭 12.1%p, 게이트 15%p 미달 🟢 **기각** |
| 이미지 경로 고장 | 픽셀 std 63.47 · 프레임 간 2.47 | 정상 🟢 **무죄** |
| 모델 용량 | `--val-fraction 0` 120epoch | train 0.0958 < 0.10 🟢 **무죄** |

**닫는 순간 거리가 조건과 무관하게 158.0~158.3mm 로 붙어 있었던 것**이 결정적 단서였다.
데이터가 무엇이든(고정/±25mm/±50mm, 59~60편) 정책이 **똑같이** 행동한다.
그러면 원인은 데이터의 내용이 아니라 **데이터의 형식**에 있다.

## 2. 가설

그날 아침 별개로 측정한 값이 실마리였다.

```
실데이터 UMI  다음 관절각의 93.8% 가 관측 없이 외삽으로 맞는다
시뮬 (신규)   87.2~87.8%
```

`action[t] = state[t+1]` 은 **"이미 간 거리"** 다. 30Hz 에서 그것은 아주 작고
(계약 단위 0.001~0.002), 거의 전부 "가던 대로"로 설명된다.

```
타깃이 이미 간 거리
   ↓ 관측 없이 87~94% 예측 가능
모델이 0.05 SD 로 거의 완벽히 맞힌다
   ↓ 롤아웃에서 자기 예측을 다시 먹는다
"가던 대로" = 정지에서 시작하면 정지가 고정점
   ↓
팔이 안 움직이고 158mm 에서 그리퍼만 닫는다
```

옛 규약 `action = data.ctrl` 은 다르다. **제어기가 쫓는 목표라 현재 자세보다 앞서 있고,
`ctrl − qpos` 가 "어디로 가려는가"를 담는다.**

## 3. 첫 격리 시도는 실패했다 — 기록해 둔다

`sim_pick_v3`(옛 규약)를 손목 전용으로 학습하려 했으나 **로더가 거부**했다.

```
ValueError: contract_version '0.2.0-provisional' != '0.3.0-provisional'
```

계약 0.3.0 로더는 옛 데이터를 학습에 쓰지 못한다. **266편 무효라고 직접 적어놓고
그 데이터로 격리하려 한 설계 실수였다.**

## 4. 두 번째 격리 — 계약을 안 깨고 가른다

수집기가 `data.ctrl` 을 **사이드카 파일**(`ep_XXXXX.command.npy`)로 같이 저장하게 했다.
`read_episode` 도 `validate()` 도 이 파일을 보지 않으므로 **계약 npz 는 그대로다.**

### 4-1. 데이터 수준 선검증 (학습 없음, 10초)

같은 59편에서 두 타깃의 외삽 설명력을 비교했다.

| 타깃 | 크기 | 외삽잔차 | 설명력 |
|---|---:|---:|---:|
| `action = state[t+1]` | 0.00356 | 0.00045 | **87.4%** |
| `command = ctrl` | 0.00316 | 0.00104 | **67.0%** |

낙폭 **20.4%p** (사전등록 게이트 20%p). 통과했지만 **여유가 0.4%p 다.**
명령 선행량 / 실제 이동량 = **1.46x** — 명령이 이동보다 1.46배 앞설 뿐이다.

이 시점의 판단: **전제는 살아남았으나 효과 크기가 작다. 학습으로 확인해야 한다.**

### 4-2. 학습 로더에 사이드카 타깃 옵션 추가

`EpisodeDataset(..., target_sidecar=...)` · `train_bc.py --target-sidecar command`.
계약 파일은 건드리지 않는다.

### 4-3. 결정적 비교 🟢

**같은 데이터 · 같은 시드 집합 · 같은 하이퍼파라미터. 타깃만 다르다.**
**독립 학습 3회 × 롤아웃 n=100 = 조건당 300 시행.**

| 시드 | `action = state[t+1]` | | `command = ctrl` | |
|---|---:|---:|---:|---:|
| | 성공률 | 닫는 순간 | 성공률 | 닫는 순간 |
| 0 | 0/100 | 158.1mm | 13/100 | 45.2mm |
| 1 | 0/100 | 158.4mm | 1/100 | 42.5mm |
| 2 | 0/100 | 158.3mm | 8/100 | 48.8mm |
| **합계** | **0/300 = 0.0%** | **158.3mm** | **22/300 = 7.3%** | **45.5mm** |
| 95% 구간 | **[0.0, 1.3%]** | 폭 0.3mm | **[4.9, 10.9%]** | 폭 6.3mm |

조건: MuJoCo 3.12.0 EGL 헤드리스 · 30Hz · 2cm 20g 큐브 · 물체 xy 지터 ±50mm ·
`sim_pick_cmd` 59편 · `cam_wrist` 1대 · `joint_delta_gripper_binary` ·
학습 시드 0·1·2 · 평가 시드 3000~3099 (학습과 분리) · `offsamples 0`(결정론)

**성공률 신뢰구간이 겹치지 않는다** — [0.0, 1.3] vs [4.9, 10.9].

**그리고 닫는 순간 거리가 훨씬 강한 증거다.**

```
contract  158.1 / 158.4 / 158.3      폭 0.3mm
command    45.2 /  42.5 /  48.8      폭 6.3mm
```

**3.5배 차이이고 두 분포가 전혀 겹치지 않는다.**
성공률은 시드 간 13배(1% vs 13%) 갈리는데 거리는 14% 안에서 논다 —
즉 거리는 학습 편차에 둔감하고 **정책이 어디로 가려 했는지를 직접 잰다.**

⚠️ `contract` 조건의 158mm 는 **총 다섯 개 조건에서 재현**됐다 (j0·j25·j50·cmdtest·ctr 2시드).
데이터 내용·편수·물체 지터가 전부 달라도 폭 0.4mm 다.
계약 규약 아래서는 **정책이 무엇을 학습하든 같은 자리에서 닫는다.**

## 5. 남는 한계 — 먼저 말한다

- **7.3% 는 게이트 20% 한참 미달이다.** 원인 하나를 제거한 것이지 문제를 푼 것이 아니다
- **시드 편차가 크다** — 1% / 8% / 13%. 단일 시드 수치를 인용하면 안 된다.
  특히 "13%" 단독 인용 금지. 평균 7.3% [4.9, 10.9] 와 범위를 같이 쓴다
- **실물에 `ctrl` 에 해당하는 값이 있는지 모른다.** 트랙 A 확인 사항이다.
  UMI raw 에 EEF 목표 pose 계열이 남아 있으면 그것이 대응물이다
- `command` 타깃도 `shoulder_pan` 58% · `wrist_roll` 70% 가 정확히 0 이다.
  스크립트 시연이라 `ctrl` 이 웨이포인트 사이에서 계단 함수이기 때문으로 보인다 🟡.
  사람 시연에서는 다를 수 있다
- 시뮬 씬은 여전히 옛 그리퍼다 (이슈 166). 이 비교는 **시뮬 내부 조건 간 비교**로만 유효하다

## 7. 이 건에서 내가 틀린 것

1. 계약 0.3.0 을 따르려고 `collect.py` 를 고쳤고, **그 변경이 시뮬 학습을 죽였다.**
   규약 자체의 결함이지만 계기는 내 패치였다
2. 첫 격리를 **0.2.0 데이터로 설계**했다. 로더가 거부한다는 것을 알고 있었는데도
3. 하루 동안 처방 후보를 둘(다운샘플·물체 변주) 세워 둘 다 기각했는데,
   **진짜 원인은 그 목록에 없었다.** 증상(정책이 안 움직인다)을 먼저 보고
   형식(액션 정의)을 나중에 본 순서가 늦었다

### ① 정책은 이미지를 실제로 쓴다 🟢 — 오늘 가장 강한 결과

두 번 독립적으로 확인했다.

**시뮬 `command` 6시드 (0914 실행 / 0915 판독)**

| | 성공/전체 | 성공률 | 95% 구간 |
|---|---:|---:|---|
| 정상 이미지 | 56/600 | 9.3% | [7.3, 11.9] |
| 이미지 파괴 (`--image-noise 96`) | 10/600 | 1.7% | [0.9, 3.0] |

같은 시드끼리(3·4·5) 붙이면 11.3% [8.2, 15.4] vs 0.0% [0.0, 1.3] 로 **완전 분리**.
붕괴 시드가 노이즈 조건에서만 났다(6시드 중 2건) — 학습 불안정이 아니라 파괴의 효과다.

**청킹 조건 (0915)**

```

chunk8 궤적타깃   9.7% [6.8, 13.5]  vs  이미지파괴 0.0% [0.0, 1.3]
```

⇒ **액션 정의 처방(0914)이 실효가 있었다. 8~13% 는 상태 기반 지름길이 아니라
시각운동 학습이다.** 그리고 **트랙 A v6 의 궤적 타깃도 이미지를 쓴다** — 내 예측이
틀렸고, 그 축에서는 v6 에 문제가 없다.

## 2. BC 계열 처방이 소진됐다

```
제어주기 다운샘플 30->10Hz    기각 (낙폭 12.1%p, 게이트 15%p 미달)
물체 위치 변주 확대            기각 (낙폭 0.6%p, 세 조건 전부 0/300)
액션 타깃 리드 state[t+k]      기각 (0/300, 게인 교란 있음)
행동 청킹 K=2/4/8/16           기각 (구간 전부 중첩)
액션 정의 ctrl                 효과 있음 0% -> 8~13%. 게이트 20% 는 미달
```

**모델을 더 바꾸는 것은 여기서 멈춘다.** 다음 가설은 데이터다.

```
scripted (정답 위치 사용)   84%                          태스크는 풀린다
학습 정책 최고              13.3%                        위치 추정 비용 70%p
DAgger 손목전용             51.4% [47.0, 55.8] n=500 🟢
```

같은 씬·같은 카메라 1대인데 13.3% 와 51.4% 다. **차이는 수집 방식뿐이다.**

⚠️ DAgger 데이터는 계약 0.2.0 이라 현행 로더가 거부한다. 0.3.0 + `command` 사이드카
재수집이 필요한지 확인이 선행이다.

## 4. 고친 버그

**① `TargetTransform.to()` 가 `grip_mid` 를 버렸다** 🔴
`--device cuda` 학습은 전부 이 경로다. 데이터 파생 그리퍼 임계값이 매번 버려지고
시뮬 설정값으로 되돌아갔다. 시뮬은 두 값이 가까워 영향이 작지만 **실데이터에서는
틀린 임계값으로 이진화된다.**

⚠️ 이 수정 때문에 `command` 정본이 바뀐다. **9.3% [7.3, 11.9] n=600 → 8.0%
[5.4, 11.6] n=300** (지금 코드 기준). 구간이 겹쳐 결론은 불변.

**② `eval/repeat.py` 가 학습 기록을 (데이터, 시드) 로만 찾았다** 🔴
8잡 병렬 실행에서 서로의 `val_loss` 를 집어갔다. `train_bc` 기록에 `out`·`chunk` 를
넣고 체크포인트 경로로 찾게 고쳤다. **성공률은 원래 `policy_ckpt` 로 찾아서 무사했다.**

**③ 내가 낸 버그 7건** — 전부 "새 걸 만들고 그걸 쓰는 쪽을 안 봤다".
상세와 조치는 `TS_chunking_0915.md` 5절.

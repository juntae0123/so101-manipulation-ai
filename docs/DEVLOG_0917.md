## 1. 과제 ② — 시뮬 UMI 모방학습 🟢 게이트 통과

```
seed 0   92/100 · seed 1  100/100 · seed 2   99/100
합산   291/300 = 97.0%  Wilson95 [94.4, 98.4]  시드 범위 8.0%p
G1a 통과 (하한 94.4 > 5) · G1b 통과 (하한 ≥50 이고 폭 ≤20%p)
```

scripted expert 자신이 생성 시 100/100 이었으니 **정책이 전문가에 거의 근접**했다.

조건: 시뮬 시연 100편(시드 6000–6099) · 공식 UMI diffusion · 60 epoch · batch 8 ·
평가 시드 7000–7099 · 성공 = 리프트 > 0.10m 이고 hold ≥ 0.5초.

⚠️ 같은 태스크·같은 물체·같은 작업영역이다. 물체 위치 변주에 대한 일반화지 sim2real 이 아니다.

## 2. 과제 ③ — 정책 2종 🟢 게이트 전부 통과

```
T1 자기평가 can_side   291/300 97.0% [94.4, 98.4]
T2 자기평가 can_left   288/300 96.0% [93.1, 97.7]
교차 T1정책→can_left     4/300  1.3% [0.5, 3.4]
교차 T2정책→can_side     4/300  1.3% [0.5, 3.4]
```

**G3a 통과 ×2 · G3b 통과 ×2.** 교차 상한 3.4% 와 자기평가 하한 93.1% 가 겹칠 여지가 없다.

T1/T2 차이는 `workspace_y` 뿐이다(중앙 ±35mm vs 60~100mm). 가장 가까운 가장자리가
25mm 밖에 안 떨어져 안 갈릴 수도 있다고 미리 적었는데 **완전히 갈렸다.**

⚠️ **발표 문구 상한** — "다른 조작 태스크 2종"이 아니라 **"같은 태스크의 다른 위치 2개"** 다.
정확히는 "2개 타겟을 각각 학습·저장하고 선택 실행".

## 3. 과제 ① — 질문이 틀렸다. 이게 오늘의 핵심

### 3-1. 실데이터는 이미 서버에 있었다

기다리던 69편이 `~/S15P21A103_umi/AI/datasets/umi_real_relative_20260911_v10` 에
**70편 다 있었다.** 트랙 A 가 계속 푸시하고 있었고 나는 도착을 기다리고 있었다.
`dataset.json` 하나 열어보면 끝날 일이었다.

### 3-2. v10 규약을 스윕으로 확정 🟢

v10 은 절대 pose 를 담지 않는다. `action[i,0]` 을 연쇄해 복원해야 하는데
규약을 몰랐다. **추측하지 않고 8개 조합을 전부 재봤다.**

```
 rows  compose  trans |  pos_med  pos_max
 True    right  False |   0.0000    0.000   ← 정답
 (나머지 7조합)       |   2.0~4.2mm 남음
```

**`r0, r1` 은 회전행렬의 열이 아니라 행이다.** 열로 읽으면 중앙오차 4mm 가
**조용히** 남는다. 그리고 `source_row` 간격이 균일하지 않다(2·3 혼재) —
0.1초 고정으로 속도를 계산하면 1.5배 어긋난다.

### 3-3. 폐기율 71% — 철회

전체 궤적 기준 IK 수용률 **19/65 = 29.2%** 가 나왔고, 거부의 43%가 자세 불일치라
**"5자유도 때문에 시연의 71%를 버린다"** 로 해석했다. HW·PM 에 6축 전환 검토를
요청하는 보고서까지 썼다. **보내기 직전에 사용자가 잡았다.**

> 사람이 요란법석을 떨면서 집어도 로봇은 요란 떨 필요 없이 똑같이 집으면 된다.

**이 제품은 궤적을 재현하지 않는다.** 접근 중 손 휘저은 구간까지 실패로 세면
숫자가 통째로 부풀려진다. 재는 대상이 틀렸던 것이지 계산이 틀린 게 아니다.

### 3-4. 앵커를 파지 순간으로 옮기니 🟢

물체가 어디 있었는지는 **그리퍼가 닫혀 멈춘 순간**이 말해준다(사용자 지적).

```
T_base[t] = T_grasp_sim @ inv(chain[closure]) @ chain[t]
```

```
앵커 start · 구간 full    29.2%   ← 궤적 모방 난이도. 폐기율 아님
앵커 start · 구간 grasp    47.5%  ← 앵커가 틀린 중간 산물
앵커 grasp · 구간 grasp   waypoint 533/535 = 99.6% · chunk 30/30 = 100%
                          거부 rotation 2건이 전부
```

**5자유도는 결과 모방의 병목이 아니다.** 535개 중 자유도로 막힌 건 2개다.

### 3-5. 닫힘 검출을 검증했다 🟢

닫힘 순간의 gap 은 곧 물체 폭이다. 70편이 같은 물체를 잡았으니 모여야 한다.
```
중앙 38.5mm · 범위 32.4~43.5mm (n=69)   ← 트랙 A 케이스 39mm 잠정과 일치
```
**이 검증이 없었으면 99.6% 도 못 믿었다.**

⚠️ 부수 발견 — 38.5mm 가 지침의 *"대상물 1.5~2.5cm"* 범위 **밖**이다.
9/13 그리퍼 변경 이후인지 지침이 낡은 건지 **모른다. HW 확인 필요.**

### 3-6. 남은 실패는 전부 속도, 그리고 그건 게이트가 아니다

시간확대율 최대 48.0. 예산의 분모가 **의도적으로 느린 시뮬 스크립트**라
"사람 손이 우리 스크립트보다 48배 빠르다"는 뜻이지 서보 한계가 아니다.
SO-101 실제 속도 한계는 미측정(LIMITS). 결과 모방이면 로봇이 자기 속도로 가면 된다.
**이 판단은 결과를 보기 전에 선언했다.**

# MEASURE — 이미지 어블레이션: 정책이 이미지를 쓴다

- 실행 2026-09-14 · 판독 2026-09-15 · 김준태(트랙 B)
- 이슈 S15P21A103-34, -171 · 사전등록 판정규칙은 실행 전 확정 (대화 기록)
- 결론 **`command` 타깃 정책은 이미지를 실제로 사용한다** 🟢

---

## 0. 세 줄

1. 같은 데이터·같은 시드·같은 설정에서 **이미지만 파괴**했더니 성공률이
   **9.3% → 1.7%** 로 떨어졌다. 95% 구간 비중첩
2. 같은 시드끼리 붙이면 더 깨끗하다 — 시드 3·4·5 에서 **11.3% vs 0.0%**, 완전 분리
3. **학습 붕괴가 이미지 파괴 쪽에서만 났다** (6시드 중 2건). 붕괴를 빼도 결론 불변

## 1. 왜 쟀나

액션 정의를 `state[t+1]` 에서 `ctrl` 로 바꾸자 시뮬 롤아웃이 0/300 → 22/300 으로
살아났다 (0914 🟢). **그런데 그 7.3% 가 무엇인지는 몰랐다.**

- 이미지를 써서 물체를 찾아간 결과인가
- 아니면 물체와 무관한 고정 궤적이 우연히 맞은 것인가 (상태 기반 지름길)

실수집 UMI 에서는 이미지를 96계조 노이즈로 파괴해도 val 이 안 변했다 (3시드 중첩).
**시뮬 `ctrl` 정책에는 이 대조군을 한 번도 안 돌렸다.** 외부 검토에서 지적받아
빈 칸을 채웠다.

⚠️ 이 칸이 비어 있으면 액션 정의 처방이 옳았는지 알 수 없다. 지름길이라면
청킹을 얹어도 같은 벽이고, 모델이 아니라 데이터·평가 파이프라인으로 돌아가야 한다.

## 2. 결과 🟢

조건: MuJoCo 3.12.0 EGL · 30Hz · 2cm 20g 큐브 · 물체 xy 지터 ±50mm ·
`sim_pick_cmd` 59편 · `cam_wrist` 1대 · `joint_delta_gripper_binary` ·
`--target-sidecar command` · 평가 시드 3000~3099 · `offsamples 0`(결정론)

이미지 파괴는 `--image-noise 96` (학습 이미지에 σ=96계조 잡음).

### 합산 (시드 0~5, 조건당 6런 × n=100)

| | 성공/전체 | 성공률 | 95% 구간 |
|---|---:|---:|---|
| **정상 이미지** | 56/600 | **9.3%** | **[7.3, 11.9]** |
| **이미지 파괴** | 10/600 | **1.7%** | **[0.9, 3.0]** |

**구간 비중첩.**

### 같은 시드 head-to-head (시드 3·4·5)

| | 성공/전체 | 성공률 | 95% 구간 | 시드별 |
|---|---:|---:|---|---|
| 정상 이미지 | 34/300 | 11.3% | [8.2, 15.4] | 17 / 12 / 5 |
| 이미지 파괴 | 0/300 | 0.0% | [0.0, 1.3] | 0 / 0 / 0 |

**완전 분리.** 데이터·시드·하이퍼파라미터가 전부 같고 이미지만 다르다.

### 시드 0~2 (1차, 판정 유보였던 것)

| | 성공/전체 | 성공률 | 95% 구간 |
|---|---:|---:|---|
| 정상 이미지 | 22/300 | 7.3% | [4.9, 10.9] |
| 이미지 파괴 | 10/300 | 3.3% | [1.8, 6.0] |

4.9~6.0 이 겹쳐 **1차에서는 판정할 수 없었다.** 게이트를 옮기지 않고 n 을 올려
해소했다 (3시드 → 6시드).

## 3. 학습 붕괴가 한쪽에서만 났다 🟢

```
정상 이미지 6시드   val 0.072 ~ 0.089    붕괴 0건
이미지 파괴 6시드   val 0.123 ~ 5.971    붕괴 2건
```

붕괴 기준은 **자명한 예측기(항상 열어둠) 손실 2.55132** 다. `train_bc` 가 매 실행
머리말에 이 값을 찍는다. val 이 여기 붙으면 학습이 안 된 것이다.

```
cmd_noise96      시드 2   val 2.554
cmd_noise96_s345 시드 3   val 5.971
```

**정상 이미지 쪽은 6시드 전부 0.072~0.089 로 안정적이다.** 붕괴가 노이즈 조건에서만
나므로 이것은 학습 불안정이 아니라 **이미지 파괴의 효과**다.

붕괴 2시드를 제외해도 결론이 안 바뀐다:

```
이미지 파괴 (붕괴 제외)   10/400 = 2.5% [1.4, 4.5]   vs   정상 [7.3, 11.9]
```

여전히 비중첩. **어느 쪽으로 세든 같은 답이다.**

## 4. 실패 모양 🟢

이미지 파괴 조건의 실패 100건:

```
그리퍼 명령 최솟값 중앙   -0.193   (scripted -0.756)
실패 100건 전부 닫는 동작 없음 (명령 진폭 < 0.05)
파지점-물체 최소 수평거리 중앙 28.5mm  (이 태스크 허용오차는 약 10mm)
```

**그리퍼 출력이 죽어 있고 물체 근처로 가지도 못한다.** 정상 이미지 조건에서는
45.5mm 에서 실제로 닫았다. 이미지가 없으면 물체 위치를 못 찾는다는 것이
실패 모양에서도 보인다.

## 6. 수치 정정

`command` 조건의 정본 수치를 갱신한다.

```
이전 인용   7.3% [4.9, 10.9]   n=300 (3시드)
정본        9.3% [7.3, 11.9]   n=600 (6시드)
```

**앞으로 9.3% [7.3, 11.9] n=600 을 쓴다.** 기존 문서의 7.3% 는 3시드 표기로 남긴다.

## 7. 계측기

`tools/pool_rollouts.py` 를 새로 만들었다. 모든 실행 로그를 훑어 조건별로 합산하고
Wilson 구간을 내며, **val 이 자명한 예측기 수준이거나 nan 인 시드를 자동으로 표시**한다.

1차 판정이 오염된 이유가 붕괴 시드를 사람이 못 보고 지나친 것이었다.

⚠️ **한계** — 분석기가 `command` 시드 0~2 의 실행 로그를 찾지 못했다
(`out/logs/` 밖에 있다). 6시드 합산은 손으로 더한 값이다.
해당 로그를 `out/logs/` 로 옮겨야 자동 합산이 완전해진다.

## 8. 예측 대조

실행 전 예측: **"겹칠 것 같다"** (= 이미지를 안 쓴다).

**틀렸다.** 이미지를 쓴다. 근거로 든 것은 시드 편차가 크다는 점과 실데이터에서
이미지 기여가 0 이었다는 점인데, **실데이터의 그 성질은 액션 정의 때문이었고
시뮬에는 해당하지 않았다.**

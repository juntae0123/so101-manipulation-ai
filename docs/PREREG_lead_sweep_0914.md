## 0. 왜 하나

계약 0.3.0 의 `action[t] = state[t+1]` 이 학습을 무력화한다 (0914 확정 🟢, 0/300 vs 22/300).
`ctrl` 은 살아났지만 **실수집 UMI 에 대응물이 있는지 모른다** — 트랙 A 확인 대기다.

`state[t+k]` 는 **기존 계약 데이터만으로 계산된다.** 재수집도, 계약 변경도,
상대 트랙 답변도 필요 없다. 이것이 `ctrl` 을 대체하면:

- 기존 UMI 67편이 재수집 없이 살아난다
- D-AI-47(계약에 `command` 추가)이 **불필요해진다**
- 트랙 A 답변 대기 없이 진행된다

## 1. 무엇을 바꾸나 — 하나만 바꾼다

같은 데이터(`sim_pick_cmd` 59편), 같은 시드 집합(0·1·2), 같은 하이퍼파라미터.
**타깃만** 다르다.

```
lead1   state[min(t+1, T-1)]   = 계약 action (계측기 검증용)
lead2   state[min(t+2, T-1)]
lead4   state[min(t+4, T-1)]
lead8   state[min(t+8, T-1)]
lead16  state[min(t+16, T-1)]
command ctrl                    = 0914 측정된 기준점 (재측정 안 함)
```

종단 규약: `t+k` 가 에피소드를 넘으면 **마지막 state 로 클램프.** 자르지 않는다 —
샘플 수가 k 에 따라 변하면 조건 간 비교가 깨진다.

사이드카(`ep_XXXXX.lead{k}.npy`)로 쓴다. `read_episode` 도 `validate()` 도 보지 않으므로
**계약 npz 는 그대로다.**

## 1-정정 (2026-09-14, 1차 실행 직후) — 계측기에 결함이 있었다 🟢

**1차 스윕에 쓴 설명력의 외삽 기준선이 1스텝 고정이었다** (`2*s[t] - s[t-1]`).
k 스텝 앞 타깃을 1스텝 외삽으로 맞히라고 시키는 계측기다. k 가 커질수록 기준선이
자동으로 무너지고, **그 무너짐이 "좋은 타깃"으로 오독된다.**

증거 — k=16 에서 외삽잔차/크기 = 0.04345 / 0.04636 = **93.7%.**
외삽이 사실상 아무것도 못 맞히고 있었다.

| k | 크기 | 외삽잔차(1스텝) | 비율 |
|---|---:|---:|---:|
| 1 | 0.00356 | 0.00045 | 12.6% |
| 2 | 0.00697 | 0.00362 | 51.9% |
| 4 | 0.01359 | 0.01027 | 75.6% |
| 8 | 0.02581 | 0.02265 | 87.8% |
| 16 | 0.04636 | 0.04345 | **93.7%** |

**수정**: 기준선을 `s[t] + k*(s[t] - s[t-1])` 로 바꿨다 — "가던 대로 k 스텝 가면 어디".
`ctrl` 은 정수 스텝이 아니므로 실측 리드 비율(1.46)을 지평으로 쓴다.
두 값을 나란히 출력해 옛 수치와 대조 가능하게 뒀다.

⚠️ **1차 출력의 낙폭 수치(lead2 39.3%p 등)는 폐기한다.** 2차 출력으로 판정한다.
G1 게이트 자체는 그대로 둔다 — 게이트를 옮기는 게 아니라 계측기를 고친 것이다.

⚠️ 남는 한계: 정책은 state 이력이 아니라 **현재 state 한 장**만 본다
(`use_state=true`, 단일 프레임). 외삽 기준선은 정책이 실제로 쓸 수 있는 것보다
강하므로 **설명력은 상한이다.**

## 2. 계측기 검증 — 쓰기 전에 검증한다

| 검사 | 통과 조건 |
|---|---|
| `lead1` == 계약 `action` | 마지막 틱 제외 최대 차이 < 1e-4 |
| `lead1` 학습 롤아웃 | 기존 contract 조건 재현 — 0/300, 닫는 순간 158.3 ± 1mm |

**두 번째가 실패하면 이 스윕 전체가 무효다.** 같은 것을 다르게 재고 있다는 뜻이다.

## 3. 게이트 — 결과 보기 전 확정

**1차 (데이터 수준, 학습 없음).** 통과 못 하면 학습을 돌리지 않는다.

```
G1  어떤 k 에서 설명력 낙폭이 ctrl 의 낙폭(20.4%p) 이상이다
```

**2차 (롤아웃, 조건당 학습 3회 × n=100 = 300 시행).**

```
G2  어떤 k 의 성공률 95% 하한이 command 조건의 하한(4.9%) 이상이다
    -> 기존 UMI 수집분 구제 가능. D-AI-47 불필요

G3  어떤 k 의 성공률 95% 하한이 20% 이상이다
    -> 게이트 통과. (기대 안 함. 아래 예측 참조)
```

**닫는 순간 거리도 함께 본다** — 성공률보다 학습 편차에 둔감하고 분리가 뚜렷하다.
기준점: contract 158.3mm (폭 0.3) / command 45.5mm (폭 6.3).

⚠️ **게이트를 옮기지 않는다.** 미달이면 n 을 올리거나 기각한다.

## 4. 예측 — 실행 전에 적는다 🟡

| k | 설명력 | 성공률 |
|---|---:|---:|
| 1 | 87.4% (측정됨 🟢) | 0% (측정됨 🟢) |
| 2 | 78~83% | 0~2% |
| 4 | 68~75% | 3~8% |
| **8** | **58~68%** | **5~12%** ← 최적 예상 |
| 16 | 45~58% | 3~10% |
| command | 67.0% (측정됨 🟢) | 7.3% (측정됨 🟢) |

**핵심 예측: k=4~8 에서 `ctrl` 과 비슷해진다.** `ctrl` 의 리드/이동 비가 1.46x 였으니
그 정도 리드를 만드는 k 가 4 근처다.

**반증 가능한 형태로 적는다 — 틀릴 수 있는 지점:**

1. **k 가 커지면 단조 개선일 수 있다.** 그러면 "리드가 클수록 좋다"이고,
   최적은 스윕 밖(k=32 이상)에 있다. k16 > k8 이면 이쪽
2. **어떤 k 도 `ctrl` 을 못 따라갈 수 있다.** `ctrl` 의 값어치가 리드가 아니라
   **제어기 내부 정보**(웨이포인트 계단 구조)라면 그렇다. 전부 4% 미만이면 이쪽
3. **전부 0% 일 수 있다.** 리드는 필요조건이지 충분조건이 아닐 수 있다

2번이면 D-AI-47 이 필수가 되고 실데이터는 트랙 A 답변에 통째로 걸린다.
3번이면 남은 처방은 청킹(S15P21A103-171)뿐이다.

## 5. 이 실험이 답하지 않는 것

- **게이트 20% 를 넘는 방법.** 기대치가 5~12%다. 원인 제거이지 해결이 아니다
- **실물 성능.** 전부 시뮬이고 시뮬 성공률은 sim2real 갭의 하한이다
- **실데이터의 최적 k.** 시뮬(설명력 87.4%)과 실데이터(93.8%)는 다르다.
  시뮬에서 정한 k 를 실데이터에 그대로 쓰는 것은 🟡 가정이며 172 에서 따로 잰다
- **스크립트 시연 특유일 가능성** 🟡 — `ctrl` 이 웨이포인트 사이 계단 함수라
  `command` 타깃도 `shoulder_pan` 58% · `wrist_roll` 70% 가 정확히 0 이다.
  사람 시연에서는 다를 수 있다

## 2. 왜 회전만 identity 보다 나쁜가 — 잡음/편향 분리 🟢

single-sample 오차만 보면 "회전을 못 배웠다"와 "표집 잡음에 묻혔다"가 **같은 출력**으로 나온다.
가르려면 같은 관측을 K번 표집해 흩어짐을 따로 재야 한다. `diag_action_noise_floor.py` 가 그것이다.

```
single   K개 표본 각각의 GT 오차
spread   K개 표본이 자기들 평균에서 흩어진 정도   ← 잡음
mean_K   K평균 예측의 GT 오차                    ← 편향 (K 유한이면 상한)
```

### A_s0 · K 스윕

| | train 1021표본 | | | holdout 226표본 | | |
|---|---|---|---|---|---|---|
| | trans_mm | rot_deg | gap_mm | trans_mm | rot_deg | gap_mm |
| single | 29.58 | 4.78 | 2.54 | 40.27 | 5.33 | 3.50 |
| spread | 24.28 | 4.47 | 1.94 | 23.80 | 4.44 | 2.04 |
| mean_K=8 | 18.46 | 2.53 | 2.00 | 31.56 | 3.17 | 3.07 |
| **mean_K=32** | **15.88** | **1.83** | **1.90** | **29.75** | **2.63** | **2.94** |
| identity | 49.22 | 2.31 | 5.26 | 50.72 | 2.45 | 5.43 |
| K=32 개선 | +67.7% | **+20.6%** | +63.8% | +41.4% | **-7.1%** | +45.8% |

### 판정 (기준은 결과 보기 전 확정했다)

사전 기준: *"K=32 에서 train rot mean_K < identity 2.305 → 회전도 학습됨"*
→ **1.831 < 2.305. 통과.**

```
회전 오차의 94%가 표집 잡음이다 (spread 4.47 / single 4.78)
→ 규약(행/열)·정규화 역변환·시간 정렬에 계통 버그 없음
→ single-sample 에서 identity 에 지던 것은 신호(0.8초에 2.3도)가 잡음에 묻혔기 때문
```

**결론: A조건은 세 채널 모두 학습됐다. 회전만 홀드아웃으로 일반화되지 않는다.**
(train +20.6% / holdout -7.1%)

**이것이 과제 1 이 겨눌 구멍이다 — 회전 일반화.** 시뮬 사전학습(B조건)이 여기를
메우는지가 E2 의 실질 시험대다.

### 한계

- K=8 → 32 에서 mean_K 가 아직 내려가는 중이다. **수렴하지 않았다.** mean_K 는 편향의
  상한이므로 실제 편향은 양쪽 다 더 낮고, holdout 의 -7.1% 는 K 를 더 키우면 뒤집힐 수 있다.
  기준을 K=32 로 박아뒀으므로 여기서 멈춘다.
- **K평균은 사전등록 지표가 아니다.** 주 지표는 single 이고 B-A 비교도 single 로 한다.
  K평균은 별도 관찰로만 기록한다. 게이트를 옮기지 않는다.
- 롤아웃 성공률이 아니다. val_loss 가 내려가도 롤아웃 0% 였던 전례가 있다.

### 부수 관찰 (미검증, 결정 근거로 쓰지 말 것) 🟡

K평균을 추론에 쓰면 병진 오차가 홀드아웃에서 39.9mm → 29.7mm 로 준다. 추론 비용 K배.
**실행 주기 안에 들어가는지 측정 안 했다.** 롤아웃 효과도 미측정.

## 3. 어시스턴트 오류 — 이 측정에서 나온 것

### 1. 계측기 결함: `--limit` 이 기준선을 흔든다

`diag_action_noise_floor.py --limit 240` 으로 train 부분집합만 재자 identity 기준선이
바뀌었다.

```
240표본  identity trans 73.07 · rot 3.96
1021전수 identity trans 49.22 · rot 2.31
```

rot 판정 부호가 뒤집힐 정도의 차이다(부분집합 +27.2% → 전수 -9.9%).
**모수를 같이 찍은 덕에 잡혔다** (`데이터셋 표본 240 / 전체 1021`). 규칙이 작동했다.

**더 나쁜 것**: 결함을 찾아놓고 **같은 실행에서 나온 결론은 철회하지 않았다.**
"회전도 학습 데이터에선 identity 를 이긴다"를 그대로 보고했다가 전수 재측정에서 뒤집혔다.
→ **계측기 결함을 발견하면 그 계측기가 낸 판정도 같이 철회한다.**

### 2. 한 장의 스냅샷으로 "기동 실패" 단정

`nvidia-smi` 한 번에 GPU2 가 0 MiB 인 걸 보고 C_s2 가 안 떴다고 보고했다. 대기 루프
프로세스가 살아있는지 안 봤다. 실제로는 몇 분 뒤 정상 기동했다.
→ **"없다"를 말하기 전에 범위가 완전한지 본다.** 진행 중인 것은 한 시점으로 판정하지 않는다.

### 3. 엉뚱한 파일을 근거로 누수 경보 2회

`ds_real.split.json` (69편 기준 잔재)을 권위 있는 분할로 읽고 "기록과 적용이 다르다",
이어서 "진짜 누수일 수 있다"고 두 번 보고했다. 실제 권위 파일은
`ds_real_train.split.json` / `ds_real_holdout.split.json` 이고 누수는 없었다.
→ **같은 이름의 파일이 여러 개면 어느 것이 실제로 쓰였는지부터 확인한다.**

### 4. 예측 빗나감 2건 — 방향 기록

| 시점 | 예측 | 실제 | 방향 |
|---|---|---|---|
| K=8 진단 전 | mean_K 2도 이하 | 2.89 (train) | 오차 **과소**추정 (낙관) |
| K=32 진단 전 | mean_K 2.0~2.2 | **1.831** | 성능 **과소**추정 (비관) |

참조집단은 둘 다 "잡음분이 1/sqrt(K) 로 감쇠하는 모형"이었다. 같은 모형으로 두 번 예측해
한 번은 낙관, 한 번은 비관으로 빗나갔다 — **모형이 방향을 잡아주지 못한다.**
회전 채널 예측에는 이 참조집단을 다시 쓰지 않는다.

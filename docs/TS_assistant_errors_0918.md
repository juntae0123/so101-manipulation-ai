# TS — 2026-09-18 **전반부** · 어시스턴트 오류 11건과 그 모양

작성자: 김준태(트랙 B) · 기록 대상: **어시스턴트 자신의 오류**
"고쳤다"가 아니라 "어떻게 드러났나 / 무엇이 잡아줬나"를 적는다.

> **범위 정정 (2026-09-18 추가).** 이 문서는 0918 사이클 **전반부**
> (E2 folds · 실물 기하 · K 스윕 · `replay_trajectory`) 의 11건만 담는다.
> **후반부**(수집 선별 ~ 실데이터 첫 정책)의 18건은
> `TS_assistant_errors_0918_2.md` 에 있고 **이 11건과 겹치지 않는다.**
> 사이클 전체는 **29건**이다. 한쪽만 보고 "하루에 11건"이라 쓰지 마라.
>
> 초판 제목이 범위를 밝히지 않아, KPT 초판이 후반부 18건을 11건으로 적을 때
> 이 문서의 11 과 구분되지 않았다. **문서 제목에 범위를 적는다.**

하루 분량이 많다. 낱개로 세지 말고 **모양 5가지**로 묶는다.

## A. 잘린 범위·대표성 없는 표본을 전체로 읽음 — 5건

이 프로젝트에서 가장 자주 반복되는 모양이다. 기존 규칙
*"검색 0건이면 범위가 완전한지 먼저 본다"* 가 이미 있는데도 다섯 번 났다.

| # | 무엇 | 실제 | 무엇이 잡아줬나 |
|---|---|---|---|
| A1 | `grep` 결과 앞 40줄만 보고 "`set_torque` 가 없다" | **헤더에 있었다**. `.cpp` 만 보고 `.hpp` 를 안 봄 | 사용자가 "된다 했잖아" |
| A2 | "URDF 에 카메라 링크가 없다" | **다른 URDF**(`so101_phone_holder.urdf`)에 있었다 | 사용자가 폴더 공유 |
| A3 | `ds_real.split.json`(69편 잔재)을 권위 파일로 읽고 **누수 경보 2회** | 권위는 `ds_real_train/holdout.split.json`. 누수 없었다 | `provenance.json` 대조 |
| A4 | GPU 스냅샷 한 장으로 "C_s2 기동 실패" | 몇 분 뒤 정상 기동. 대기 프로세스를 안 봄 | 다음 스냅샷 |
| A5 | `training_ready:false` 2편에서 **카메라 각도 일반 결론** | 대충 찍은 테스트 녹화. 프로토콜 대표성 없음 | 사용자가 "대충 찍은 거다" |

**공통점**: 전부 **모수를 확인하지 않고** 결론을 냈다. 도구에는 모수를 찍게 해놓고
정작 내 추론에는 안 적용했다.

→ **추가 규칙**: "없다" 를 말하기 전에 **찾은 범위가 전체인지 한 줄로 명시한다.**
그리고 **진행 중인 것은 한 시점으로 판정하지 않는다.**

## B. 파생값·기억을 원본 대신 씀 — 2건

| # | 무엇 | 실제 |
|---|---|---|
| B1 | `err_A_s0.json` 이 epoch 22 짜리인 걸 **알면서** paired 비교에 씀 | `B-A -45.49mm` (정상은 -11.96). 시드 1·2 와 4배 차이로 드러남 |
| B2 | HW 구두값 `0.09 도/틱` 을 검산 없이 인용 → **66.42도** | 소스는 `TICKS_PER_TURN = 4096.0` → **64.86도**. 트랙 A 에 틀린 값을 전달함 |

B2 가 더 나쁘다. **틀린 값이 다른 트랙으로 흘러갔다.** 블렌더 간섭검사 +65도와
64.86 이 맞는 걸 보고서야 알았다 — 즉 교차검증이 원래 신호를 주고 있었는데 내가
66.42 를 기준으로 읽어서 "1.4도 차이"로 뭉갰다.

→ **추가 규칙**: **원시값(틱)과 소스의 환산식을 쓴다.** 남이 준 파생값은 검산 전까지
인용하지 않는다. 표에 옮겨 적은 숫자는 JSON 에서 다시 뽑아 대조한다.

## C. 계측기 결함을 찾고도 그 결론을 안 죽임 — 1건

`diag_action_noise_floor.py --limit 240` 으로 train 부분집합만 재자 identity 기준선이
`trans 73.07 / rot 3.96` → 전수 `49.22 / 2.31` 로 바뀌었다.

**결함을 내가 먼저 지적해놓고, 같은 실행에서 나온 판정("회전도 학습 데이터에선
identity 를 이긴다")은 그대로 보고했다.** 전수 재측정에서 부호가 뒤집혔다.

→ **추가 규칙**: **계측기 결함을 발견하면 그 계측기가 낸 판정도 같이 철회한다.**
결함과 결론을 분리해서 보고하지 않는다.

## E. 절차 생략 — 1건

실물을 구동하는 `replay_trajectory.py` 를 만들어놓고 *"팔 앞에서 5분이면 첫 숫자가
나온다"* 고 제시했다. **설치물 간섭·TCP/베이스 정렬·속도/가속도·비상정지 절차를
건너뛰려 했다.**

트랙 A(황도경)가 제기해 멈췄다:
> *"시뮬 전문가 관절궤적의 실물 직접 재생은 아직 승인된 시험이 아니다."*

→ **추가 규칙**: **실물을 움직이는 제안은 안전 절차 확인을 제안에 포함해 낸다.**
도구에 사전검사를 넣은 것과 절차를 밟는 것은 다른 문제다.

## 반대로, 규칙이 작동해서 잡힌 것 — 3건

기록의 균형을 위해 같이 적는다.

- **"모수를 같이 찍는다"** → `--limit` 결함이 `표본 240 / 전체 1021` 출력으로 드러났다
- **"부분합이 전체와 다르면 죽인다"** → 손목 회전만 셌으면 `wrist_flex` 위반 14~16% 를
  못 잡았다. 5관절 전수를 센 게 걸렸다
- **"계측기에 정답을 아는 행을 넣는다"** → `check_marker_scale.py` 가 검출 0건일 때
  조용히 넘어가지 않고 **"판정하지 않는다"로 멈췄다**

"잡음분이 1/sqrt(K) 로 감쇠하는 모형"으로 두 번 예측해 한 번은 낙관, 한 번은 비관으로
빗나갔다. **그 참조집단은 회전 채널 예측에 다시 쓰지 않는다.**

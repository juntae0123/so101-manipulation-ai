## 결론 한 줄

**사람이 폰으로 찍은 시연 70편 중 로봇이 끝까지 재현할 수 있는 것은 20편(29.2%)이다.
나머지 71%는 버려야 한다.**

기획서의 "범용 6축"과 실측 하드웨어 5자유도의 차이가 처음으로 숫자가 됐다.
프로젝트 문서에 몇 주째 *"UMI 궤적 재현 불가 폐기율이 이 값에 통째로 의존한다"* 로
열려 있던 항목이다.

## 1. 측정 결과

```
실 UMI 시연          70편 (2026-09-11 수집, Galaxy S23 + ARCore)
판정 가능 분모        65편  (너무 짧은 5편, 검증 불가 1편 제외)

에피소드 전체 재현 가능   19/65 = 29.2%   95% 신뢰구간 [19.6, 41.2]
웨이포인트 단위           811/1291 = 62.8%
8스텝 구간 단위           306/771 = 39.7%

실패 원인   위치를 못 맞춤   272건
            자세를 못 맞춤   208건   ← 5축 문제
```

**측정 조건** (이 조건 없이 숫자만 인용하지 마십시오)
- MuJoCo 3.13.0 시뮬레이터 안에서 SO-101 역기구학으로 판정
- 시연 시작 자세를 로봇 홈 자세에 맞추는 방식 (simulation-only 정렬)
- 허용 오차: 위치 8mm, 자세 5도
- 연속 궤적 검사 — 이전 관절해를 다음 웨이포인트의 시작점으로 사용

## 2. 왜 이런 일이 생기나

```
사람 손      6자유도로 움직인다  (위치 3 + 회전 3)
SO-101       관절 5개
```

자유도가 하나 모자라면 **임의의 위치와 자세를 동시에 만족시킬 수 없다.**
위치를 맞추면 손목 각도가 틀어지고, 각도를 맞추면 위치가 어긋난다.

소프트웨어로 해결되는 문제가 아닙니다. 캘리브레이션 오차도 아닙니다.
**팔의 구조에서 오는 기하학적 한계입니다.**

## 3. 이게 수집 계획에 미치는 영향

현재 계획: 스킬 5종 × 150편 = 750편

```
폐기율 71% 반영 시  실제로 찍어야 하는 양 ≈ 2,570편
                    (750 ÷ 0.292)
```

⚠️ 신뢰구간 하한(19.6%)으로 잡으면 **3,800편**, 상한(41.2%)으로 잡으면 **1,820편**입니다.
편차가 큽니다. 아래 4-2 의 추가 계측으로 좁힐 수 있습니다.

## 4. 확정된 것과 아닌 것

### 확정 🟢
- 이 정렬 방식·이 허용오차에서 65편 중 19편만 완주 가능
- 실패의 43%가 **자세 불일치**다 (208/480)

### 미확정 ⚠️ — 숫자가 움직일 수 있는 여지
1. **정렬 방식에 따라 달라진다.** 이번엔 "시연 시작점 = 로봇 홈" 한 가지만 썼습니다
   (결과를 보기 전에 정해둔 방식입니다). 파지 순간을 기준으로 맞추면 달라질 수 있습니다
2. **허용 오차를 어디까지 볼지** — 자세 5도는 저희가 정한 값입니다.
   실제로 작업이 성공하는 데 몇 도까지 허용되는지는 측정된 바 없습니다
3. **SO-101 실제 관절 속도 한계 미측정** — 별개 항목이지만, 사람 손이
   시뮬 스크립트보다 중앙값 15배 빠릅니다. 재현하려면 느리게 재생해야 합니다

**단, 자세 불일치는 정렬을 바꿔도 완전히 사라지지 않습니다.** 5축이 6자유도 궤적을
따라갈 수 없다는 것은 기하학이기 때문입니다.

## 5. 결정이 필요한 사항

### (가) 팔을 6축으로 갈 것인가 — HW·PM

6축이면 이 폐기율 대부분이 사라집니다. 대신 비용·조립 일정·페이로드가 바뀝니다.
**이미 부품을 발주했거나 조립이 진행 중이면 지금이 되돌릴 수 있는 마지막 시점일 수 있습니다.**

### (나) 5축으로 간다면 — PM

수집 계획을 **3.4배**로 다시 잡아야 합니다. 또는 스킬 수나 스킬당 편수를 줄여야 합니다.
전시(FLY ASIA)까지 남은 기간에 2,500편 수집이 가능한지가 판단 기준입니다.

### (다) 대안 — 시연 방식을 로봇에 맞춘다

사람에게 "로봇이 따라 할 수 있게" 시연하도록 제약을 주는 방법입니다.
손목을 과하게 꺾지 않기, 접근 방향 고정 등. 폐기율은 내려가지만
**"사람이 편하게 시연하면 로봇이 배운다"는 제품 컨셉이 약해집니다.**
이건 제품 결정이라 PM 판단입니다.

## 6. 확인 요청 (AI 파트가 모르는 것)

1. **현재 팔이 확정입니까?** 프로젝트 문서에는 "로봇팔은 변형 예정"으로 돼 있습니다
2. **6축 옵션의 비용·리드타임**은 얼마입니까
3. **수집 인력·시간**으로 2,500편이 가능한 규모입니까

## 7. AI 파트가 다음에 할 계측 (원인 귀속)

지금 숫자는 "5축 때문"이라는 **해석**이 붙어 있습니다. 그 해석을 직접 검증합니다.

**자세 허용 오차를 5도 → 20도로 풀고 같은 검사를 다시 돌립니다.**
- 수용률이 크게 오르면 → 원인은 자유도(자세)입니다. (가) 판단의 근거가 확실해집니다
- 거의 안 오르면 → 원인은 도달 범위이고, 6축으로 바꿔도 크게 안 나아집니다

**1시간이면 나옵니다. (가)를 결정하기 전에 이 결과를 기다려 주십시오.**

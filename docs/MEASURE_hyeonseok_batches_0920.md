## 0. 먼저 — "atlas A/B" 는 존재하지 않는다 🟢

`runs/s22_pick_v3_e120` 와 `runs/s22_pick_v3_atlas_v1_e120` 은 이름만 다르고
**같은 데이터로 학습했다.**

```
review_v1.zarr.zip                sha256 3ada1f84… 318901383 B
s22_pick_v3_atlas_v1.zarr.zip     sha256 0e02c735… 318901383 B
```

sha256 이 다르지만 **내용은 같다.** zip 헤더가 mtime 을 담으므로 재압축만 해도
해시가 바뀐다. 배열로 대조한 결과:

```
robot0_eef_pos / rot_axis_angle / gripper_width / episode_ends   동일 4 / 전체 4
camera0_rgb                       표본 동일 50 / 표본 50 (전체 3475 프레임)
```

`config.yaml` diff 도 이름·경로 4곳뿐이고 하이퍼파라미터는 완전히 동일하다.
report 11개 항목 중 9개 일치 — 불일치는 경로와 `dataset_sha256` 뿐이고
`config_sha256` 은 동일하다.

→ **train_loss 가 둘 다 0.022 인 것은 우연이 아니라 같은 실험이기 때문이다.**
→ atlas 효과를 재려면 atlas 를 안 쓴 데이터가 따로 있어야 한다. 현재 없다.

**미확정**: `review_v1` 자체가 이미 atlas 산출물인지, 아니면 atlas 결과가 학습에
전혀 안 들어갔는지는 이 자료만으로 갈리지 않는다. `incoming/` 내용 확인 필요.

⚠️ 어시스턴트 오류: 파일 크기와 run 이름만 보고 "현석이 A/B 를 돌렸다"고 먼저 말했다.
   해시 차이를 내용 차이로 읽을 뻔했다. 배열 대조로 정정했다.

## 2. 읽히는 것

**시연이 정제됐다.** 이동거리 1.416 → 0.371 m (3.8배), 편 길이 7.2 → 3.3 초.
같은 물체를 집는데 손을 훨씬 덜 휘젓는다. "환경은 다양하게, 시연 방식은 동일하게"에
맞는 방향이다.

**y 축이 거의 고정이다 (폭 59mm).** 한 방향에서만 접근한다. 회전 크기 폭도 0.127 rad
(7.3도)로 v4의 4분의 1이다. **5자유도 SO-101 에 유리한 조건이다** — 자세 자유도 요구가
줄어든다. 다만 일반화 범위도 같이 줄어든다. 5스킬 확장 시 재확인 필요.

**결측 0.** 두 배치 모두 NaN/Inf 행이 하나도 없다.

  정렬 없이 IK 에 넣으면 안 된다.** 어댑터 미작성
- 30.0021Hz 원본이다. 우리 파이프라인은 표본 10Hz — 다운샘플 규약 대조 미실행

  라고만 있고 값이 없다. hand-eye 는 상수 편향이라 학습이 못 지운다 — 현석한테 받아야 한다

## D-AI-56 · wrist_roll 실효 가동범위를 +64.86도로 확정

**작성자**: 김준태(트랙 B) · **상태**: 확정 (실물 확인됨)

```
URDF / ros2_control   [-2.743847297, +2.841206309] rad = [-157.21도, +162.79도]
실효 (브래킷)          [-2.743847297, +1.132086   ] rad = [-157.21도, **+64.86도**]
```

### 근거 4종이 같은 값을 가리킨다

| 출처 | 값 |
|---|---|
| HW 실측 (김현석) | 물리 정지 **2864틱**. `zero_tick` 2126 → 738틱 |
| 환산 (`so101_system.hpp` 원문) | `TICKS_PER_TURN = 4096.0` → 738 x 360/4096 = **64.863281도** |
| 블렌더 간섭검사 (`handoff/validation/KNOWN_LIMITATIONS.md`) | L_bracket_v010 이 URDF **+65도**부터 교차 |
| 방향 검증 (`BACKEND_INTERFACE.md`) | wrist_roll `direction +1`, 틱 증가 = URDF 양각 |

**64.86 과 65 가 0.14도 차이로 맞는다.** 물리 정지와 간섭 시작이 사실상 같은 지점이다.

⚠️ **정정 기록**: 2026-09-18 오후에 이 값을 **66.42도**로 공유했다(트랙 A 포함).
HW 가 구두로 준 `0.09 도/틱`을 검산 없이 인용한 결과다. 소스의 실제 환산은
`0.087890625 도/틱` 이다. **남이 준 파생값 대신 원시 틱과 소스 환산식을 쓴다.**

폰 홀더 자체의 간섭(+90~105도, +124~142도)은 브래킷이 먼저 막아 **도달하지 않는다.**
검사표와 앞뒤가 맞는다.

### 우리 정책에 미치는 영향 — 없다 🟢

```
T1 (can_side) 20편   wrist_roll [-0.48, +0.36]도   위반 0/1196 스텝
T2 (can_left) 20편   wrist_roll [-0.73, +8.81]도   위반 0/1336 스텝
```

**E1 97.0% · E3 96.0% 는 그대로 유효하다. 재학습 없음.**
시뮬 config 에 이 제약을 박지 않는다 — 정책이 안 쓰므로 효과가 0이고,
안 쓰는 제약을 박으면 브래킷 수정 시 되돌릴 것만 늘어난다.

⚠️ **재측정 조건**: 대상물이 **원통이 아닌 것**으로 바뀌면 이 결론은 무효다.
can 은 yaw 가 무의미해서 손목을 안 돌린다. 케이스 같은 직육면체는 파지축 정렬이
필요해 손목을 쓸 수 있다.

### 되돌릴 조건
브래킷 수정(HW, 다음 주 예정) 후 간섭 재검사 결과가 오면 갱신한다.
트랙 A 는 현재 오프라인 IK 에 **잠정 +60도** 적용 중(황도경). 근거값만 64.86 으로 맞춘다.

### 성격 — 하드웨어 결함이 아니다
원본 SO-101 은 wrist_roll 전 범위를 쓴다. ver1 그리퍼와 폰 홀더를 얹으면서 줄어든
**설계 트레이드오프**다. "SO-101 이 66도밖에 못 돈다"로 적으면 틀린 기술이다.

## D-AI-57 · 그리퍼 사양 확정, 기획서 기재 폐기

```
gripper = 좌우 접촉면 사이 전체 간격.  범위 0 ~ 90 mm
```

| 출처 | 내용 |
|---|---|

| 시연 리그 | 스프링 상시 개방 90mm, 방아쇠로 닫음 (사용자 확인) |

### 폐기

> ~~기획서: "그리퍼 닫힘 간격 약 1.7cm → 대상물 1.5~2.5cm"~~

**완전 닫힘은 0mm 다.** "대상물 1.5~2.5cm" 는 근거 없는 좁힘이었다.
트랙 A 실측 케이스 폭 **40mm** 는 정상 범위 안이고, 트랙 B 의 닫힘 순간 gap 중앙
**38.5mm** [32.4, 43.5] (n=69) 와도 맞는다.

### 부수 효과 — 파지 여유

```
횡방향 허용 오차 = (개구 90 - 물체 40) / 2 = +-25 mm
```
이 값이 카메라 마운트 정밀도·정책 위치 정확도의 기준선이 된다.

### 되돌릴 조건
패드 교체나 핑거 형상 변경 시 재측정. `MODELING_SPEC` 도 "핑거/패드 변경 시
실제 접촉 기준점과 일치하는지 재검토한다"고 적고 있다.

## D-AI-58 · 실물 복구에 따른 평가 전환

**작성자**: 김준태(트랙 B) · **상태**: 확정 · **트랙 A 조건 반영됨**

### 사실
**2026-09-18 실물 로봇팔 모터 교체 완료 · 정상 동작 확인.**
D-AI-52 의 되돌릴 조건(*"실물 로봇팔이 복구되면 롤아웃 기반 재측정으로 대체한다"*)이
발동했다. 프로젝트 지침의 *"실물 평가 불가"* 전제는 더 이상 유효하지 않다.

### 갭 측정 사다리 — 한 단계가 갭의 한 원인만 격리한다

| | 내용 | 로봇 구동 | 상태 |
|---|---|---|---|
| **0** | 기하 검증 (손목·그리퍼·포락선·통신) | 손으로만 | **완료 · 4/4 일치** |
| **1a** | 궤적 재생, 물체 없이 → 관절 추종 오차 | **있음** | 승인 대기 |
| **1b** | 궤적 재생, 물체 있음 → 파지 성공률 | **있음** | 승인 대기 |
| **2** | 같은 장면 실물/시뮬 이미지로 액션 비교 | 없음 | 가능 |
| **3** | 폐루프 롤아웃 | **있음** | 어댑터 대기 |

### ⚠️ 1a·1b 착수 조건 (트랙 A 황도경 제기, 수용)

> *"시뮬 전문가 관절궤적의 실물 직접 재생은 아직 승인된 시험이 아니다.
> 설치물 간섭과 TCP·베이스 정렬, 관절 속도·가속도, 비상정지 절차를 HW와 확인한 뒤
> 감독하에 진행해야 한다."*

**전부 확인되기 전에는 `--read-only` 외의 사용을 하지 않는다.**
도구(`AI/tools/replay_trajectory.py`)는 준비됐고 관절·브래킷 한계 사전검사 후
하나라도 걸리면 한 스텝도 움직이지 않는다. 그래도 절차가 먼저다.

### wrist_flex — 원상 유지 요청

HW 가 `+-90도` 제한을 걸려 했으나 확인 결과 **물리 간섭이 아니라 안전 마진**이었다.

```
정책 실측   T1 [-94.97, +18.29]도   1196스텝 중 176개(14.7%)가 -90도 밖
            T2 [-96.02, +18.47]도   1336스텝 중 215개(16.1%)가 -90도 밖
URDF 한계   +-94.99도 — 정책이 하한에 0.02도까지 붙어 **포화**해 있다
```

**URDF 값(+-94.99도) 유지를 HW 에 요청했다.** 5도를 깎으면 측면 파지 자세가 잘린다.
→ **E1·E3 재학습 취소.** (조였을 경우 학습 2h36m x3 + 평가가 들었을 것)

# MEASURE — `episode_start_trim_s` 기본값이 파지 순간을 지운다 (2026-09-21)

작성 김준태 (트랙 B) · 계측기 `AI/tools/audit_umi_zarr.py` (자체검증 12/12)
산출물 `out/sample10/zarr_gate.json` (기본값) · `zarr_gate_trim0.json` (trim 0.0)

## 무엇이 일어났나 🟢

02 빌더의 `configs/dataset.json` 기본값이 `episode_start_trim_s: 3.0` 이다.
`--dataset-config` 를 주지 않고 `build` 를 돌리면 **편마다 앞 3초(30Hz 에서 90프레임)가
잘린다.** 그 결과 파지 순간이 사라져 **닫힘이 한 편도 관측되지 않았다.**

현석 배치들은 전부 `episode_start_trim_s: 0.0` 이었다 (v4 · s22_pick_v3 · 20260921 report).

## 프레임 수로 확정

```
raw 10편 합계   249+241+248+249+254+232+247+245+230+172 = 2367
기본값 빌드                                               1467
차이                                                       900 = 90 × 10편
90 프레임 / 30 Hz                                          3.0 초
```

정확히 일치한다. 추측이 아니다.

## 같은 10편, config 만 바꾼 비교 🟢

| | 기본값 (trim 3.0) | **trim 0.0** |
|---|---|---|
| 프레임 | 1467 | **2367** |
| 편 길이 중앙 | 156 | 246 |
| **파지 닫힘 채점** | **0 / 10편** | **10 / 10편** |
| 파지 개구 중앙 | 산출 불가 | **40.3 mm** |
| 개구 p10–p90 폭 | 산출 불가 | **0.78 mm** |
| 게이트 | 통과 4 · 불합격 4 · **미판정 1** | 통과 4 · 불합격 5 · 미판정 0 |

개구 폭 0.78mm 는 현석 v4(1.55mm) · s22_pick_v3(1.4mm) 보다 좁다.

## 왜 위험했나

닫힘이 0편이어도 **빌드는 `status: pass` 로 끝난다.** 학습도 돈다. 그 데이터로 학습한
정책은 파지 순간을 한 번도 본 적이 없는데, 그 사실이 어떤 오류 메시지로도 안 나온다.

**우리 감사기가 `파지 닫힘 채점률 0 / 10` 과 `미판정 1` 로 잡았다.** 게이트가 없었으면
내일 찍은 20편이 전부 같은 상태로 학습에 들어갔을 것이다.

## 어시스턴트 오류

`build_dataset.py build` 에 `--dataset-config` 를 주지 않고 **기본값에 의존했다.**
이 프로젝트가 명시한 함정 — *"설정 기본값이 '당연히 된다'고 가정하지 않는다.
`env.py` 기본값으로 config 를 써서 0/60 을 받았다"* — 과 같은 모양이다.

부수 오류: `build <plan> <output>` 의 `output` 은 **최종 파일명 그대로**다.
`.zarr.zip` 이 자동으로 붙지 않는다. `ds_sample10` 을 주고 `ds_sample10.zarr.zip` 이
나올 거라 가정해서 노트북 7번 셀이 `FileNotFoundError` 로 죽었다.
`rc == 0` 만 보고 산출 파일 존재를 확인하지 않은 것도 같은 결함이다.

## 조치

- 노트북 0번 셀에 `DATASET_CFG` 를 두고 **`trim 0.0` 을 명시**한다. 기본값에 의존하지 않는다
- 6번 셀의 `ZARR` 은 `.zarr.zip` 까지 포함한 전체 경로로 준다
- 6번 셀 `assert` 에 **산출 파일 존재**를 넣는다. `rc == 0` 만으로는 오늘 같은 통과가 난다

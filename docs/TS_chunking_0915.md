## 1. 사전등록 게이트 판정

| 게이트 | 기준 | 결과 |
|---|---|---|
| G0 계측기 검증 | `chunk=1` 이 기존 BC 와 일치 | **조건부 통과** (아래 3절) |
| G1 청킹 효과 | `chunk8` 하한 > 대조군 상한 11.6% | **미달** — 하한 9.9% |
| G2 배포 게이트 | 하한 ≥ 20% | **미달** |
| G4 이미지 어블레이션 | 노이즈 상한 < 조건 하한 | **통과** — 완전 분리 |
| G5 궤적타깃 이미지 | 〃 | **통과** — 완전 분리 |
| G6 최적 K | K 별 최대점 존재 | **없음** — 2/4/8/16 전부 구간 중첩 |

**게이트를 옮기지 않았다.** G1 은 9.9% vs 11.6% 로 1.7%p 차이지만, 겹치면 주장하지
않는다는 규칙이 이런 자리에 있는 것이다.

## 2. 무엇이 확정됐나

**청킹은 처방이 아니다** 🟢 — 8.0% → 13.3% 는 구간이 겹친다. 그리고 K 를 2에서 16까지
훑어도 전부 겹친다. 되먹임 고리를 끊는 것이 이 태스크의 병목이 아니었다.

**정책은 이미지를 실제로 쓴다** 🟢 — 이것이 오늘 유일하게 강한 결과다.

```
chunk8 command   13.3% [9.9, 17.6]  vs  이미지파괴 0.0% [0.0, 1.3]
chunk8 궤적      9.7% [6.8, 13.5]   vs  이미지파괴 0.0% [0.0, 1.3]
```

**궤적 타깃(트랙 A v6 대리)도 이미지를 쓴다.** 내 예측은 "궤적 타깃은 외삽으로 풀리니
이미지 어블레이션에 안 무너진다"였고 **틀렸다.** v6 전제가 이 축에서는 문제없다.

## 3. G0 이 비트 동일이 아니었던 이유

`chunk=1` 이 11/2/11 = 24/300, 기존 BC 는 13/1/8 = 22/300. 비트 동일이 아니다.

원인은 청킹이 아니라 **같은 날 내가 고친 별개 버그**다 — `TargetTransform.to()` 가
`grip_mid` 를 버려서, `--device cuda` 학습이 데이터 파생 그리퍼 임계값 대신 시뮬 설정
파생값을 쓰고 있었다. 그 수정이 이진 라벨 경계를 바꿨다.

⚠️ **따라서 `command` 정본 수치 9.3% [7.3, 11.9] n=600 은 그 버그가 있던 코드로 낸
값이다.** 지금 코드 기준 대조군은 **8.0% [5.4, 11.6] n=300** 이고, 앞으로 이것을 쓴다.
구간이 겹치므로 결론은 바뀌지 않는다.

## 4. 계측기 사고 — val_loss 가 조건 간에 섞였다 🔴

합산표의 val 열이 조건마다 소수점 5자리까지 같게 나왔다.

```
chunk8_cmd   3.10246 / 1.49944 / 6.48092
chunk4_cmd   3.10246 / 1.49944 / 6.48092     ← 동일
```

원인:

```python
# eval/repeat.py (수정 전)
train = _latest_record("train_bc", {"trained_on": str(data), "seed": seed})
```

**체크포인트를 보지 않고 (데이터, 시드) 로만 찾는다.** 8잡을 같은 데이터·같은 시드로
병렬 실행하자 서로의 학습 기록을 집어갔다.

**성공률은 오염되지 않았다** — 롤아웃 기록은 원래 `{"policy_ckpt": str(ckpt)}` 로
찾고 있었고, 체크포인트 이름에 tag 가 들어가 조건마다 유일하다.

수정: `train_bc` 기록에 `out`(체크포인트 경로)·`chunk` 를 넣고, `repeat.py` 가
`{"out": str(ckpt)}` 로 찾게 했다.

⚠️ **이 실행의 val 열과 "자명한 예측기 수준" 🔴 표시는 전부 무효다.** 그리고 합산기
(`pool_rollouts.py`)의 붕괴 판정 기준(2.55132)은 `chunk=1` 전용이다 — `chunk=K` 는
손실이 K 스텝에 걸쳐 계산돼 스케일이 다르다. 그것도 고쳐야 한다.

## 5. 이 건에서 내가 낸 버그 — 전부 같은 종류

| # | 버그 | 대가 |
|---|---|---|
| 1 | `--target-sidecar` 를 `repeat_runs` 에 안 뚫음 | 잡 즉사 |
| 2 | `--chunk` 를 `repeat_runs` 에 안 뚫음 | 잡 즉사 |
| 3 | `run_queue` 에 `--tag` 중복 추가 | 내가 잡음 |
| 4 | 독스트링 미종료 | 문법 오류 |
| 5 | **`ACTPolicy.name` 을 "act" 로** | **8잡 사망** |
| 6 | 스모크가 `rc=1`(게이트 실패)을 오류로 판정 | 캠페인 1회 무산 |
| 7 | 캠페인 마지막 줄이 `out/logs` 를 봄 (큐는 `out/queue_*`) | 결과가 합산에 안 잡힘 |

**전부 "새 걸 만들고 그걸 쓰는 쪽을 안 봤다"이다.** 5번이 대표적이다 —
`eval/rollout.py` 가 `success_rates["bc"]` 로 **배포 게이트·실패모양·클립통계**를
찾는데 이름을 바꿔서 전부 끊겼다. `repeat.py` 가 `KeyError` 로 죽어준 게 운이 좋았다.
안 죽었으면 **게이트를 조용히 건너뛰고 수치만 나왔을 것이다.**

**조치** — 캠페인 맨 앞에 관통 스모크를 넣었다. 학습→체크포인트→롤아웃→성공률 파싱까지
1시드 × 2편으로 2분에 통과시킨다. 5번을 정확히 잡았을 단계다. 기억이 아니라 스크립트가
강제한다.

## 6. 남는 것

**BC 계열에서 모델로 할 수 있는 것이 끝났다.** 처방 목록이 소진됐다.

```
제어주기 다운샘플 (30->10Hz)   기각
물체 위치 변주 확대            기각
액션 타깃 리드 state[t+k]      기각
행동 청킹 K=2/4/8/16           기각   ← 오늘
액션 정의 ctrl                 효과 있음 (0% -> 8~13%). 게이트는 미달
```

다음은 데이터다. 근거:

```
scripted (정답 위치 사용)   84%     태스크 자체는 풀린다
학습 정책 최고              13.3%   이미지로 위치를 추정하는 비용이 70%p
DAgger 손목전용             51.4% [47.0, 55.8] n=500 🟢
```

**같은 씬·같은 카메라 1대인데 13.3% 와 51.4% 다. 차이는 수집 방식뿐이다.**
스크립트 시연 59편으로 20% 를 넘기려는 것이 무리라는 가설이 남는다.

⚠️ 단 DAgger 데이터는 계약 0.2.0 이라 현행 로더가 거부한다. 0.3.0 + `command`
사이드카로 **재수집**이 필요한지부터 확인해야 한다.

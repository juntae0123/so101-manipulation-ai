## 1. 시드 누설 검사 — 가장 비쌌을 뻔한 건

### 증상

DAgger 혼합 조건에서 63.7% 가 나왔다. 어제 천장이 13.3% 였다.
너무 좋아서 누설을 의심했고, 제일 무서운 경로는 **DAgger 세그먼트를 평가에 쓸
초기 상태에서 수집한 것** 이었다. 그러면 정책이 그 시드를 외운다.

```python
vs = [k.get('behavior_seed') for k in eps]
vs = [v for v in vs if v is not None]
print('평가시드 교집합:', sorted(set(vs) & set(range(3000, 3100))))
```

```
behavior_seed n=0 필드없음
평가시드 3000~3099 교집합: []
```

**교집합이 비어 있었다. 그런데 통과가 아니다.**

### 왜 통과가 아닌가

`behavior_seed` 는 그 위치에 없었다. 빈 리스트와의 교집합은 당연히 빈 집합이다.

```
분리되어 있어서 빈 교집합   <-- 통과
읽을 게 없어서 빈 교집합    <-- 미검사
```

`n=0 필드없음` 을 같이 찍게 해둔 것이 유일한 단서였다.
그게 없었으면 **"시드 분리 확인됨" 으로 넘어가고 63.7% 를 게이트 통과로 발표했을 것이다.**

### 어떻게 좁혔나

1. 출력에 `n=0` 이 있었다 → 교집합이 아니라 **입력** 을 의심
2. 수집기 소스(`tools/collect_dagger_segments.py` 217~228행)를 열었다
3. `behavior_seed` 는 `EpisodeMeta.notes` **안쪽** 이었다. 최상위 키가 아니다
4. 경로를 고치고, **찾은 개수를 전체 편수와 대조하도록** 바꿨다

```python
vs = [k['notes']['behavior_seed'] for k in eps if 'behavior_seed' in k.get('notes', {})]
print('찾음 %d / 전체 %d  (같아야 한다)' % (len(vs), len(eps)))
```

결과: `찾음 120 / 전체 122`, 시드 4000~4059, 평가·학습 시드와 공집합. **분리 확인 🟢.**
덤으로 json 2건이 npz 없이 떠 있는 것도 드러났다.

큐 진행 표시 스크립트가 **전 조건을 즉시 "완료"** 로 표시했다. 실제로는 1/3 이었다.

`grep` 이 매칭됐다는 것은 그 줄이 있었다는 뜻이지 그 **의미** 였다는 뜻이 아니다.

## 3. `grep -c` 를 `&&` 사슬에 넣었다

```bash
ls ... && grep -c "패턴" 로그 && tail -12 로그 && python -c "..."
```

`grep -c` 는 0건이면 **종료코드 1** 이다. 0 을 출력하고 사슬이 거기서 끊겨
뒤의 `tail` 과 `python` 이 통째로 안 돌았다. 화면에는 `0` 만 남는다.

"결과 없음" 이 정상인 명령을 게이트로 쓴 것이다. 1번과 같은 병이다.

**교훈**: 진단 명령은 `;` 로 잇는다. `&&` 는 **실패 시 뒤를 막아야 할 때만** 쓴다.

## 4. `data/collect.py` 요약 — 폐기 경로 둘, 카운터 하나

전문가 136편을 수집했는데 133편이 저장됐다. 요약은 이랬다.

```
에피소드 133개 저장 (도달불가로 건너뜀 1개)
```

136 - 1 = 135 여야 하는데 133 이다. **2편이 설명되지 않는다.**

소스를 보니 버리는 경로가 둘이었다.

```python
if got is None:
    skipped += 1                    # 카운터 있음 -> 요약에 나옴
    print("SKIP  도달 불가")
    continue
problems = validate(ep)
if problems:
    print(f"INVALID: {problems}")   # ⚠️ 카운터 없음 -> 요약에 안 나옴
    continue
```

로그에는 찍혀 있었다:

```
[ 67/136] INVALID: ['state out of (-1.0, 1.0): min=-0.8182 max=1.0016', ...]
[ 86/136] INVALID: ['state out of (-1.0, 1.0): min=-0.8182 max=1.0010', ...]
```

계약 범위를 1.0016 / 1.0010 으로 초과했다 (RANGE_TOLERANCE 1e-4 의 10~16배).
**버려야 할 편이 맞다.** 계약 검증은 제 일을 했다. 문제는 요약이 그걸 안 센 것뿐이다.

⚠️ 여기서 **내 grep 도 부실했다.** 패턴이 `건너|실패|X |✗|skip` 이라 소문자
`skip` 만 잡고 `SKIP`·`INVALID` 를 놓쳤다. 답이 이미 로그에 있었는데 못 찾았다.
계측기를 고치러 가서 계측기로 또 놓친 셈이다.

### 조치

```python
print(f"시도 {args.episodes} = 저장 {len(written)} + 도달불가 {skipped} + 계약위반 {invalid}")
accounted = len(written) + skipped + invalid
if accounted != args.episodes:
    print("!! 합이 안 맞는다 ... 집계되지 않는 폐기 경로가 있다")
    raise SystemExit(4)
```

**합을 사람이 눈으로 검산하게 두지 않는다.** 폐기 경로가 하나 더 생기면
그날 바로 죽는다.

## 5. 규칙 — 네 건에서 나온 하나

> **"없음" 과 "괜찮음" 이 같은 모양으로 나오는 검사는 검사가 아니다.**

집합 연산·필터·`get()` 기본값·`grep` 카운트가 전부 이 성질을 가진다.
빈 입력이 들어오면 조용히 "문제 없음" 을 출력한다.

### 지켜야 할 것

1. **모든 집계에 모수를 같이 찍는다**
   ```
   나쁨   print('교집합:', a & b)
   좋음   print('찾음 %d / 전체 %d' % (len(a), len(all)));  print('교집합:', a & b)
   ```
2. **부분합이 전체와 다르면 죽인다.** 경고 출력이 아니라 종료코드
3. **종료 신호 문자열은 다른 맥락에서 나오는지 먼저 확인한다**
4. **진단 명령은 `;` 로 잇는다.** `&&` 는 뒤를 막아야 할 때만
5. **`grep` 패턴은 대소문자를 먼저 의심한다.** 못 찾은 것과 없는 것은 다르다

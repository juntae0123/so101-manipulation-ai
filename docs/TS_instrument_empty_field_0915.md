## 증상

DAgger 혼합 조건에서 63.7% 가 나왔다. 어제 천장이 13.3% 였다.
너무 좋아서 누설을 의심했고, 제일 무서운 경로는 **DAgger 세그먼트를 평가에 쓸
초기 상태에서 수집한 것**이었다. 그러면 정책이 그 시드를 외운다.

검사 명령을 냈다.

```python
vs = [k.get('behavior_seed') for k in eps]
vs = [v for v in vs if v is not None]
print('평가시드 교집합:', sorted(set(vs) & set(range(3000, 3100))))
```

출력:

```
behavior_seed n=0 필드없음
평가시드 3000~3099 교집합: []
```

**교집합이 비어 있었다.** 그런데 통과가 아니다.

## 왜 통과가 아닌가

`behavior_seed` 는 그 위치에 없었다. `n=0` 이다.
빈 리스트와 3000~3099 의 교집합은 당연히 빈 집합이다.

```
분리되어 있어서 빈 교집합   <-- 통과
읽을 게 없어서 빈 교집합    <-- 미검사
```

**이 둘이 같은 출력을 낸다.** 출력만 보면 구분이 안 된다.
`n=0 필드없음` 을 같이 찍게 해둔 것이 유일한 단서였고, 그게 없었으면
"시드 분리 확인됨" 으로 넘어갔을 것이다.

## 어떻게 좁혔나

1. 출력에 `n=0` 이 있었다 → 교집합이 아니라 **입력**을 의심
2. 수집기 소스(`tools/collect_dagger_segments.py` 217~228행)를 열었다
3. `behavior_seed` 는 `EpisodeMeta.notes` **안쪽**에 있었다. 최상위 키가 아니다
4. 경로를 고치고, **찾은 개수를 전체 편수와 대조하도록** 검사를 바꿨다

```python
vs = [k['notes']['behavior_seed'] for k in eps if 'behavior_seed' in k.get('notes', {})]
print('찾음 %d / 전체 %d  (같아야 한다)' % (len(vs), len(eps)))
```

결과: `찾음 120 / 전체 122`, 시드 4000~4059, 평가·학습 시드와 공집합.
**분리 확인 🟢.** 덤으로 json 2건이 npz 없이 떠 있는 것도 드러났다.

## 교훈 — 프로젝트 원칙의 구체형

> 계측기를 쓰기 전에 계측기를 검증한다. 고장난 계측기는 스스로 알리지 않는다.

이번 건의 구체형은 이렇다.

**"없음" 과 "괜찮음" 이 같은 모양으로 나오는 검사는 검사가 아니다.**

집합 연산·필터·`get()` 기본값이 전부 이 성질을 가진다.
빈 입력이 들어오면 조용히 "문제 없음" 을 출력한다.

### 규칙

모든 존재 검사에 **모수를 같이 찍는다.**

```
나쁨   print('교집합:', a & b)
좋음   print('찾음 %d / 전체 %d' % (len(a), len(all)));  print('교집합:', a & b)
```

찾은 개수가 전체와 다르면 그 자리에서 눈에 띈다.

### 어디에 더 있나 (점검 대상)

- `pool_rollouts.py` — 정규식이 로그에서 `자명한 예측기` 를 못 찾으면 `nan` 이 되고
  붕괴 검사가 조용히 통과한다. **현재 `nan` 은 표에 표시되므로 드러난다.** 유지
- `run_queue.py --dry-run` — yaml 키 오타는 무시되고 인자가 그냥 안 붙는다.
  0915 오전에 `--chunk` 누락으로 8잡이 죽은 것이 같은 계열이다
- 데이터셋 로더 — 사이드카가 없으면 계약 `action` 으로 **조용히** 되돌아간다.
  이번에 `사이드카 수 == npz 수` 를 먼저 확인한 이유다

# PREREG — M0: 파인튜닝 없는 베이스 VLM 스킬 선택 2026-09-12

작성자: 김준태(트랙B) · 이슈 S15P21A103-36, S15P21A103-112
도구: `tools/probe_vlm_m0.py` · `vlm/skill_choice.py`
관련 결정: **D-AI-17**(게이트 정본) · **D-AI-22**(스킬 5종) · **D-AI-24**(출력 형식)

## 왜 지금

VLM 은 0901 이후 멈춰 있다. 해놓은 것은 fp16 안전성 하나뿐이다 🟢
(Qwen2.5-VL-3B argmax 0.9909 / SmolVLM2-500M 0.9961, 둘 다 통과).

D-AI-17 이 **LoRA 착수 전에 M0 를 재라고 못박았다.** 안 재고 파인튜닝을 돌리면
성능이 나와도 파인튜닝 덕인지 사전학습 덕인지 가릴 수 없다 — BC→ACT 규칙과 같은 논리다.
**M0 는 아직 한 번도 안 돌았다.** 이슈 112 가 여기서 막혀 있다.

## 게이트 — 새로 만들지 않는다. D-AI-17 에 이미 있다

```
n=100 · 5지선다 · 우연 = 0.20

>= 0.90        파인튜닝 취소. 자원을 grounding 정확도로 돌린다
0.50 ~ 0.90    LoRA 필요. 시뮬 렌더 데이터셋 진행
<  0.50        모델 후보 재검토
```

이 숫자는 2026-09-01 에 결과 없이 확정됐다. **결과를 보고 옮기지 않는다.**
정밀도가 부족하면 게이트가 아니라 n 을 올린다.

## 무엇을 재는가 — 두 개를 따로 잰다

섞으면 어느 쪽이 고장인지 모른다.

| | 무엇 | 어디에 쓰나 |
|---|---|---|
| **강제선택 정확도** | 후보 5개를 각각 답으로 붙여 **답 토큰만의 평균 로그확률** → argmax | **D-AI-17 게이트 판정은 이 수치로 한다** |
| **자유생성 형식 준수율** | JSON 을 내게 하고 파싱 성공·enum 준수·기권 사용을 센다 | D-AI-24(enum 제약 + 기권 게이트)가 실제로 필요한지 |

**평균(합계 아님) 로그확률로 고르는 규칙은 결과 보기 전에 정했다.** 후보마다 토큰 수가
달라 합계를 쓰면 짧은 이름이 유리해진다.

강제선택을 게이트로 쓰는 이유: 형식 실패가 정확도를 오염시키지 않는다. 자유생성만 쓰면
"JSON 을 못 냈다"와 "스킬을 모른다"가 한 숫자에 섞인다.

## 조건

| | |
|---|---|
| 항목 | 100 = 스킬 5종 × 지시문 20개. 균형은 도구가 실행 전에 검사하고 깨지면 **거부한다** |
| 모델 | fp16 안전성 통과한 것만. SmolVLM2-500M-Video-Instruct 우선, Qwen2.5-VL-3B 추가 |
| dtype | fp16 (V100 sm_70 은 bf16 연산이 없다) · `attn_implementation="sdpa"` |
| 생성 | `do_sample=False` · `max_new_tokens=48` |

### 이미지 조건 — `blank` 는 빼지 않는다

| 조건 | 무엇 | 성격 |
|---|---|---|
| `blank` | 0으로 채운 224×224 | **대조군.** 지시문만으로 나오는 성능 |
| `render` | MuJoCo 렌더 `cam_wrist` | 시뮬 |
| `real` | UMI 실물 시연 프레임 (180° 회전 보정) | 배포 분포 |

`cam_wrist` 를 쓰는 이유: 실물에 대응물이 있는 카메라가 그것뿐이다 (L76).

**`blank` 와 차이가 작으면 M0 정확도는 '지시문 분류' 정확도다.** 2026-09-11 관측 절제에서
쓴 것과 같은 방법이다 — 조건을 지우고 얼마나 떨어지는지를 본다.

## 사전등록 판정 (결과 전 확정)

**주 판정: 최고 이미지 조건의 강제선택 정확도 → D-AI-17 표 그대로.**

**보조 판정**

1. `(render 또는 real) − blank < 0.10` 이면 → **이미지 기여 미확인.** 이때 M0 수치를
   "VLM 이 현장을 이해한다"로 읽지 않는다. 스킬 선택은 사실상 텍스트 분류이고,
   **비전이 필요한 부분은 grounding(bbox) 이므로 다음 계측을 그쪽으로 옮긴다**
2. `real − render` 가 **0.15 이상** 벌어지면 → L22(렌더로 학습한 VLM 이 실사에서 도는가)가
   M0 단계에서 이미 관측된 것이다. 렌더 데이터셋 계획(D-AI-17)을 재검토한다
3. 자유생성 `enum 준수율 < 0.90` 이면 → **D-AI-24 의 enum 제약이 필수다.**
   0.90 이상이면 제약은 방어책이지 필수 장치가 아니다
4. 혼동행렬이 한 스킬로 쏠리면(예측의 60% 이상이 한 값) → 모델이 사전확률로 찍는 것이다.
   정확도가 우연보다 높아도 **그 쏠림을 먼저 보고한다**
5. 항목 균형 검사가 실패하면 → **계측기 오류. 해석 중단**

## 예측 (실행 전) 🟡

- 강제선택 **0.70~0.90** (blank 포함 전 조건에서 비슷). 근거: 지시문이 스킬을
  자연어로 거의 지시하고 있어 한국어를 읽는 모델이면 대부분 맞힌다
- **`blank` 와의 차이가 0.05 미만일 것이다** — 즉 보조판정 1에 걸린다.
  근거: 스킬 5종은 **놓기 단계로만 구분되고**(D-AI-22), 그 차이는 사진에 안 나온다.
  사진으로 `sort_two` 와 `line_up` 을 구분할 방법이 없다
- 자유생성 enum 준수율 **0.6~0.9** (SmolVLM-500M 이 더 낮을 것)
- `real` 이 `render` 보다 **약간 높다** — 실사 분포가 사전학습에 가깝다

**크게 빗나갈 때**: 강제선택이 0.50 미만이면 D-AI-17 의 "모델 후보 재검토" 구간이고,
Jetson 8GB 제약(이슈 42) 안에서 쓸 모델이 없다는 뜻일 수 있다. 그러면 VLM 스코프
자체를 줄이는 논의로 간다 (W7 Target 항목이라 MVP 는 안 막는다).

## 해석 제한 — 먼저 말한다

- **지시문 100개를 어시스턴트가 썼다.** 문제를 내는 쪽과 푸는 쪽을 같은 과정이 만들었다.
  실사용자 발화보다 쉬울 가능성이 크다. **"사용자가 말하면 이만큼 맞춘다"로 읽지 않는다.**
  사람(PM·사용자)이 다시 쓰면 그 판이 정본이고, 이 수치는 그때 다시 잰다
- n=100 에서 95% 구간 반폭이 약 ±9%p 다. 0.90 게이트 근처 값은 게이트를 확정하지 못한다
- 이미지는 스킬 라벨과 **무관하게** 붙는다 (같은 사진에 5종 지시문이 다 온다).
  이것은 의도다 — 스킬은 지시문이 정하고 사진은 현장이다. 따라서 이 측정은
  **grounding 을 재지 않는다.** bbox 정확도는 별도 계측이다
- 시뮬 렌더는 `sim_pick_*` 계열이라 스킬 5종의 장면이 아니다. 장면과 지시문이
  안 맞는 조합이 대부분이다 — `blank` 대비 차이를 읽는 용도지 절대값이 아니다
- VLM 은 보조 도구다 (프로젝트 원칙). 이 결과가 MVP(W6)를 막지 않는다

## 2. E1 — 시뮬 UMI 모방학습이 도는가 (과제 ②)

**하는 것**
1. 시뮬 시연 100편 생성 (seed 6000–6099) → zarr export
2. 공식 UMI diffusion 학습 3회 (seed 0/1/2), 서버 V100
3. 각 체크포인트 롤아웃 100편 (seed 7000–7099), **로컬 GPU**

**상한·하한**
- 상한: scripted expert 자신의 성공률 (같은 시드 블록에서 별도 측정)
- 하한: 팔이 안 움직이면 물체 z 가 절대 +0.10 m 를 못 넘으므로 구조적으로 0% 🟡
  (구조 논증이지 측정이 아니다. replay baseline 은 시간이 남으면 잰다)

**게이트 — 2단으로 나눠 미리 박는다**
- **G1a (작동)**: 3시드 합산 성공률의 Wilson **하한 > 5%**
  → "학습이 됐다" 고 말할 수 있는 최소선
- **G1b (실용)**: 3시드 합산 Wilson **하한 ≥ 50%** 이고 시드 간 범위 ≤ 20%p
  → 발표에서 "시뮬 모방학습이 동작한다" 고 쓸 수 있는 선
- G1a 불통과 → E2·E3 중단. 학습 파이프라인부터 고친다

**예측 (지금 적는다)**: G1a 통과, **G1b 불통과**.
합산 65~85%, 시드 간 범위 15~30%p 로 본다.
근거 🟢 — 같은 데이터·설정으로도 학습 실행 간 성공률이 25%p 갈린 전례가 있다.
diffusion + 16스텝 청킹이라 BC 보다 안정적일 것으로 보지만 **미검증**이다.

## 3. E2 — 시뮬이 실데이터 학습을 돕는가 (과제 ①) ★핵심

**3팔, 전부 같은 평가 시드**

| 팔 | 학습 | 의미 |
|---|---|---|
| A | 실 UMI 데이터만 | 시뮬 없이 도달하는 선 |
| B | 시뮬 100편 사전학습 → `--init-checkpoint` → 실데이터 파인튜닝 | 시뮬 보조 |
| C | 시뮬 100편만 | 실데이터가 기여했는지 가르는 대조 |

`--init-checkpoint` 는 모델·EMA 를 유지하고 optimizer 와 카운터를 리셋한다
(handoff `umi_adapter/train.py` 실측 🟢). 이게 "시뮬이 돕는다" 의 구현체다.

**게이트 G2**: **B 의 Wilson 하한 > A 의 Wilson 상한** → "시뮬 사전학습이 돕는다" 주장 가능
- 겹치면 → "이 데이터 양에서는 차이를 못 본다". **게이트를 내리지 않는다**
- **추가 조건**: B 가 C 도 넘어야 한다. B ≈ C 면 이득의 출처는 시뮬이고
  실데이터는 기여하지 않은 것이다. 이건 다른 결론이므로 따로 적는다

**예측 (지금 적는다)**: **G2 통과, 단 B ≈ C.**
실데이터 69편은 파인튜닝에 너무 적어서 A 는 거의 바닥(0~10%)일 것으로 본다.
그러면 B > A 는 쉽게 나오지만, 그건 "시뮬이 돕는다" 가 아니라
"실데이터만으로는 아무것도 안 된다" 에 가깝다.
**이 예측이 맞으면 발표 문구는 "시뮬 사전학습이 실데이터 부족을 메운다" 이지
"시뮬이 실데이터 학습을 개선한다" 가 아니다.** 둘은 다른 주장이다.

⚠️ 평가가 전부 시뮬 안에서 일어난다 (실물 로봇팔 모터 고장).
시뮬 성공률은 sim2real 갭의 **하한**이지 실물 보장이 아니다 — 반드시 병기한다.

## 4. E3 — 정책 2종 타겟 (과제 ③)

**타겟 선정 (D-AI-49 초안, 작성자 김준태)**

| 타겟 | config | 전문가 경로 | 왜 이 둘인가 |
|---|---|---|---|
| T1 측면 파지 | `configs/can_side.yaml` | `run_side_expert` | 기존 검증됨 |
| T2 상면 파지 | `configs/box_top.yaml` (신규) | `run_expert` 기본 경로 | **접근 궤적이 직교한다** |

같은 물체를 위치만 바꾼 두 태스크는 "2종" 이 아니다. 접근 축이 수평/수직으로
갈라져야 정책이 실제로 다른 것을 배웠는지 판정할 수 있다.
물체(캔·박스)는 파이프라인 구축용 더미다 — 실제 5종 스킬 물체로 교체 예정.

**게이트 G3 — 두 조건을 모두 본다**
- G3a: T1·T2 각각 자기 태스크에서 G1a 통과
- G3b **교차 평가에서 떨어진다**: T1 정책을 T2 에서 돌린 성공률의 Wilson **상한 < T2 정책 하한** (반대 방향도)
  → 둘 다 잘 되면 그건 2종이 아니라 하나의 범용 정책이다. **구분됐다는 증거가 필요하다**

**예측**: G3a 통과, G3b 통과. 교차 성공률 0~5% 로 본다.
근거 🟡 — 측면 접근 정책은 상면 태스크에서 물체 옆을 지나가므로 파지 자체가 성립 안 한다. 설계 판단이고 미측정.

**되돌릴 조건 (D-AI-49)**: `box_top.yaml` 로 scripted expert 성공률이 80% 미만이면
T2 를 폐기하고 T1 의 workspace 변주(넓은 영역)로 2종을 재정의한다.
⚠️ top-down `run_expert` 는 pre/lift 오프셋과 `<0.06` 폭을 **하드코딩**한다 —
config 로 제어되지 않는 부분이 있다. T2 착수 전 이걸 먼저 확인한다.

## 5. 자원과 병목

| | 학습 | 평가(롤아웃) |
|---|---|---|
| 어디 | 서버 V100 (1·2·3·4·6) | **로컬 5070 / 4070** |
| 왜 | GPU 5장 병렬 | 트랙 A 조건 — 공용 서버는 학습 전용 |

학습 잡 수: E1 3 + E2 9 + E3 6 = **18잡**, 5 GPU → 4 wave.
롤아웃 수: E1 300 + E2 900 + E3 1200(교차 포함) = **2400 에피소드**.

🔴 **여기가 진짜 병목이고, 아직 계측 안 했다.**
착수 전 첫 계측: **로컬에서 롤아웃 1편 소요 시간**. 이 값 없이 2400편 일정은 못 짠다.
1편 30초면 20시간 — 2일 안에 안 들어간다. 그 경우 n 을 줄이는 게 아니라
**실험을 줄인다** (E3 교차평가부터 n=50 으로, 그다음 E2 의 C 팔).
⚠️ 게이트를 낮추지 말고 **실험 개수를 줄인다.** 다른 문제다.
